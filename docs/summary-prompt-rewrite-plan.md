## 关键决定（拍板记录）
- **去掉 note_plan + 接地门**，总结回到 **"边读 PDF 边写"** 一趟做完。理由：note_plan 的实测危害 > 收益（见 §四）。
- 首要消费者是 **agent**，判断轴 = **正确性 > 可提取性 > 文笔**。
- **数字让位 PDF**：总结给量级/方向 + 出处，不堆精确数字；精度权威在 PDF。
- 论断写成**原子句 + 内联 strength 标签**；新增"适用边界"一等段落。
- codex 核查跟着改：告知"数字让位 PDF 立场"防误报 + 加"方向反转"专项检查 + 数字精度从宽。
- **note_plan claim-JSON 对 agent 公开**：本轮**不做**，留作检索层独立增强。

## 一、summarize prompt（`build_prompt` 整体重写为 3 步）

```
你是论文精读员。请**边读这份 PDF 边写**一份**中文**结构化总结。
{重做时插 _resummary_block，首次为空}

【这份总结给谁看、干嘛用】首要读者是别的 AI agent(其次研究者本人):它检索到这篇时,
靠你的总结判断"方法是什么、值不值得打开 PDF 深读"。判断轴:正确性 > 可提取性 > 文笔。
精确数字/超参/确切公式不必给全——需要时读者按你给的出处去 PDF;你的任务是讲清
方法、直觉(为什么 work)、结果方向、什么时候管用。

【铁律·只用本 PDF】所有事实/数字/公式/方法细节只能来自这份 PDF;原文没写到的写
`[原文未提]`,绝不用记忆脑补(这条只管"事实从哪来",中文表达照常发挥)。
反向也一样:不要断言原文"没有/未给出"某内容(你没读到≠不存在,附录常在后几页),
拿不准就把后面的页读完再说。

论文元信息:
- 标题 / 作者·年份·venue·引用·DOI / 与本研究主题的相关性评分 + 理由

【第一步·通读全文】用 Read 读取 PDF 全部页面(多页;>20 页用 pages 分批读完,
含正文后的附录/补充/大表)。直读 PDF 能看到公式/图/表。读完再动笔,不要只读前几页就写。

【第二步·写总结】严格用模板,中文:
- 每条论断写成能独立成立的原子句(一句一个点,便于 agent 单独抽取)。
- 结果/方向性结论句末内联标 strength:observed|supported|strong,没把握往低报;
  措辞不许超过 strength——observed 只能说"在 X 任务上更好",不许"全面/大幅超越"。
- 数字克制 + 指向 PDF:给量级或方向即可;确需写具体值时紧跟出处("约 0.3,见 §5.2 表3"),
  不把它当结论卖点;不确定的数字宁可不写。
- 必须讲直觉:为什么这个方法能 work(机制),不只是罗列它做了什么。
- 准确转写关键数学公式;重要图表说明它呈现什么、支撑什么结论。
- 引关键原文时加引号(中文转述 + 括注英文原话或出处),让人能回 PDF 定位。
- "适用边界"与"局限与我的质疑"分别写够。{quality_directive 注入}

【第三步·写完自查(逐条对照,不达标回去补)】
1. 方向准确:每个结果方向有没有写反或夸大(observed→全面超越)?
2. 直觉:讲清"为什么 work"了,还是只罗列做了什么?
3. 适用边界:什么时候管用/不管用、跟强基线还是弱基线比,说清了吗?
4. 接地+防张冠李戴:每条关键论断都能在 PDF 找到依据吗?有没有把背景/被引工作的结果当成本文的?
5. 数字克制:有没有把孤立精确数字当结论卖点?该让位 PDF 的让位了(附出处)吗?
6. 原子可提取:每条论断独立成句、能被 agent 单独抽取吗?
7. 证明 vs 没证明:真证明的 和 没证明/未来工作的,分开了吗?

输出:完成后只把总结 markdown 输出到 stdout,不要额外说明、不要代码围栏。
输出模板:{_template}
```

### 模板 `_template`（加"适用边界"）
```
## 一句话
## 解决了什么问题
## 用什么方法解决的（含直觉：为什么 work）
---
## 动机 & 背景
## 方法细节
## 数据集 & 实验设置
## 主要结果 & 结论（写方向，不堆精确数字）
## 适用边界（什么时候管用 / 什么时候不管用）   ← 新增
## 核心贡献
## 局限与我的质疑
```
`_resummary_block`（核查后重做避坑块）保持现状不变。

## 二、codex verify prompt（`vprompt`）

判据主体不动，加/调三处 + 删 note_plan 残留：

1. **新增"总结数字立场"告知（防误报，最关键）**：总结故意不堆精确数字、把精确值让位 PDF；
   总结没给某精确数值或只给量级/方向 **不是问题、不要报**;只有数字**与原文矛盾、或被安到错误
   对象/设定(张冠李戴)**才算错。
2. **新增"方向反转"专项检查**（通用 judge 抓不住，需专门提示）：逐条结果对一下方向——
   谁比谁好写成谁比谁差、有效写成无效、稳定写成不稳定、正/负相关写反、梯度/不等式方向写反；一律 major。
3. **severity 微调**：major=编造/方向写反/张冠李戴/把 observed 夸成全面超越;minor=措辞略强/孤立论断无据;
   **孤立数字精度偏差(对象绑定对、只数值不够精确)从宽,不报或至多 minor**;unverifiable=这轮没核到。
4. **删 note_plan 残留**：`plan_block`/`anchor_task`（"撰写者 note_plan 辅助坐标"）整段删——以后没有总结再产 note_plan。

## 四、为什么去掉 note_plan —— 实测危害证据
1. **"无锚论断"假阳性洪水 → 版本通胀**（最硬的账）：note_plan 被当成"完整锚点清单",但撰写者从不会把每条
   论断都登记成锚点;于是 verify 把每条**未登记但原文其实支持**的论断标成 `[minor] note_plan 无对应锚点,
   疑未接地`。`logs/redo-batch2-20260617/summary_verification.md.bak` 里成片这种 minor，几乎都附注"本轮核查
   原文可支持"——即**假阳性**。叠加旧"非 pass 全重写"策略 → v2/v3 暴涨但多非真修
   （`logs/SESSION-2026-06-17-codex-quota.md:35`）。
2. **接地门只验"引文在不在"、不验"绑得对不对"** → 防的是编造引文，**防不住真正危险的张冠李戴**
   （引文是真的、被安到错对象，如 ±528）。即收益错位。
3. **两段式"把数字从语境剥离成锚点"本身是张冠李戴诱因**（GAE/Learning-to-Walk;`SESSION-2026-06-17-
   summary-version-comparison.md:48`，实测频率低于预期但机制性风险确在）。
→ 新方向下 ①数字不再每个挂锚点、②codex 语义核查本就抓张冠李戴(且抓接地门抓不到的"绑错对象")，
note_plan 的活基本被覆盖，危害却仍在 → 去掉。

4. **接地门到底防住了什么?——查史:它防的威胁本就几乎没发生**(2026-06-18 复查 2026-06-10 老总结时代核查报告):
   - **严格"编造引用"(凭空捏一句 PDF 没有的逐字英文引文)→ 无记录**。老总结几乎不引原文(IMPL 对照:英文引文 39 vs 3、页/节锚点 71 vs 0),没有"逐字引文"这个表面可捏;且接地门唯一真跑那次 bake-off,36 条引文全过、一个编造引文都没抓到,那篇真幻觉是 **codex 抓的**(门"结构上管不到")。
   - **真正在发生的 major 是别的**:数字写反(62.48% 写成低于 59.26%)、基线数字抄错、消融归因写反、过度概括、张冠李戴、**编造内容**(凭空加 PDF 没有的技术名 "PGExplainer"/数字"相关性评分 26"/比较)——**这些接地门一个都接不住**(要么语义/方向错,要么非引文形式的编造)。
   → 即:接地门冲"编造引文"建,但老时代编造引文本不是问题,真问题(方向/张冠李戴/过度声称/编造内容)它接不住、本就得靠 codex。删它不放走任何它真在防的东西。证据:`logs/verify-baseline-20260615/`、`logs/SESSION-2026-06-16-summarize-verify-IMPL.md`。
