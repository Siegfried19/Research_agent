# A survey on large language model based autonomous agents
> Lei Wang, Chen Ma, Xueyang Feng, Zeyu Zhang, Hao Yang, Jingsen Zhang, Zhiyuan Chen, Jiakai Tang, Xu Chen, Yankai Lin, Wayne Xin Zhao, Zhewei Wei, Ji-Rong Wen · 2024 · Frontiers of Computer Science · 引用 1108 · DOI 10.1007/s11704-024-40231-1

## 一句话
一篇系统综述,把"以大语言模型为中央控制器的自主智能体"这一新兴领域,从**构建(架构+能力获取)、应用(社科/自然科学/工程)、评估(主观/客观)** 三大维度梳理成统一分类框架,并提出 6 类开放挑战。

## 解决了什么问题
LLM-based autonomous agent 这一领域在 2022–2023 间爆发式增长(论文图 1 统计 2021.1–2023.8 累积论文),但此前各模型(Generative Agents、ReAct、Reflexion、Voyager、HuggingGPT 等)都是**孤立提出、缺乏横向对比与统一抽象**。作者要做的是给这个碎片化领域一份"全景地图":让新人能快速建立背景知识,也给后续研究指方向。它**不提出新方法、不做实验**,纯综述。

## 用什么方法解决的
文献综述 + 自建分类法(taxonomy)。核心产出是一个**统一智能体架构框架**,把以往工作拆成四个模块:
- **Profiling(画像)** 模块:定角色(coder/教师/专家),三种造画像法——手工指定 / LLM 生成 / 真实数据集对齐。
- **Memory(记忆)** 模块:借鉴认知科学的短期/长期记忆;结构分 unified(只短期、写进 prompt)与 hybrid(短+长期、向量库检索);格式分自然语言/嵌入向量/数据库/结构化列表;操作分读(按 recency/relevance/importance 三项打分,给出统一打分公式)、写(处理重复与溢出)、反思(把低层记忆蒸馏成高层洞察)。
- **Planning(规划)** 模块:分"无反馈"(单路 CoT / 多路 ToT、GoT、MCTS / 外部规划器 PDDL)与"有反馈"(环境反馈 ReAct/Voyager、人类反馈、模型反馈 Reflexion/Self-Refine)。
- **Action(行动)** 模块:从目标、产生方式、动作空间(外部工具 API/数据库/外部模型 vs LLM 内部知识)、动作影响四个角度刻画。

能力获取(agent capability acquisition)按是否微调分两类:**微调**(用人工/LLM 生成/真实数据集)与 **不微调**(prompt 工程 + "机制工程"——试错、众包辩论、经验积累、自驱进化)。最后用一张表(Table 1)把代表性工作映射到这套分类,应用与评估各成一章。

## 动机 & 背景
传统自主智能体(强化学习路线)假设智能体基于简单启发式策略、在**孤立受限环境**中学习,这与人类"从广泛环境中学习"的过程差异巨大,难以做出人类水平决策。LLM 通过海量 Web 知识展现出接近人类的智能,于是出现一波用 LLM 当中央控制器、给它配上记忆与规划等"人类能力"来构建智能体的研究。作者主张:相比 RL 智能体,LLM 智能体有**更全面的内部世界知识**(无需领域数据训练即可行动)、且提供**自然语言接口**(更灵活、可解释)。

## 方法细节
(本文是综述,"方法"即其分类体系,核心已在上文"用什么方法解决的"展开。)几个值得记的细节:
- **记忆读取统一公式**:m* = argmax αs_rec + βs_rel + γs_imp,通过调三个权重囊括不同策略(如只看相关性 α=γ=0,或三项等权)。相关性打分可用 LSH/ANNOY/HNSW/FAISS 实现。
- **反思机制**:Generative Agents 先由近期记忆生成 3 个问题→检索→产出 5 条高层洞察,且可层级化(洞察生成洞察)。
- **规划无反馈 vs 有反馈**的权衡:无反馈实现简单但只适合少步简单任务;有反馈设计复杂但能处理长程任务。
- **机制工程(mechanism engineering)** 是作者提的新概念,与微调、prompt 工程并列为第三类能力获取途径,涵盖 GITM/Voyager 的技能库与经验积累、多智能体辩论众包、LMA3 的自驱进化等。

## 数据集 & 实验设置
**无**。本文不训练、不评测、不做实验,只统计文献(声明共整理了约 100 篇 LLM agent 相关工作)。涉及的"数据集"都是被综述工作里出现的,如 WebShop(118 万真实商品)、Mind2Web(137 网站 2000+ 任务)、ToolBench(16464 个真实 API)等,作者只做归纳引用。评估一章梳理了主观评估(人工标注、图灵测试)与客观评估(任务成功率/人类相似度/效率等指标;真实模拟/社会评估/多任务/软件测试等协议;ALFWorld、AgentBench、WebArena、Minecraft 等基准)。

## 主要结果 & 结论
作为综述,"结果"即三套分类法 + 三张映射表(Table 1 构建、Table 2 应用、Table 3 评估)+ 6 类挑战:
1. **角色扮演能力**:罕见/新兴角色难模拟,LLM 缺自我认知。
2. **广义人类对齐**:做社会模拟时反而需要智能体能呈现"负面/错误价值观"(否则无问题可发现),与现有 LLM 统一对齐到正确价值相矛盾,需研究"再对齐"。
3. **Prompt 鲁棒性**:多模块导致 prompt 框架复杂、微小改动结果大变、跨 LLM 不通用。
4. **幻觉**:高置信度生成假信息,代码生成等场景风险大。
5. **知识边界**:LLM 知道得太多,做用户行为模拟时难以"假装不知道"用户本不知道的信息。
6. **效率**:自回归推理慢,而每步动作要多次查询 LLM。

## 核心贡献
- 提出囊括多数已有工作的**统一四模块架构框架**(profile/memory/planning/action),给碎片化领域一个公共词汇表。
- 给出按"是否微调"组织的**能力获取分类**,并提出"机制工程"这一概念。
- 系统覆盖**应用三域(社科/自然科学/工程)与评估两路(主观/客观)**,配三张工作-分类映射表,实用性强。
- 凝练 6 类开放挑战,对后续研究有指引价值(高引用量印证其影响力)。

## 局限与我的质疑
1. **作者自述局限**:综述坦承这是领域"初期"的快照,prompt/机制设计空间过大、找不到最优解;评估手段无法完整衡量所有能力;微调法只适用于开源 LLM、不微调法受上下文窗口限制。挑战章对每条几乎只给"微调或调 prompt"两条泛泛建议,缺乏可操作深度。
2. **时效性与覆盖偏差**:截稿 2024 年初、统计止于 2023.8,正值领域月月翻新,如今已严重过时(多模态 agent、agentic RL、长程工具调用等基本未覆盖)。声称"整理约 100 篇"但 LLM agent 领域当时远不止此数,**选样标准未交代**,分类表里同一篇被反复引用,代表性存疑。
3. **纯定性、零验证**:全文无任何实验或定量对比,统一框架是否真"能囊括多数工作"、各模块划分是否互斥完备,均靠作者主观断言(如"unified/hybrid 之外几乎没有纯长期记忆"只是 speculation)。框架更像事后归纳的描述性叙事,而非可证伪的理论,读者无法判断哪种设计在什么任务上更优。
4. **对 RL 的论述偏薄且略带稻草人**:开篇贬低 RL"孤立环境、启发式策略"以反衬 LLM agent 优势,但并未公平讨论 RL 在连续控制、具身物理交互上的成熟度,把 RL 当背景板而非可融合路线(实际上 Reflexion/Voyager/Retroformer 都用了 RL 思想,文中却轻描淡写)。
5. **与本主题(RL 训练数字人与环境交互)关联薄弱**:本文焦点是**文本/符号空间的决策智能体**——软件开发、社会模拟、工具调用、问答规划,几乎不触及**连续动作空间、物理仿真、运动控制、感知-动作闭环**这些数字人具身交互的核心难点。它谈的"action"多是调 API、发对话、改环境状态(挖木头、放积木),而非关节力矩、步态、接触动力学。其"感知-记忆-规划-行动"高层认知框架**或可启发数字人的决策/对话层**(尤其 memory/reflection 与 planning-with-feedback 的环境反馈回路),但对"如何用 RL 训出能与物理环境实时交互的身体"这一主题,本文提供的是上层脚手架而非可直接迁移的方法,相关性评分 35 偏低是合理的。
