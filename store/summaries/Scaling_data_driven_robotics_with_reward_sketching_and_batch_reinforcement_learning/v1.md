# Scaling data-driven robotics with reward sketching and batch reinforcement learning
> Serkan Cabi, Sergio Gómez Colmenarejo, Alexander Novikov, Ksenia Konyushkova, Scott Reed, Rae Jeong, Konrad Zolna, Yusuf Aytar, David Budden, Mel Vecerik, Oleg Sushkov, David Barker, Jonathan Scholz, Misha Denil, Nando de Freitas, Ziyu Wang · 2019 · arXiv · 引用 0 · DOI arxiv:1909.12200

## 一句话
DeepMind 提出一套"数据驱动机器人"循环系统：用"奖励草图（reward sketching）"低成本从人类偏好中学到任务奖励函数，用它回溯标注海量历史经验，再用 batch（离线）RL 纯从存储数据里学到能在真实机械臂上执行多种操作任务的视觉策略。

## 解决了什么问题
真实机器人 RL 受困于两点：①数据贵（真机采集不能超过实时速度，没有像模拟器那样能"一天跑 180 年"），②真实世界里没有天然奖励信号，复杂任务又难以手工设计奖励。本文要让 RL 在真机操作任务上"可扩展"——不必每一步学习都去真机上跑、也不必为每个任务手工写奖励。

## 用什么方法解决的
三个核心 idea 串成一个五阶段循环：(1) 持续把所有机器人经验（遥操作示范、脚本随机策略、训练出的策略产生的轨迹）存入中心化的 NeverEnding Storage（NES，带 SQL 可查的元数据）；(2) 人通过"奖励草图"界面拖动视频游标画出每一帧"朝目标的进展曲线"，快速得到逐帧奖励标注；(3) 用这些标注以"片段内排序（intra-episode ranking）+ 成功阈值"的 hinge loss 训练奖励网络，再用它回溯给 NES 里所有历史/跨任务数据打上该新任务的预测奖励；(4) 用类 D4PG 的**分布式（distributional）batch RL** 从这个被标注的大数据集纯离线学策略（actor-critic 均为递归网络，输入多路相机像素+本体感知，75% 数据来自全库 + 25% 来自当前任务的固定比例 batch）；(5) 把学到的策略部署到真机评估并继续采集新数据，形成循环（每个任务一般迭代 2–3 次以修正"奖励妄想/delusion"）。

## 动机 & 背景
深度学习在视觉、语音、NLP、模拟环境 RL 上的成功都依赖海量带标注数据，而机器人领域既缺数据又缺天然奖励信号。现有真机 RL 大多依赖针对特定任务手工设计的奖励（如抓取、避免坠机），随任务复杂度上升不可扩展。作者主张：与其为每个任务手工写奖励，不如**让人对"进展"做判断**来学奖励函数，并把昂贵的真机交互从学习循环里彻底拿掉（改用离线 batch RL）。

## 方法细节
- **遥操作示范**：用 6-DoF 鼠标或 VR 手柄遥控 Sawyer 机械臂提供首人称示范，支持交互式接管/交还控制以修正 corner case（数据集中约 15% 的人类示范最终失败，也保留）。
- **NES 存储**：中心化关系型数据库，给每条轨迹挂环境/策略元数据 + 人类可读标签 + 奖励草图，可按训练阶段动态切片检索。记录 3 个机笼相机 + 3 个腕部相机（含广角与深度）+ 本体感知，连续记录动作，10Hz 控制。
- **奖励草图**：标注者"擦动"视频时画进展曲线，单人每分钟可标数百帧；为每帧给出 s(xt)∈[0,1]，绿色区表示目标达成。
- **奖励学习**：因标注者对帧间相对优劣一致、但对整体尺度不一致，故不直接回归数值，而用"片段内排序"：同一片段两帧 xt、xq，若草图 s(xt) 比 s(xq) 高出阈值 µs，则预测奖励须高出 µr（Lrank）；并用成功阈值约束（Lsuccess）。总损失 Lrank + λLsuccess，参数 µs=0.2, µr=0.1, τs=0.85, τr1=0.9, τr2=0.7, λ=10。奖励网络是非递归残差网络 + spatial softmax + sigmoid 输出。
- **batch RL**：类 D4PG，分布式价值函数 + DPG 策略更新；actor/critic 各用 2 层 256 单元 layer-norm LSTM；BPTT 训练，零初始 recurrent 状态；固定比例 batch（75% 全库 + 25% 当前任务）。**纯离线**，无行为克隆初始化、无特征预训练、无 batch 修正项、无辅助损失。每个 agent 训 400k 步。
- **奖励妄想修正**：早期奖励覆盖不足时策略会"钻空子"骗高奖励，靠对这些片段补标草图、重训奖励、再重训策略，循环 2–3 次。

## 数据集 & 实验设置
- **硬件**：Sawyer + Robotiq 2F-85 夹爪 + 腕部力矩传感器，35×35cm 篮筐；动作空间 6 连续自由度（笛卡尔平移/旋转速度）+ 1 个二值夹爪控制；10Hz；每片段 200 步（20 秒）。
- **两个子集**：rgb 数据集（红/绿/蓝三种变形刚体；学 lift_green 与 stack_green_on_red）和 deformable 数据集（软球/绳/布；学 lift_cloth）。
- **数据量**：rgb 数据集约 37.9K 片段 / 7.0M 步 / 193.3 小时；deformable 约 36.5K 片段 / 6.9M 步 / 191.2 小时。共采集 400+ 小时多相机视频。lift_green/stack_green_on_red/lift_cloth 分别有 894/1201/585 个草图片段，约 90% 训练 10% 验证；仅约 600 个完整遥操作片段对应这两个目标任务。
- **评估**：真机上用固定初始条件，分 normal / hard / unseen 三档难度，每档 10 个初始位置；成功率由人判定。lift_cloth 用随机初始条件 50 次试验。

## 主要结果 & 结论
- **rgb 数据集**：lift_green 成功率 normal 80% / hard 80% / unseen 50%；stack_green_on_red normal 60% / hard 40% / unseen 40%。lift_cloth（变形物体）成功率 74%。
- **消融**（关键结论）：①只用任务专属数据训练 → 几乎全 0%（说明跨任务历史数据至关重要）；②去掉 random_watcher 随机脚本数据 → 性能下降，最难的 unseen 场景损失最大（可达 -30%）；③非分布式 RL → 大幅劣于分布式（确认分布式价值函数对 batch RL 是 essential）。
- **对比**：与 Zhu et al.（lift 64% / stack 35%）、Wulfmeier 等（依赖 QR 码状态估计、固定方块）、Jeong 等（sim2real，固定大方块 62%）相比，本方法在更多样物体 + 6-DoF 像素控制下取得相当或更优表现（作者声称物理设置不同、不完全可比）。
- **泛化与鲁棒**：能从失误中恢复、抗对抗扰动、泛化到未见物体/初始条件、操作变形物体；某些情况下比人类遥操作更快（Fig.9）。
- **交互式 USB 插入任务**：在线紧耦合学习（不依赖历史数据/batch RL），3 次重复实验平均 8 小时内达 >80% 成功率，期间标注者额外提供 65±10 个草图——展示"一个工作日内从视觉学会工业相关任务"。

## 核心贡献
1. 提出"奖励草图"——一种高效从人类逐帧偏好中学奖励函数的交互方法（适合人能可靠比较两帧优劣的操作任务）。
2. "回溯奖励标注"：用固定的人工标注成本即可给整个历史库打上新任务奖励，复用所有跨任务经验。
3. 证明分布式 batch RL 可纯离线从混合（off-policy + off-task）数据学到真机可用的视觉操作策略，并发现**训练数据多样性**是成功关键。
4. 公开发布数据集（Sketchy）与 canonical agents（Acme），推动 batch RL 在机器人上的后续研究。

## 局限与我的质疑
- **来源说明**：本文为 arXiv 预印本（v3, 2020-06），库内元信息显示引用 0、来源信息不全，未经同行评审确认。其报告的成功率、消融结论均出自作者团队自评，下文结论应保留态度看待。
- **作者自述局限**：①训练需"人在环"，有额外成本；②奖励草图不通用——对"速度可变""有周期（如行走）"的任务难以草图化，作者明确说不适用；③学到的策略对显著扰动仍敏感。这些直接限制了方法的任务范围。
- **样本量与评估可信度存疑**：核心成功率每档仅 10 次试验，stacking 60%/40% 这类数字的置信区间很宽，难以支撑"显著优于他人"的强结论；"成功由人判定"也引入主观性，缺乏方差/多次重复报告（USB 任务才重复 3 次）。与他人方法的对比作者自己也承认"物理设置不同、不完全可比"，却仍用来佐证优越性，有过度解读之嫌。
- **奖励学习的循环验证问题**：奖励函数好坏只能靠把策略放真机上跑来判断，且要靠人反复补标修"奖励妄想"。这意味着奖励质量没有独立、客观的度量，整套循环里"奖励对不对"和"策略好不好"互相纠缠，难以判断成功到底来自方法本身还是来自人类反复纠错的隐性监督。
- **泛化主张偏弱**：所谓"泛化"仍局限在同一篮筐、同类物体（颜色块、布/绳）、固定相机视角的桌面抓取/堆叠，unseen 档成功率也只 40–50%。距离真正开放环境的鲁棒操作还很远。
- **与"RL 训练数字人与环境交互"主题的差距（相关性 68 的来源与短板）**：本文的命中点在**学习型奖励函数 + 离线/off-policy RL**这套"奖励工程之外"的范式，对本主题"如何低成本获得交互任务的奖励、如何用偏好/草图替代手工奖励"很有借鉴价值。但它研究对象是**工业机械臂的物体操作**，不是仿真/具身数字人，没有全身控制、没有人形/角色动画、没有与人或动态环境的社会性交互；草图式奖励也明确不适合带周期的运动（如行走/步态），恰恰是数字人最需要的那类技能。因此它能直接迁移的是"奖励获取与离线学习的方法论"，而非具体的数字人交互建模。
- **工程依赖重、复现门槛高**：方法严重依赖 DeepMind 规模的持续数据采集（400+ 小时多相机）、NES 存储基础设施和大量遥操作人力，作者也承认"需要大量工程"。这使其在小团队/学术场景的可复现性和可扩展性都打折扣。
