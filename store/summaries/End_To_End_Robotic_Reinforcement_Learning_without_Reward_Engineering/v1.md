# End-To-End Robotic Reinforcement Learning without Reward Engineering
> Avi Singh, Larry Yang, Kristian Hartikainen, Chelsea Finn, Sergey Levine · 2019 · arXiv · 引用 208 · DOI 10.15607/rss.2019.xv.073

## 一句话
让真实机器人直接从摄像头图像学操作技能,但不用人工写奖励函数——只给少量"成功结果照片"加几十次"这算成功吗"的二值主动查询来学出奖励,1–4 小时真实交互即可学会推杯、盖布、插书三个任务。

## 解决了什么问题
机器人 RL 要"端到端从像素学",但奖励函数本身往往又得靠人工设计的感知系统或环境布置传感器来判断任务是否成功——这恰恰否定了端到端学习的初衷(`"manually defining reward functions typically requires manually-designed perception systems or instrumentation of the environment"`,p.1)。逆强化学习需要专家演示(采集负担重、不直观);用目标图像训分类器当奖励则会被 RL 策略钻空子:策略跑到分类器没见过的状态、骗它输出成功标签(`"the policy can learn to exploit the classifier ... and fool it into outputting a success label erroneously"`,p.3)。已有的 VICE 虽能用对抗挖负样例缓解钻空子,但依赖大量(图像观测下约 5 万)初始正样例、且用 on-policy RL 需上百万样本,真实世界不现实。

## 用什么方法解决的
核心是把奖励学习拆成"分类器奖励 + 主动查询",并把整套搬到 off-policy:
- **分类器即奖励**:训分类器区分目标/非目标状态,用成功对数概率作奖励——`"a particularly convenient form for the reward is given by log pg(y|s)"`(p.3)。
- **RAQ(主动查询)**:不预先给全套负样例,而是边训边问。关键设计是查询哪个状态——不用最大熵不确定性,而是**挑分类器判成功概率最高的未标注状态**去问用户(`"select the previously-unlabeled states with the highest probability of success according to the classifier"`,p.4),公式 `"k = arg max ... log pg(y = 1|st) ∀ t since last query."`(p.4)。机制依据:钻空子源于假阳性而非假阴性,只有正预测状态才可能是假阳性,所以专查这些状态最能堵漏(`"classifier exploitation is due to false positives rather than negatives ... Since only states with positive predictions can be false positives, querying for labels for these states is an effective mechanism"`,p.4)。查询按固定间隔触发,每次训练做 25–75 次(p.4)。
- **底层 RL**:最大熵框架,目标 `"J(π) = ... Eτ∼π [r(st, at) − log π(at|st)] . (1)"`(p.3),用 off-policy 的 SAC,稳定且省样本。
- **Off-Policy VICE(本文对 VICE 的两点扩展)**:① 把 VICE 从 on-policy 搬到 off-policy——用 SAC + 直接从 replay buffer 采负样例并丢掉重要性权重(`"adversarial IRL can drop the importance weights both in theory ... and in practice ... without importance weighting"`,p.5);判别器形式 `"Dψ(s, a) = exp(fψ(s, a)) / (exp(fψ(s, a)) + π(a|s)) . (2)"`(p.5)。② 免除用户提供动作标签——对正样例的动作用当前策略 π(a|s) 积分掉(`"integrating out the actions for the positive examples ... by using the current policy π(a|s)"`,p.5),收敛时与给真值动作有相同不动点。
- **VICE-RAQ(最终方法)**:把主动查询并进 VICE——查询为正就加入正样例集,查询为负则不必加,因为 VICE 本就把所有采样状态当负样例(`"If the label is negative, there is no need to append the state, since VICE already uses all sampled states as negatives"`,p.5)。这样既靠 VICE 用满全部 RL 数据,又靠 RAQ 把所需初始正样例从数千压到很少。
- **平滑奖励**:神经网络分类器给的是硬边界(类似稀疏奖励),作者用 mixup 正则化把预测平滑化:`"˜s = λsi + (1 − λ)sj, y˜ = λyi + (1 − λ)yj , (3)"`,λ∼Beta(α,α)(p.6),使学出的奖励更平滑、更利于 RL。

## 数据集 & 实验设置
- 硬件/观测:7 自由度 Sawyer 机械臂,末端执行器位置控制,观测为 84×84 RGB 图像,**不用关节角/末端位置**(`"end-effector position control on a 7 DoF Sawyer ... RGB image of size 84 × 84. We do not make use of robot joint angles or end effectorpositions"`,p.6)。
- 网络:策略、critic、奖励 fψ 共用同一 CNN——两层卷积(各接最大池化,仿真每层 8 滤波器、真实每层 32),展平后两层各 256 单元全连接,均接 ReLU(p.6)。
- 三个真实任务:视觉推杯(把杯推上杯垫,非抓取式操作)、视觉盖布(把布平整盖到盒上,可变形物体)、视觉插书(把书插进书架多个空槽之一,多成功条件)。
- 规模:每任务 **80 个成功样例**;推杯/插书每 250 步查一次、盖布每 500 步;推杯 6.2K 步(约 90 分钟)做 25 次查询,盖布 25K 步(约 4 小时)做 50 次查询,插书 19K 步(约 3 小时)做 75 次查询(p.7)。对照含朴素分类器、off-policy VICE、RAQ。

## 主要结果 & 结论
- **三任务成功率(10 次试验平均)**:VICE-RAQ 三项全部解决,VICE 与 RAQ 各只在部分任务成功、另一些失败(`"In all cases, VICE-RAQ succeeds at learning the task, while VICE and RAQ succeed at some tasks while failing at others"`,p.7);表 5 给出数字 VICE-RAQ 100/100/100、RAQ 60/100/0、VICE 0/100/60、朴素分类器全 0。
- **推杯**:VICE-RAQ 100%、RAQ 仅 60%,off-policy VICE 与朴素分类器均失败(p.8)——表明主动查询有用,且 VICE-RAQ 能进一步利用 RL 过程中策略采到的数据。
- **插书**:RAQ 单独解决不了、off-policy VICE 只偶尔成功,只有 VICE-RAQ 稳定解决(p.8)——查询标签 + VICE 的全状态负样例两者结合改善了分类器训练。该任务还展示"分类器比目标图像更有表达力":方法会按书的起始位置插进最近的空槽以最大化分类器奖励,而目标图像方式会总插进固定槽(p.7,图 6)。
- **盖布**:只用末端 3D 位置 + 手工欧氏距离奖励的基线失败(走直线无法盖布),说明此类可变形物体任务必须靠视觉关注布的形变(p.8,图 7)。
- **效率对比**:整套只需 1–4 小时真实交互(p.1);相较从人类偏好学习的工作,Christiano 等在低维仿真中约做一千次查询、需上千万步,而本文真实世界只 50–75 次查询、约数万步(p.2)。

## 核心贡献
作者明确主张的主要贡献:一个从高维观测(图像)学机器人技能、**无需手工设计奖励函数**的框架,用少量正样例(无演示)+ 少量二值主动查询替代奖励工程,底层基于高效 off-policy RL,适合真实世界(`"The primary contribution of this paper is a framework for learning robotic skills from high-dimensional observations ... without hand-designing reward functions"`,p.2)。技术上的两块新东西是:把 VICE 扩展到 off-policy 并去掉用户给动作标签的需求;以及用"查最高成功概率状态"的主动查询机制把所需初始正样例从数千降到很少。

## 局限与我的质疑
- **作者自述局限**(p.8):① 仍需用户提供标签,引入额外假设;② 每次训练约 50 次查询仍非平凡,未来可用贝叶斯神经网络等更聪明的查询准则压低;③ 方法不利用任务间共享结构,跨任务元学习或可进一步减少查询/样例。
- **实验规模太小、统计不足**:三个真实任务、每个仅 10 次试验,且成功率清一色 0/60/100 这种粗粒度数字。VICE-RAQ 三项满分很漂亮,但 n=10 下 100% 与 60% 的差距置信区间很宽;论文没给方差/多随机种子,"VICE-RAQ 全面优于基线"的结论证据强度只能算 observed,不宜读成稳健的统计显著优势。
- **没有真正的强外部基线/SOTA 对比**:对照组全是作者自家方法的消融(RAQ、off-policy VICE、朴素分类器)和一个手工奖励基线。没有跟同期其他无奖励工程方法横向比,所以"更高效""1–4 小时远少于先前工作"主要是定性叙述,缺直接同条件对照。
- **查询选取机制的隐含代价**:"挑成功概率最高的状态去问"很巧妙,但它高度依赖人在回路中**可靠、即时**地判定成功;一旦标注有噪声或主观(尤其盖布"无褶皱"这类边界判断),奖励可能系统性偏移,文中未做标注噪声敏感性分析。
- **"无奖励工程"是否被过度解读**:方法确实免了手写奖励函数,但把工作量转移到了"准备 80 张成功样例 + 设置查询频率 + 人值守应答查询"。对成功条件本身高度视觉化、人一眼能判的任务才成立;对需要精密物理量(力、精度)判定成功的任务,这套二值查询未必够用——论文未触及这类任务边界。
- **与本研究主题(去除奖励工程/规约痛点)的契合与不足**:正面直击 reward specification 痛点,主动查询 + off-policy 是很实用的工程组合;但它解决的是"如何判定成功(终局奖励)",对"过程塑形/稠密奖励设计"基本靠 mixup 平滑 + log 概率的隐式 shaping,没有正面处理长程稀疏任务的探索难题,泛化到更复杂多阶段任务的能力本文未予证明。
