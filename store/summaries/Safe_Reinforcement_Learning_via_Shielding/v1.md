# Safe Reinforcement Learning via Shielding
> Mohammed Alshiekh, Roderick Bloem, Rüdiger Ehlers, Bettina Könighofer, Scott Niekum, Ufuk Topcu · 2018 ·  · 引用 617 · DOI 10.1609/aaai.v32i1.11797

## 一句话
用形式化方法（反应式综合）从时序逻辑安全规约自动合成一个叫"盾（shield）"的反应式系统，把它套在 RL agent 与环境的回路里，强制保证学习和执行全程都不违反安全约束，且对学习算法几乎无侵入。

## 解决了什么问题
RL 只优化累积奖励，**不保证学习期或执行期的安全**——探索过程会撞墙、闯红灯、让系统进入灾难态。已有"安全 RL"要么只能表达简单不变式（invariance），要么靠人类老师临时给建议、靠调奖励来软约束，**都给不出硬保证**。作者要的是：在一段事先未知的最优性能目标之上，叠加一层可形式化验证的、确定性的安全保证。

## 用什么方法解决的
1. **规约**：用线性时序逻辑（LTL）的**安全片段**写"坏事永不发生"，转成确定性安全自动机 ϕs。
2. **环境抽象**：给环境 MDP 一个粗粒度有限状态抽象 ϕM（保守、可远少于真实状态数，甚至真实状态无穷也行），用来"提前规划"——在不可逆地走向危险之前就拦住。
3. **博弈求解**：把 ϕs 与 ϕM 的乘积构造成一个二人安全博弈（环境选观测、系统选动作），用标准安全博弈求解算出**赢区 W**，再翻译成一个反应式系统——这就是 shield。它保证**正确性**（只走安全态）与**最小干预**（只在动作可能导致无法挽回的违规时才禁，证明了这是所有合规盾里最不啰嗦的）。
4. **两种接法**：
   - **抢先式（preemptive）**：盾在 agent 之前，每步先给出一份安全动作清单，agent 只能从中选。
   - **后置式（post-posed）**：盾在 agent 之后，监视 agent 选的动作，仅当不安全时才替换成安全动作；agent 甚至可以不知道自己被罩着。后置式还支持 agent 给动作**排序**，盾选排序里第一个安全的；并可对被改写的动作给惩罚 r′<0 或照常给奖励 r，借此一步做多次策略更新。
5. **收敛性**：把盾和 MDP 合成乘积 MDP M′，论证凡在标准 MDP 上收敛的学习算法在加盾后仍收敛（后置式需要"无安全动作时按固定分布兜底"这一条件）。

## 动机 & 背景
学习型控制器越来越多地部署在人身边，安全/正确性受关注却远不如收敛性、最优性研究得透。作者从形式化方法视角切入：先用时序逻辑给"安全/正确"一个无歧义且足够丰富的定义，再回答核心问题——"**能放手时就让 agent 随便做，只在绝对必要时才介入**"。Shield 的思想源自 Bloem 等人 [3] 的运行时强制（runtime enforcement），本文是把它针对 RL 场景做的具体实现，并强调盾的构造代价只取决于规约复杂度和很抽象的系统模型、**与被控系统中与安全无关的状态分量数无关**——这是相对 Wen et al. [23]、Junges et al. [10] 的关键优势（后者不支持函数逼近，难上复杂场景）。

## 方法细节
- **安全规约**：trace 不在语言里 ⇒ 必有有限前缀使后续全部出界，即"坏事永不发生"。可表达不变式，也能表达"阀门一开必须保持开至少三秒"这类时序约束。
- **抽象的作用**：博弈里环境玩家选标签 L（来自 MDP 观测），系统玩家选动作 A；安全态集合 F^g = (F×QM) ∪ (Q×(QM∖FM))——即"规约满足"**或**"抽象已被证伪"都算系统赢，因为系统只需在符合抽象的环境里正确。
- **最小干预的证明**：若盾禁了某动作，作者构造一个与已观测行为和抽象一致的"另一个 MDP M′"，其中所有抽象允许的有限 trace 都有非零概率发生，从而证明放行该动作会带来非零违规概率，故必须禁。
- **盾的规模**：状态空间 = 抽象 × 规约自动机的乘积，可能很大；但若规约是"每步标签满足某条件"这类单状态规约、且抽象态可由最后一个 MDP 标签确定，盾可化简为单状态，此时 learner 只需观测 MDP 自身状态，**与无盾时无异**。

## 数据集 & 实验设置
四个场景，机器为 i7-4790K + 16GB RAM / Ubuntu 16.04，源码与输入文件公开（github.com/safe-rl/safe-rl-shielding）：
1. **格子世界**：9×9（含四个炸弹、需按序访问彩色区，约束 ϕs1 不撞墙/对手 + ϕs2 炸弹上不超两步）与 15×9（绕圈移动的对手）。tabular Q-learning + ε-greedy，可一次多更新。盾合成耗时 2s / 0.6s。
2. **自动驾驶**：480×480 环境，学顺时针绕街区，避免撞墙。DQN + Boltzmann 探索，抢先式与后置式盾各 2s 合成。
3. **Atari Seaquest**：DQN（DeepMind 方法的 Python 复现）以 RGB 像素为输入，agent 当黑盒；两条约束：缺氧前必须浮出、未救潜水员且氧足时不许浮出。
4. **水箱**：不可干涸/溢出 + 阀门切换后至少保持 3 步；后置式盾 <1s 合成，对比 Q-learning 与 SARSA。

## 主要结果 & 结论
- **格子世界**：只有无盾版本出现负奖励；加盾版本不仅安全，还**学得更快**。15×9 里只有 |rankt|=3 且无惩罚的盾找到最优路径；|rankt|=1 或带惩罚则次优。带大惩罚的无盾版本既没达到最高分、也没加速学习。
- **自动驾驶**：无盾累积奖励虽上升但到仿真末期仍会撞车；无惩罚的盾版本学得更快且**从不撞车**。
- **Seaquest**：加盾**不改变性能曲线**，但两条安全规约始终不被违反（说明黑盒套盾零代价）。
- **水箱**：加盾与不加盾的 Q-learning / SARSA 都能收敛到最优策略，但加盾版本**显著更快**达到最优。
- 总结论：所有场景中加盾 agent 表现**至少不差于**无盾，多数情况下还改善了学习性能；盾只依赖输入输出行为、环境抽象与规约，与学习算法内部细节无关。

## 核心贡献
1. 提出"**盾**"框架，把时序逻辑安全规约的硬保证与 RL 的最优性结合，给出**安全 RL** 的形式化定义（学习与执行两阶段都满足 ϕs）。
2. 给出从安全规约 + MDP 抽象经安全博弈求解**自动合成盾**的算法，并形式化证明其**正确性**与**最小干预**最优性。
3. 提出抢先式与后置式两种接法，后置式可把已训练好的黑盒策略也罩住，并讨论了惩罚/奖励两种回写与动作排序变体。
4. 给出加盾后学习算法的收敛性论证，并在四类（含 Atari 像素输入）场景实证盾能在保证安全的同时往往加速学习。

## 局限与我的质疑
- **作者自述的核心局限**：必须事先有一个"何时何动作不安全"的环境抽象模型，否则无从知道哪些动作可放行。作者辩称这"不可避免"，但这恰恰是整套方法的命门——**抽象的获取成本与正确性被一笔带过**。一旦抽象错（不保守或漏建模），最小干预证明里"抽象被证伪即系统赢"的设计意味着盾会**默默放行**，安全保证就此失效，而论文没给任何"抽象错误"的鲁棒性实验。
- **可扩展性存疑**：盾的状态空间是抽象 × 规约的乘积，作者也承认"可能很大"。所有实验都是**离散、低维、安全规约极简**的玩具环境（格子、4 维车状态、两条氧气规则）。Seaquest 虽是像素输入，但盾只管"氧气/深度/潜水员数"这几个从模拟器**特权读取**的离散量，并没有从像素里学安全模型——这与真实"端到端从感知到安全"的难度不在一个量级。LTL→安全博弈在连续高维状态上是否可行，**完全未触及**。
- **"加盾还更快"的结论可能被过度解读**：加速主要来自盾让 agent 跳过了在不安全动作上的无效探索 + 一次多更新（|rankt| 排序），这是**特定任务结构**下的便利，并非普遍规律。在安全约束与最优策略高度耦合、或盾频繁干预的任务里，硬性遮蔽完全可能把 agent 引向次优（论文自己的 |rankt|=1/带惩罚版本就只收敛到次优路径），样本太少不足以支撑"多数情况改善性能"的普适断言。无 error bar、无多 seed 统计，曲线说服力有限。
- **与"RL 训练数字人与环境交互"主题的差距**：本文的安全是**离散符号约束**（不撞墙、不溢出），而数字人/具身交互的安全更多是**连续、高维、接触丰富的物理约束**（关节限位、平衡、与人接触力、避碰人体），很难写成干净的 LTL 安全自动机，也很难给出可博弈求解的有限抽象。后置式"罩黑盒策略"的思路对数字人有吸引力（可套在已训练的运动策略外），但**动作空间连续**时"枚举安全动作清单/替换为安全动作"如何实例化、实时性如何保证，本文没有答案。把它当数字人安全层用，最多是高层离散决策（如交互意图调度）的护栏，触及不到底层运动控制的安全。
- **奖励回写方案两难未解**：后置式给不安全动作回写真实奖励 r 时，agent 可能把不安全动作学成"最优"，于是盾**永久不能撤**；回写惩罚 r′ 又破坏了"对学习算法无侵入/不改奖励"的卖点。两条路都让"盾只在训练期需要、之后可摘"的理想落空——这在部署成本上是实打实的代价，论文只是陈述而未量化。
