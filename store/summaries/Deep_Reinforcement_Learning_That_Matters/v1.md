# Deep Reinforcement Learning That Matters
> Peter Henderson, Riashat Islam, Philip Bachman, Joëlle Pineau, Doina Precup, David Meger · 2018 · Proceedings of the AAAI Conference on Artificial Intelligence · 引用 1499 · DOI 10.1609/aaai.v32i1.11694

## 一句话
一篇通过系统实验揭露"深度强化学习结果极难复现"的实证警示论文：超参数、随机种子、环境选择、代码实现这四类内外因都能让同一个算法的报告结果天差地别,因此必须配套显著性检验和更严格的实验报告规范。

## 解决了什么问题
深度 RL 论文蓬勃增长(图1),但同一个 baseline 算法在不同论文里报出的结果范围极宽,新方法"超越 SOTA"的说法很难判断是真改进还是噪声/挑数据。作者要回答:深度 RL 的结果到底为什么这么难复现?哪些因素在作祟,各自影响多大?以及该用什么统计手段和报告规范来止血。

## 用什么方法解决的
聚焦连续控制下的策略梯度类算法(TRPO、DDPG、PPO、ACKTR),主要用 OpenAI Baselines 实现,在 MuJoCo / OpenAI Gym 环境(Hopper-v1、HalfCheetah-v1,部分加 Walker2d-v1、Swimmer-v1)上做受控实验:每次只动一个待研究的超参,其余用默认值,每种配置跑 5 个固定随机种子、训练 2M 步。逐项考察网络结构与激活函数、奖励缩放、随机种子、环境特性、代码库差异五个变量对结果的影响;再引入机器学习/统计里的 bootstrap 置信区间、功效分析(power analysis)、2-样本 t 检验、K-S 检验等显著性工具,演示如何更可靠地比较算法。

## 动机 & 背景
RL 近年在机器人连续控制、围棋、Atari、竞技游戏上成果亮眼,论文数量逐年激增(图1)。但要维持这种进展,前提是已有工作能被复现、新方法能被公正比较。现实却是复现深度 RL 极其困难,文献里同一 baseline 报出的结果范围很宽(引 Islam et al. 2017)。作者把影响复现性的因素分成两类:**外在因素**(超参数、代码库)与**内在因素**(随机种子、环境随机性等方法固有方差)。相关领域(监督学习、ALE 评测)已有人讨论复现性与实验规范,但作者称这是**首篇**在深度 RL 语境下系统讨论该问题的工作。

## 方法细节
- **算法**:四个有公开实现、常被当 baseline 的免模型策略梯度方法——TRPO(共轭梯度+KL 约束)、PPO(把约束改成惩罚/裁剪目标)、DDPG(确定性策略的 actor-critic,off-policy)、ACKTR(Kronecker 分解的信赖域)。论文给出了策略梯度定理与各方法的优化目标公式。
- **实验协议**:大部分实验用 OpenAI Baselines 实现(代码库对比实验除外);每种评估跑 5 个**预设且全实验共用**的随机种子;尽量用默认设置,只改当前研究的超参;函数近似一律用 MLP,并明确各算法的隐层尺寸与激活(如 DDPG actor/critic 用 (64,64,ReLU),TRPO/PPO 策略用 (64,64,tanh) 等)。
- **考察的变量**:① 网络结构((64,64)/(100,50,25)/(400,300))与激活(tanh/ReLU/LeakyReLU);② 奖励缩放(σ̂ 从 1e-4 到 100,含有无 layer norm);③ 随机种子(跑10个种子,拆成两组各5个分别平均);④ 环境特性(4个 MuJoCo 环境横扫);⑤ 代码库(同一算法的不同实现:TRPO 三种、DDPG 三种)。
- **统计工具**:bootstrap(10k 次重采样)求均值与95%置信区间;bootstrap 功效分析判断是否需要更多 trial;2-样本 t 检验、K-S 检验、bootstrap 百分比差异。作者也区分了"在线学习视角"与"策略优化视角"两种评估口径。

## 数据集 & 实验设置
- **环境**:OpenAI Gym 的 MuJoCo 连续控制任务,主用 Hopper-v1(动力学更不稳定)、HalfCheetah-v1(更稳定),环境实验扩展到 Walker2d-v1、Swimmer-v1。
- **训练量/评估**:训练 2M 时间步;表1、表2 报的是 5 次 trial、最后 100 条轨迹回报的"均值 ± 标准误"。表3 给出 bootstrap 均值和95%置信界。
- **关键现象**:
  - 网络结构/激活影响巨大且**跨算法、跨环境不一致**——同一改动在不同算法上效果相反;大网络(400,300)使 PPO/部分配置崩溃,作者发现大网络的更新 KL 散度平均是 (64,64) 的 33.52 倍。
  - 奖励缩放影响大但同样不一致;DDPG 在 σ̂<0.01 的小尺度下学不动,且 layer norm 会改变缩放的作用方式。
  - **随机种子**:仅靠不同种子,把10个 run 拆成两组各5个分别平均,两条学习曲线能落到统计上不同的分布(t=−9.09, p=0.0016)。即同样的超参也能"刷"出显著不同的结果。
  - **环境**:没有全场通吃的算法。HalfCheetah 上 DDPG 最强,但到不稳定的 Hopper 上优势骤降(DDPG 退化成"靠存活奖励苟到回合结束"的局部最优);Swimmer 上 TRPO 远超他者,但其实只学到"蜷缩扑腾"的局部最优(回报~130,视频可见并非真会游泳)——所以只报回报不放策略演示会误导。
  - **代码库**:同一算法的不同实现,在相同超参下最终性能差异巨大(表1/2、图6),很多实现细节论文里根本没写。

## 主要结果 & 结论
深度 RL 的复现困难来自内在(随机种子、环境随机性/特性)和外在(超参数、代码库)两类非确定性,且各因素影响因算法和设置而异、极不一致。高方差使得"更高平均回报"未必代表"更好",必须做显著性分析。作者的核心建议:
1. 超参要做标准搜索,至少复现出 baseline 原报告性能;新实现要对齐原代码库结果。
2. 因方差大,必须用**多个不同随机种子**多次运行并报告分布,而非挑 top-N 或只跑 <5 次取平均。
3. 做**显著性检验**(t 检验/K-S/bootstrap 置信区间),并可用 bootstrap 与功效分析估计需要多少 trial。
4. **最重要**:完整报告所有超参、实现细节、实验设置和评估方法,并随论文公开代码。
5. 既报回报曲线也要展示学到的策略行为(避免把局部最优当成功);多环境报告,别只挑赢的那个。
6. 呼吁研究"超参不敏感(hyperparameter-agnostic)"的算法,以及更适合 RL 的显著性度量;并多讨论算法到底在什么真实场景下有用("让深度 RL 真正 matter")。

## 核心贡献
- 首次在深度 RL 语境下系统量化"复现危机":用受控实验把内外四类非确定性来源(超参/代码库/随机种子/环境)逐一拆开并演示其破坏力。
- 给出"仅凭随机种子就能制造统计显著差异"的标志性反例,直接动摇了大量论文的实验可信度。
- 把 ML/统计学的 bootstrap 置信区间、功效分析、显著性检验引入 RL 评估,并给出可操作的报告规范清单——成为后续 RL 实证方法学(如多种子评测、报告标准)的奠基性参考。

## 局限与我的质疑
1. **作者自述局限**:实验只覆盖连续控制下的策略梯度类算法(TRPO/DDPG/PPO/ACKTR)和少数 MuJoCo 环境,主结论多基于 Hopper/HalfCheetah 两个环境;且承认无法给出"该跑多少个种子/trial"的确切数字,从 ML 借来的修正显著性检验其假设未必适用于 RL,合适的 RL 显著性度量仍待研究。这意味着论文是"诊断+倡议",并未给出一套被验证好用的标准方案。
2. **样本量自身的方差悖论**:全文论证"5 个种子不够、方差极大",但很多关键实验(表1/2)恰恰只用了 5 个种子、报标准误。用一个被自己批评为不足的样本量去下"差异显著"的结论,统计基础其实也脆弱;那个 t=−9.09 的著名反例本身就是从小样本里挑出来的极端切分,有 cherry-pick 之嫌——它能证明"种子可以制造差异",但不能量化这种情况有多普遍。
3. **结论易被过度解读**:论文常被引用为"深度 RL 结果都不可信"。但作者真正展示的是"报告不规范+不做显著性检验时容易误导",并非算法本身无效。把方法学警示等同于"RL 没用"是过度延伸;反过来,论文给的建议(多种子、报全超参)是必要条件而非充分条件,照做也不保证可复现。
4. **未触及问题的"为什么"**:论文充分记录了"现象"(种子/超参/实现差异大),但对内在机制解释偏定性(如归因于深网络追踪移动目标、off-policy 探索噪声),缺乏对方差来源的理论刻画或可预测的诊断,工程上难以据此提前判断某个结果是否可靠。
5. **与本主题(用 RL 训练可与环境交互的数字人)的差距**:本文环境是 Hopper/Cheetah 这类低维 MuJoCo 仿真,既无高维感知、无人机交互/社交对象,也不涉及人类反馈、模仿学习或 sim-to-real;它给数字人训练的价值在**方法学层面**(必须多种子、报方差、做显著性、展示真实行为而非只看回报曲线,警惕"苟存活/蜷缩扑腾"式局部最优),而非任何可直接迁移的算法或数字人交互结论。对于训练数字人这种回报函数更复杂、行为质量难以用单一标量回报衡量的场景,本文"只报回报会误导、要看策略演示"的告诫尤其值得吸取,但论文本身并未涉及这类任务的评估难题。
