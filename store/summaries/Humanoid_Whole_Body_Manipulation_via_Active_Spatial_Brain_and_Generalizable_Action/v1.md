# Humanoid Whole-Body Manipulation via Active Spatial Brain and Generalizable Action Cerebellum
> Zhizhao Liang, Yi-Lin Wei, Xuhang Chen, Mu Lin, Yi-Xiang He, Zhexi Luo, Jun-Hui Liu, Kun-Yu Lin, Wei-Shi Zheng · 2026 · arXiv · 引用 0 · DOI arxiv:2605.21133

## 一句话
用"大脑(VLM主动空间感知+规划)+小脑(多智能体动作生成)"的多智能体框架,让人形机器人在复杂3D场景里完成全身操作,且**完全不需要任务专属的真机数据**来训练。

## 解决了什么问题
把桌面级操作扩展到"空间感知型人形全身操作(spatial-aware humanoid whole-body manipulation)"时面临两大难题:1)**空间理解难**——真实3D环境中物体遮挡、空间关系复杂,固定视角不够用;2)**动作泛化难**——真机数据昂贵稀少,数据驱动模型在分布外(新物体、新空间布局)泛化差。作者想绕开"靠大规模真机数据训练策略"这条路。

## 用什么方法解决的
提出分层多智能体闭环框架,由两大组件构成:
- **Active Spatial Brain(主动空间大脑)**:基于主流VLM,做主动感知+决策。含三模块:① 主动空间感知——VLM直接从视觉+指令决定相机视点,机器人配 2-DoF 颈部相机 + 4-DoF 底盘移动(x/y/z 平移 + z 轴旋转)主动探索;② 记忆库(Memory Bank)——只保留"上次底盘移动以来"拍的图(配相机位姿)+ 全局文本执行历史,以维持空间一致性;③ 自适应任务规划——把长程目标拆成子任务,每步对照记忆库判断阶段,触发"调视点"或"调用小脑智能体",并在失败时(如抓取失败)自主重规划再试。
- **Generalizable Action Cerebellum(可泛化动作小脑)**:把全身控制拆成上下半身,由多个 foundation-model 驱动的动作智能体执行,**无需任务专属真机数据**。
  - 下半身:**导航智能体**(深度图→点云→投影成栅格图→A* 求无碰撞路径→RDP 简化成航点)做远距粗接近;**末端可达空间求解器(EES)**——用带约束的优化(式2/3)求底盘水平+高度微调 Δd、Δz,把目标拉进肩部工作空间(臂长 L、安全系数 η=0.8),并用 MuJoCo 标定的运动学偏移模型 Φ(z) 修正高度变化对肩部位姿的影响;底层用按 HOMIE 训练的 RL 运动策略 πloco 把底盘指令转成关节动作。
  - 上半身:**抓取生成智能体**——多模态生成模型先合成"手-物交互图像",再经 Hyper3D 重建物体网格 + EasyHOI 估计 MANO 人手姿态,最后通过指尖对齐优化(式6)重定向到灵巧手;**抓后轨迹智能体**——预测语义2D关键点 + 选择动作原语(推/拉/放/转),抬升到3D后按原语运动学规则得6-DoF末端位姿,IK解成关节指令。

## 动机 & 背景
人形机器人因全身移动+灵巧操作能力,在家庭/工业场景潜力大,但全身操作把观测空间和动作空间都大幅放大,对训练数据需求极高。已有工作靠人类动捕/仿真/桌面数据缓解,但仍受 sim-to-real gap、本体差异、空间分布偏移困扰,真实非结构化环境中鲁棒性和泛化都差。作者主张直接利用当前 VLM 的空间智能与可泛化知识,做"零真机数据"的框架。相关工作覆盖三块:全身操作(遥操作模仿学习、RL 如 AMO/VIRAL)、LLM 驱动操作(Code as Policies 等,但多限于固定视角桌面)、机器人空间智能(显式空间建模 / 空间感知 VLA / 空间 affordance,但多限桌面或简单 loco-manipulation)。

## 数据集 & 实验设置
- **硬件**:Unitree G1 人形 + 两只 6-DOF Inspire FTP 灵巧手 + 2-DOF 主动 RealSense D435i 相机。
- **空间智能 Benchmark(评 VLM 本身)**:Task1 把打乱的9张图复原成 3×3 网格(结构匹配准确率);Task2 VLM 驱动主动相机定位初始不可见/被遮挡目标;Task3 在杂乱障碍场景预测到达目标的地面航点(按避障距离评 Appropriate/Inappropriate/Fail)。评测了 gpt5.1、gemini-3-flash、gemini-3.1-pro、qwen3.5-plus。
- **真机任务(评框架)**:5 类设置,各含 easy/hard:① 不同高度;② 不同位置;③ 高度+位置;④ 避障;⑤ 遮挡处理(先移开遮挡物)。每设置 10–30 次试验,报成功率(发生碰撞即算失败),各方法试验数一致。
- **基线**:数据驱动的 TrajBooster、Ψ0(用官方权重微调,每设置 easy 配置至少采 20 条轨迹做后训练),VLM 驱动的 CaP(Code as Policies)。

## 主要结果 & 结论
- **真机对比(Table 1)**:Easy 设置本方法在 Task1/3/4/5 上领先(如 Task1 85 vs Ψ0 80);Hard 设置优势显著拉开,本方法在5个任务上分别为 60/70/55/60/60,远超 TrajBooster(40/20/10/0/20)、Ψ0(60/35/25/0/30)、CaP(65/50/35/30/35)。数据驱动方法在 hard(分布外)上崩塌(Task4 甚至 0)。
- **泛化(Fig7/Table2)**:本方法可达区域更广更可靠;跨物体类别对未见物体仍稳(如 Tools 77.8 vs Traj. 50.0,Items* 69.6 vs 50.0)。
- **消融(Table3)**:去掉主动感知(AP)Task3 类性能大跌(高度+位置 18.8 vs 完整 67.5);去掉 EES 也明显下降(避障 33.4 vs 70.0);两者齐备最好。
- **VLM 空间智能(Table4)**:当前 VLM 擅长粗粒度/关系型空间推理(Task1/2,gemini-3.1-pro 网格复原 98.84%、主动感知成功率 94.11%),但在需从2D做细粒度度量感知的 Task3 上普遍弱(航点 Appropriate 最高仅 64.91%)——这正佐证了"VLM 做高层规划、把细粒度动作交给专门模块"的解耦设计。
- 结论:大模型驱动的主动空间感知+决策,配合无需任务专属真机数据的动作生成,能实现可泛化的人形全身操作。

## 核心贡献
1. 提出"主动空间大脑 + 可泛化动作小脑"的分层多智能体闭环框架,面向空间感知型人形全身操作。
2. 主动空间感知机制(VLM 直接决策 2-DoF 颈 + 4-DoF 底盘视点)+ 运动条件记忆库,维持长距移动下的空间一致性。
3. 可泛化动作小脑:导航 + EES 可达空间优化求解 + 抓取/轨迹原语智能体,**零任务专属真机数据**即可生成物理可行全身动作。
4. 构建空间操作 benchmark(VLM 空间智能 3 任务 + 真机 5 类任务),系统评测主流 VLM 并验证框架优于数据驱动与 VLM 基线。

## 局限与我的质疑
1. **作者自述局限有限,但 VLM 是显性短板**:论文自己的 Table4 显示当前 VLM 在细粒度度量空间感知(Task3 航点)上很弱(最好约65% Appropriate)。框架靠"解耦"把这块外包给几何求解器/原语,但导航航点本身仍依赖 VLM 给目标像素坐标与场景判断,这层一旦出错,下游优化再准也无意义。整体性能上限被 VLM 空间能力封顶。
2. **"零真机数据"被过度宣传**:框架并非真的不依赖学习/数据——下半身 RL 运动策略 πloco 沿用 HOMIE 训练(那是要数据/仿真训练的),抓取依赖 Hyper3D、EasyHOI、底层多模态生成模型,这些都是大规模数据训练出来的 foundation model。准确说法应是"无需**本任务专属**的真机示教数据",而非"data-free"。题目/摘要的 generalizable / real-robot-data-free 措辞有夸大嫌疑。
3. **实验规模与统计可信度不足**:每设置仅 10–30 次试验,成功率以 5/10 的粒度跳动(表里大量整十数:0、60、70),置信区间必然很宽,却无误差棒/方差/显著性检验。Hard 设置 baseline 出现 0%,而本方法 60%,这种悬殊更需要重复实验佐证而非单轮试验。
4. **与"RL 训练数字人与环境交互"主题的根本错位**:本工作核心是 **VLM 多智能体编排 + 经典几何/优化(A*、IK、约束优化)**,RL 只是底层一个被沿用的 locomotion 控制器,且非本文训练贡献。它不学习交互策略本身,而是把交互拆成预定义原语(推/拉/放/转)由规则驱动。相比端到端 RL 学习与环境交互的范式,这是"用大模型规划 + 传统控制拼装"的工程路线,泛化来自 foundation model 的先验而非交互中学习,因此遇到原语库未覆盖的新交互模式(如柔性物、双手协同、接触力调控)很可能无法应对。
5. **闭环鲁棒性证据薄弱**:重规划机制(失败重抓)只给了定性图示(Fig4),没有量化"重试带来多少成功率提升"、平均重试次数、失败模式分布;记忆库"只存上次移动后的图"是否真能避免长程任务的状态遗忘,也缺消融。
6. **可复现性**:大量关键组件是闭源/外部服务(gpt5.1、gemini、Hyper3D 等),抓取流水线串了多个第三方模型,版本/接口一变结果可能不可复现,且推理时延较高(Table4 单任务动辄数十秒至上百秒),对真实闭环操作的实时性是隐忧。
