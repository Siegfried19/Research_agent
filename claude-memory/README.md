# 文档地图（什么去哪找）

> 新会话/新 agent 开局：先读仓库根 `CLAUDE.md`（速查+铁律+本地图指针），再按需跳这里。
> 一个原则：**一件事只有一个家**。现状、过程账、全局时间线各有归属，别重复写。

## 去哪找什么

| 你想要 | 去哪 |
|---|---|
| 整体框架 / 数据模型 / 脚本清单 / 模块间连接 / 总蓝图 | `ARCHITECTURE.md` |
| 某模块**现在**怎么设计的（边界/关键脚本/为什么） | `modules/<模块>/README.md` |
| 某模块**此刻状态 / 在查的 bug / 历史**（为什么这么改） | `modules/<模块>/STATE.md` |
| 横切/深度设计长文（质量体系等） | `design/` |
| 运维：夜间 cron / 换机器 / 远程 / Telegram | `ops/` |
| 全局跨模块的改动时间线 | `../claude_log.md` |

**5 个模块**：find（发现+打分+入库）· fetch（四级取全文）· summarize（写中文总结）· verify（跨模型核查）· retrieve（知识库检索/RAG）。

## 三种文件的分工（重要）

| 文件 | 性质 | 怎么写 |
|---|---|---|
| `README.md`（模块/ARCHITECTURE）| 现状设计 | **覆盖更新**，永远是"现在的样子"的干净视图 |
| `STATE.md`（每模块）| 层积日志 | **只增不删，新在上、老在下，每条带日期+时间戳**。顶=此刻，下=历史 |
| `../claude_log.md` | 全局时间线 | 按时间记全项目改动；模块内的活留一行指针，跨模块/全局的活在此详记 |

类比：`README`=当前代码，`STATE`=本模块的变更日志，`claude_log`=全项目的 commit 时间线。

## 记账规矩（改完收尾前）

1. **改一个模块** → 详细写进该模块 `STATE.md` 顶部（含"改了啥/为什么/现在到哪/卡哪"，带时间戳，**不删旧条**）。
2. **改两个模块之间的连接 / 全局** → 写 `../claude_log.md`（它是这类活的详情家）；在涉及的每个模块 STATE 顶部留**一行指针**（"⚠️ 与 X 的接口改了，详见 claude_log / ARCHITECTURE"）。连接的**设计**沉淀到 `ARCHITECTURE.md` 的"模块间连接"节 + 两边 README 各记一句接口。
3. **里程碑级改动** 照旧记 `../claude_log.md`（全局铁律）。
4. **一个 agent 一个模块**：并行干活各写各模块的文件，天然不撞车。

## 两套记忆（边界）

- **机器本地**（harness 记忆 `~/.claude/projects/.../memory/`）：只管"**怎么跟用户协作**"（工作节奏/偏好/约定）。Claude 自动维护，**项目知识一律不放这**。
- **随 git**（本 `claude-memory/` + `claude_log.md`）：**项目本身的知识**。跨机器、并行 agent 全靠它。
