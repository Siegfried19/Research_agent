## 为什么去 note_plan —— 实测危害证据（这是本文要留的"为什么"）
1. **"无锚论断"假阳性洪水 → 版本通胀**（最硬的账）：note_plan 被当成"完整锚点清单"，但撰写者从不把每条论断都登记成锚点；于是 verify 把每条**未登记但原文其实支持**的论断标成 `[minor] 疑未接地`。叠加旧"非 pass 全重写"策略 → v2/v3 暴涨但多非真修（见 `modules-modification/verify/STATE.md`）。
2. **接地门只验"引文在不在"、不验"绑得对不对"** → 防的是编造引文，**防不住真正危险的张冠李戴**（引文是真的、被安到错对象）。收益错位。
3. **两段式"把数字从语境剥离成锚点"本身是张冠李戴诱因**（GAE/Learning-to-Walk；机制性风险确在）。
4. **接地门防的威胁本就几乎没发生**（复查 2026-06-10 老总结时代报告）：严格"编造引用"无记录；唯一真跑那次 bake-off 36 条引文全过、一个都没抓到，那篇真幻觉是 **codex 抓的**。真正发生的 major 是数字写反/基线抄错/消融归因写反/过度概括/张冠李戴/编造内容——**接地门一个都接不住，本就得靠 codex**。
→ 结论：note_plan 的活被「数字不再每句挂锚点 + codex 语义核查抓张冠李戴」覆盖，危害却仍在 → 去掉。删它不放走任何它真在防的东西。
