# Skill 是怎么构成和调用的（直觉版）

> 一句话类比：**Skill 就像给员工的一份"工作手册"。** 主手册自动加载，附录、脚本、助手都"按需召唤"——省脑子、各司其职。

---

## 一、主文件 `SKILL.md`（手册本体 / 总指挥）

一个 skill 就是一个文件夹，里面必有一个 `SKILL.md`：

```
~/.claude/skills/<技能名>/
├── SKILL.md          ← 必需，入口
├── reference.md      ← 可选，参考资料
├── template.md       ← 可选，模板
└── scripts/foo.py    ← 可选，脚本
```

`SKILL.md` = frontmatter（元信息）+ 正文（指令）：

```markdown
---
name: 技能名              # kebab-case，就是 /技能名
description: 干什么 + 什么时候触发   # 模型靠这句判断要不要用
---

正文：被触发后照着做的步骤、约定、禁忌、要跑的命令。
```

**加载时机**：平时不占上下文；只有被触发（用户打 `/技能名`，或模型根据 `description` 自动判断匹配）时，**正文才整段加载**进来。

正文是**从上往下顺着读、顺着做**的——它就是总指挥，决定一切时机和顺序。

---

## 二、子文件（附录 / 模板 / 脚本）

平时**都不加载**，省上下文。它们不会"自动"被用——必须在 `SKILL.md` 正文里用文字**点名**，模型才会按需去取。两种取法：

**① 读进来（.md、模板、文档）**
正文写一句指路：「详细规则见 `reference.md`」/「按 `template.md` 格式输出」
→ 模型用 **Read** 打开 → 内容这时才进上下文。

**② 跑起来（.py、.sh）**
正文写明命令：「运行 `python scripts/foo.py <参数>`」
→ 模型用 **Bash** 执行 → 脚本被**执行**而非读入 → 只有它的输出（stdout）回到对话。

> 一句话：子文件 = 正文里点名，**Read 取内容 / Bash 取结果**，按需加载。路径相对 skill 文件夹写。

---

## 三、子 agent（把活外包给一个独立的"助手"）

子 agent 和子文件不同：子文件是"资料/工具"，子 agent 是**一个有自己独立上下文窗口的执行者**。你给他一句话任务，他自己关起门来干（有他自己的脑子），干完只把**最终结论**交回来，中间过程你不用管。还能同时派好几个助手并行干。

要分清两件事：**"干什么"** 和 **"什么时候开始干"** 在不同地方定义。

### "干什么" 拆成两层

**① 它是个什么样的助手（长期身份）** —— 定义在 `~/.claude/agents/<名>.md`
预先写好的"岗位说明书"：角色、能用哪些工具、用什么模型。**和当下任务无关**，是固有人设。结构和 SKILL.md 几乎一样：

```markdown
---
name: code-reviewer
description: 什么时候该派这个 agent
tools: Read, Grep, Bash      # 限定它能用哪些工具（可选）
model: sonnet                # 指定模型（可选）
---

正文：这个 agent 的角色、职责、工作方式（它的系统提示词）
```

（如果用临时通用助手 `general-purpose`，或只读搜索的 `Explore`、出方案的 `Plan`，这层就省了，不用单独定义。）

**② 这一次具体让它做的事（一次性任务）** —— 写在**手册正文里**，作为派活时递给它的那句话（prompt）
比如正文写：「开一个子 agent，让它去 `topics/` 下找出所有还没核查的总结，列个清单回来。」——这句**具体任务**是临时下达的，不在岗位说明书里。

> 类比：岗位说明书说"这是个会查资料的助手"（agents/*.md）；当天你跟他说"去把这批论文清单整理出来"（手册正文里的 prompt）。

### "什么时候开始干" —— 也在**手册正文里**，执行到那一步即触发

正文从上往下读，读到"现在去派个子 agent 干 XX"这一行，就在那一刻派发。所以**时机 = 它在正文里的位置**。正文可以写"先做完 A，再开子 agent 做 B"，顺序和条件都由正文控制。

---

## 四、手册和下面三者的关系（总图）

手册（SKILL.md 正文）是**总指挥**，顺序执行，沿途三种"往下使唤"的动作：

```
用户 /技能名  或  模型按 description 自动触发
        │
        ▼
   SKILL.md 正文（自动加载；从上到下执行，决定一切时机和顺序）
        │
        ├─ 读到"看附录X"        → 去 Read 那个子文件（取内容）
        │
        ├─ 读到"跑脚本X"        → 去 Bash 执行（取结果）
        │
        └─ 读到"派子agent做X"   → 用 Agent 派活
                                  ├─ 它是谁：agents/*.md（岗位说明书，或用通用的）
                                  └─ 这次做啥：手册正文里递给它的那句任务
                                  → 它独立干完，只交回结论
```

**收尾一句话**：
- **手册正文** 管"何时、按什么顺序往下使唤"，是自动加载的总指挥。
- **子文件** 的内容/结果由正文点名后 Read/Bash 取，按需加载。
- **子 agent** 的"固有身份"在 `agents/*.md`，"这次干啥 + 何时开干"都由手册正文当场决定；它独立运行，只交回结论。
