# 打分跨批次校准漂移 — 外部调研结论 + 方案修订（2026-06-17）

> deep-research 拉的带引用报告（22 源 / 100 claim → 25 核查 → 19 确认 / 6 否决）。
> 原始问题见 `claude-memory/modules-modification/find/STATE.md`；本文件 = 结论 + 对我们三步修法的修订。

## 一、文献给的核心诊断

**漂移的学名 = "rubric execution drift"**（RULERS, arXiv 2601.08654, 2026-01）：
同一 rubric 在每次推理时被 LLM 反复重新解释，criteria 定义与分数边界随 prompt 措辞 / criterion 顺序 / 输出格式 / 模型而变。这正是我们"每批独立 claude -p、批间无共享参照系"的病。

**缓解三件套（缺一不可）**：
1. **锁死的固定 rubric**（含明确 score anchors / boundaries，编译成结构化、对同任务全程不变复用的规范）
2. **证据接地**（打分要能追溯到原文证据，不是凭感觉）
3. **对人类边界的事后校准**（截断线附近的校正）

→ 我们原推的三步（加批量 / 共享锚点 / 边界重排）**方向全对**，但侧重要调：②（锚点）从"便宜的预防"升为**头号主力**，并且要补"证据接地"和"分布取均值"两个我们原本没有的零件。

## 二、逐条证据（带引用 + 核查票数）

### (a) 锚点校准 — ✅ high
- **细粒度有序刻度（0-100 或 11 档 Likert）能让 pointwise 逼近 listwise，差异常统计不显著**（"Likert or Not" 2505.19334, 4 LLM × 8+2 数据集）。→ **我们不必抛弃 0-100 打绝对分**，保留刻度是对的，关键是把刻度"钉住"。
- 做法：把**固定的 score anchors**（几个代表性参照样本 + 应得分数 + 理由）写进**每批 prompt 的固定头部、批间一字不改**。直接对应 RULERS 的 anchors/boundaries 锁定。

### (b) pairwise vs pointwise — ✅ high，但**非一边倒，不要盲目换 pairwise**
- pairwise 在**低信号 / 截断线附近会放大 tone/style 等无关 distractor**：加 distractor 后 pairwise 偏好翻转 ~35%，绝对分仅 ~9%（2504.14716, COLM 2025）。**对抗无关风格扰动，pointwise 反而更稳。**
- 另一面：comparison-native（成对比较 → Bradley-Terry 聚合成全局排序，不出绝对分）在论文评审场景优于孤立打分（CNPE 2603.17588, ACL 2026）——但**需要训练，无法用 claude -p prompt 实现**。
- **被否决的对立 claim**（诚实记录）：①"独立绝对打分不可靠"（CNPE 动机句）被 1-2 否；②"pairwise 比 pointwise 更不稳"被 1-2 否。→ 两个方向证据都软，**结论：保留 pointwise 是站得住的，不折腾换协议。**

### (c) 批内位置 / 顺序偏置 — ✅ high（真实且普遍），但对策要谨慎
- listwise 列尾候选系统性更难进顶部；pairwise 换序结论翻转、违反传递性（2604.03642 / 2406.00231 / 2604.27599）。
- **对策**：permutation self-consistency（多排列洗牌聚合）、ICL 示范"看相关不看位置"+ 双向校准 + 多 ranker 聚合（NDCG@10 +6~7，方差大降）。
- ⚠️ **"双向 swap 取均值"并非一律有益**：对 Gemini Pro +4.6pp、对 GPT-4o −2.4pp、对抗集 LLMBar 一律掉 −2.5~−7.0pp（"Judging the Judges" 2604.23178）。**不能默认开，要按模型/任务验证。**
- 对我们：加大批量会**增大**位置偏置暴露面 → 批内**洗牌顺序**是低成本对冲。

### (d) 边界重排 / 两段式 + 稳定化 — ✅ high（直接支持我们的 ③，并给了升级）
- **批量自一致 >> 逐篇**：GPT-4o 批量 1→15 次自一致 NDCG@10 43.8→51.3，逐篇只 44.9→46.8 且慢 15.3×（2505.12570, EMNLP 2025；注：该文 "PW"=pointwise 不是 pairwise）。
- **取分数 token 分布的"均值"而非"众数/greedy"**，三种设置 48 例中 42 例更准（2503.03064, EMNLP 2025）。
- → ③ 升级为：**对截断线附近的边界样本，放同一次调用里 + 多次自一致采样 + 取分数均值**重排，既省成本又稳住翻转。
- **被否决**：① "批量本身提升判断质量（靠 passage 间信息共享）" 被 1-2 否——批量的好处来自**接缝变少**，不是魔法提质；② "离散打分/greedy 最差" 被 1-2 否。→ 加批量要靠"减接缝"这个理由，别夸大。

### (e) 校准陷阱 + 整体范式 / 规模 — ⚠️ medium
- **成败更多由评测 / 截断指标决定**：成本敏感的 WMCC 把"丢失的相关证据"从 Accuracy-best 63.3% / MCC-best 43.9% 降到 5.8%（2511.12635, 9695 篇 SE 系统综述筛选）。**系统综述筛选应优先用召回敏感指标控漏检**——和我们已接受的"结构性偏向假阴性、宁可多收"哲学一致。⚠️ WMCC 要金标注才能算，我们没有，故只能当**哲学**用（截断线宁松勿紧）。
- **绝不逐批 z-score 归一化**：全证据方向一致反对（无单篇直接证伪，故 medium）——它会把"批间真实质量差异"抹平、人为制造翻转。正确做法是**用固定锚点锁刻度，而非按批重标准化**。→ 我们昨晚的 z-norm 陷阱警告**被佐证**。
- **规模演进（2026-06-17 修正，原表述把"几万篇才需 reranker"误套到打分上）**：**打分步是 scale-proof 的**——工作量取决于"每次喂 LLM 多少篇"，不取决于库里总篇数。discover 已把候选池**硬截在 ≤500 篇**（`discover.py:81` `pool_size=min(500,max(target*2,60))`），每周增量实际几十篇、被 cap 锁死、与总语料无关。所以**漂移修法（锚点+边界重排+取均值）是打分步的终局方案，打分里永远不需要 reranker。**
  reranker 真要上，落点是另外两个门，都不在打分步：
  - **上游粗筛门**：领域做大后某周 query 可能匹配 >500 篇，谁进 500 靠 `prefilter_rank`（各源名次+多源加成，**无语义**）。若长期顶到 cap，风险是**召回**（相关篇在 LLM 看到前被笨过滤器砍）→ 那时上**便宜的语义粗筛**挑对 500 篇（"挑谁去打分"，非"打分时重排"）。
  - **下游检索层**：自然语言问题查几万篇总结，cross-encoder reranker 的主场，属检索层那条线（出口②）。

## ★ 落码状态（2026-06-17，✅ 已提交落地）
**第一步（核心修法）已实现 + 三层验证通过 + 已提交**，落在 `pipeline/find/score_auto.py`（后续 facet 改写又升级为 per-facet，见 `find-facet-rewrite-design.md`）：
- ② `prompt()` 重写：`GENERIC_BANDS`（主题无关骨架，替掉硬编码的 digital-human 例子）+ `anchor_block()`（注入 `topic.json.score_anchors`，空则退回纯骨架=冷启动裸跑）+ 证据接地（reason 必须引原文片段）。
- ① `batch_size` 默认 10→20；`worker()` 批内按 `Random(start)` 洗牌（幂等）对冲位置偏置。
- ④ `boundary_rerank()`（scope a）：截断线 ±8 分窄带 → 同一次调用 ×5 次采样取均值 → 写 `scores/zz_boundary.json`（文件名排 batch_* 之后，commit 的 sorted-glob 合并按 id 覆盖，**commit.py 没动**）；scored<target 自动 SKIP（增量跑无明确截断线）。
- 验证：编译 OK；隔离逻辑（cutoff=80/band 17篇/5次调用/抖动取均值回归/zz 排最后覆盖）OK；真实 claude -p 3篇烟测——返回合法 JSON、reason 确实引原文、分数合理（15/56/92）OK。

**第二步也已完成（2026-06-17）**：
- **gt/dhi 锚点已填**进各自 `topic.json.score_anchors`（手挑，比启发式更准；已推 Telegram 供审）：gt=SAC95/泛连续控制DRL45/金星探测8；dhi=物理角色场景交互96/行人避障DRL46/量子active-learning10。低分/边界从"打过分但被拒"的候选里挑（入库篇只到 rel64，没有低分样本）。
- **冷启动改为全自动自举（2026-06-17，用户拍板"没必要我介入"）**：`score_auto.main()` 发现 topic.json 无 `score_anchors` 时，自动**裸跑整遍 → 从整遍分布挑高/边界/低 3 张样卷(`autopick_anchors`)写回 topic.json → 带锚点重打整遍**。标尺取自"整遍"而非第一批（候选池预排序、第一批全高相关给不出低/边界样本）。挑完非阻塞推 Telegram 告知（可事后改），不挡流程。冻好后增量复用、不再自举。`run auto` 一条龙全自动。
  - **为什么全自动安全**：从不需要绝对分"客观正确"，只需各批一致 + 截断线去留对；第一遍尺子整体偏一点没关系（一致地偏 >> 各批乱飘），且 ④ 边界复称独立兜底去留决策。
  - **人工干预**：想改自举挑的锚点，直接编辑 `topic.json` 的 `score_anchors` 后重跑 score 即可（无需专门工具；原 `pick_anchors.py` 已按用户要求删除）。
- **增量跑 ④ 边界定义**：`boundary_rerank` 开 DB 认首跑/增量——首跑去留线=第 target 名截断线；增量=资格闸 rel≥30 / flag_min(已入库篇跳过)。两路均测过。

## 三、修订后的落码方案（按性价比）

| 步 | 原方案 | 调研后修订 | 优先级 |
|---|---|---|---|
| ② **锚点 + 锁 rubric** | 共享锚点（便宜预防） | **头号主力**。(1) 先修 bug：rubric 档位例子硬编码在 digital-human 主题，改成**按主题注入/主题无关**；(2) 每批 prompt 固定头部塞 3 个固定锚点（明显相关/边界/明显不相关 + 应得分 + 理由），批间一字不改；(3) 保留 0-100 细粒度刻度 | ★ 先做 |
| ＋ **证据接地**（新） | — | reason 字段从"一句话理由"强化为**必须引用 title/abstract 里的具体依据**（RULERS 第 2 腿，几乎免费） | ★ 顺手 |
| ① **加大批量** | 10→25~30，批内自归一化 | 保留但**别当主力**：好处是"接缝变少"非提质；且会**增大位置偏置** → 配合批内**洗牌顺序**。建议 batch 20~25（不必到 30） | ◐ 次要 |
| ③ **边界重排** | 边界带一次重打 | **升级**：截断线 ±N 带 → 同一次调用 + **多次自一致采样 + 取分数均值**，单一参照系下定去留 | ★ 真正校正层 |
| ✘ z-score 归一化 | 已标禁 | **确认禁**，文献佐证 | — |
| ✘ 换 pairwise/检索式 reranker | 未提 | **打分里永不做**：pairwise 在边界放大 style 噪声；打分步被 ≤500 cap 锁死、scale-proof。reranker 属粗筛门/检索层，非打分步 | — |
