# Automatic Intrinsic Reward Shaping for Exploration in Deep Reinforcement Learning

## 一句话
AIRS 把"该用哪种内在奖励来鼓励探索"这件事建成一个多臂赌博机问题，用 UCB 在训练中**实时、自动地从一个预定义内在奖励函数池里挑出当前最划算的那个**（可包含"不加内在奖励"这一选项），并配一个解耦的双分支价值网络让选择只依据真实的外在任务回报，从而在缓解"探索过头反而带偏目标"的同时提升样本效率。

## 解决了什么问题
- 不同内在奖励（好奇心、状态熵、状态变化幅度等）在不同任务、不同学习阶段表现差异很大，"为某个任务挑出最好的内在奖励一直很有挑战性"（原文 §1）。
- 外在+内在的联合目标是**有偏的**：原文称"最大化它只是有时才能得到外在奖励单独定义的最优策略"，过度探索会导致"学习崩溃（learning collapse）"。
- 已有的 EIPO（Chen et al. 2022）通过受约束的策略优化自动调内在奖励重要性，但原文批评其"太复杂、且无法为任意 RL 算法提供增量"。AIRS 想要一个更通用、即插即用的解法。

## 用什么方法解决的（含直觉：为什么 work）
**总体框架（图1、图2、Algorithm 1）**：把内在奖励选择形式化为多臂赌博机——内在奖励函数集 I={I¹,…,Iⁿ}，每个函数是一个"臂"，目标是"最大化由外在奖励评估的长期回报"（§4.1）。每一轮策略更新前，用 UCB 选一个臂作为本轮的内在奖励。

**关键公式：**
- 带内在奖励的 RL 目标（式1）：`J_{E+I}(θ) = E_{π_θ}[ Σ_t γ^t (E_t + β_t·I_t) ]`，其中权重 `β_t = β_0(1−κ)^t` 随时间衰减（κ 为衰减率），用来"控制探索程度"——即探索强度随训练逐渐降下来。
- UCB 选臂（式4）：`I_t = argmax_{I∈𝓘} [ Q_t(I) + c·√(log t / N_t(I)) ]`，c 控制探索程度，N_t(I) 是该臂被选次数。
- 臂的价值估计（式5）：`Q_t(I) = (1/W)·Σ_{i=1}^W V̄^E[i]`，即用一个**长度为 W 的 FIFO 队列**存该臂最近若干次 rollout 的平均"外在任务回报"，取均值作为臂价值。
- 双分支价值网络损失（式6）：`L_V(φ) = [V^{E+I}(s_t) − V̂^{E+I}]² + [V^E(s_t) − V̂^E]²`，**一支估计混合回报 E+I、另一支只估计外在任务回报 E**。

**直觉——为什么 work：**
1. **不同阶段要不同的探索**：原文核心洞见是"不同任务和学习阶段可能受益于不同的内在奖励函数"（§4）。早期需要激进探索以快速积累有判别力的经验；后期"过度探索没必要、甚至会扰乱已学到的策略，只需保持适度探索"。把"不加 shaping"（ID, I_t=0）也作为一个可选臂，AIRS 就能在不需要探索时**自动关掉内在奖励**，这正是它能缓解"有偏目标/学习崩溃"的机制。
2. **解耦让选择信号纯净**：单独的 V^E 分支只估计外在任务回报，所以赌博机用来评判每个臂好坏的 Q 值是**真实任务回报、不被内在奖励污染**——选择因此朝着真正的外在目标走，而不是朝"内在奖励虚高"走。这是它"alleviate biased objective problem"的关键。
3. **UCB 权衡**：在"哪个内在奖励更好"这件事上做探索/利用权衡，避免过早锁死一个臂。
- 架构开放性：原文强调 AIRS 是"非常开放的架构"——可换任意 RL 算法、UCB 可换成 Thompson sampling（池里只有两个臂时）、双分支可换成把内在奖励直接加进优势估计（MiniGrid 实验就是这么做的）。

## 动机 & 背景
- 内在奖励三大流派在 Related Work 梳理：计数/伪计数（pseudo-count、RND）、好奇心驱动（ICM、RIDE）、信息论（RE3 的 Shannon 熵最大化、RISE 的 Rényi 熵最大化）。
- 选作候选池的理由（§5.2.1）：这些内在奖励"(i) 能提供可持续的探索激励（奖励不随访问消失）；(ii) 计算高效易实现；(iii) 能用编码器编码状态空间，给出相对稳定的内在奖励空间、保障算法收敛"。**注意**：Table 1 明确区分——RE3 和 RISE 用的是**固定随机编码器**（g 为 random and fixed encoder），而 **RIDE 用的是学习得到的编码器**（learned encoder，附录 B.2 说它训练了一个前向动力学模型 g 来预测编码后的下一状态）。

## 方法细节
- **骨干 = DAAC（Decoupled Advantage Actor-Critic, Raileanu & Fergus 2021）**，因其泛化能力强被选作 Procgen 基准骨干。DAAC 策略目标（式2）`J_DAAC = J_π + H_π − L_A`（PPO 策略梯度项 + 熵 bonus − 优势损失），价值损失（式3）`L_V = [V_φ(s_t) − V̂_t]²`。原文强调 AIRS 不绑定 DAAC，"可与许多 RL 算法结合，只需在价值网络里用两个分支分别估计任务回报与总回报"。
- **Algorithm 1 流程**：初始化每臂 N(I)=0、Q(I)=0、回报列表 R(I)=FIFO(W)；每轮 k：UCB 选臂 I_k → 用当前策略采样 rollout → 用 I_k 算内在奖励 → 算 V̂^E、V̂^{E+I}、优势 Â → 更新策略 θ、价值 φ → 算新策略平均回报 V̄_φ → FIFO 加入 R(I_k) → 更新 Q(I_k)=R(I_k) 均值、N(I_k)+=1。
- **内在奖励池（Table 1）**：RE3 `I_t=(1/k)Σ log(‖e_t−ẽ_t^i‖₂+1)`（Shannon 熵）、RISE `I_t=(1/k)Σ(‖e_t−ẽ_t^i‖₂)^{1−α}`（Rényi 熵）、RIDE `I_t=‖e_{t+1}−e_t‖₂/√N_ep(s_{t+1})`（奖励显著状态变化）、ID `I_t=0`（不加 shaping）。e=g(s) 是状态表示，ẽ 是编码空间里的 k 近邻，N_ep 是本回合状态访问频率。

## 数据集 & 实验设置
- **三套基准**：MiniGrid（Empty-16x16 / DoorKey-6x6 / DoorKey-8x8，稀疏奖励硬探索；7×7×3 紧凑编码观测；骨干 A2C）；Procgen（16 个程序生成游戏，64×64×3 RGB，15 离散动作，25M 帧，训练 200 关、测试全分布；骨干 DAAC）；DeepMind Control Suite（Cartpole Balance / Cheetah Run / Finger Spin / Walker Walk，背景换成 Kinetics 自然视频做干扰，测泛化；1M 帧）。
- **评测指标**：用 rliable 库报告 Median / IQM / Mean / Optimality Gap（前三越高越好、OG 越低越好），以求可靠（Agarwal et al. 2021）。
- **MiniGrid 的池只有 {ID, RE3} 两个臂**（§5.1.1）；Procgen 的池是 {RE3, RISE, RIDE, ID} 四个臂。
- 基线：MiniGrid 比 A2C、A2C+RE3；Procgen 比 PPO、DrAC、DAAC、IDAAC，以及单一内在奖励的 DAAC+RE3 / +RISE / +RIDE；DMC 比 PPO、IDAAC。超参经网格搜索、报告最好结果（附录 A–C 给了完整超参表）。

## 主要结果 & 结论（写方向，不堆精确数字）
- MiniGrid：A2C+RE3 在三个游戏都超过原始 A2C；**A2C+AIRS 取得三者里最高的性能与收敛速度**（图3），作者据此说 AIRS 缓解了有偏目标问题、智能控制了探索程度。supported（5 个随机种子）。
- Procgen 聚合：**AIRS 在四个指标上都最高，Median 与 IQM 尤其明显，IDAAC 第二**（图5）。supported。逐游戏看，AIRS 在训练关 8/16、测试关 9/16 游戏上最高（Table 5/6，尤其 BigFish、StarPilot）。observed（部分游戏领先，并非全面碾压）。
- 改进概率（图6）：**AIRS 优于 DAAC 的概率 67%、优于 IDAAC 的概率 61%**——对 IDAAC 的优势接近五五开，属边际优势。observed。
- 选择行为（图7/13）随游戏差异极大：BigFish 最常选 RIDE、33.7% 时间选"不 shaping"；Miner 最常选 RISE、59.3% 不 shaping；Ninja 最常选 RISE、66.5% 不 shaping；CoinRun/BossFight 三种函数分摊；Chaser/StarPilot 几乎只选 RE3。这支持"该不该探索、用哪种探索都该随任务/阶段变"的论点。observed。
- 价值估计（图8/14）：双分支损失在约 1M 环境步后趋稳，说明两支能有效追踪各自目标。observed。
- 消融：池只留 {RE3, ID} 时，测试 IQM=1.27、OG=0.015，仍优于 DAAC+RE3——说明"自动决定要不要探索"本身就有增益，并非全靠多臂。supported。
- DMC（图9）：AIRS 在全部四个任务上最高，IDAAC 全面超过 PPO。observed（任务少、仅 4 个）。
- **附带产物**：开源 PyTorch 内在奖励工具箱 rllte（附录 D），即插即用实现 PseudoCounts/ICM/RND/GIRM/NGU/RIDE/RE3/RISE/REVD，统一 `compute_irs(rollouts)` 接口。这是论文一个明确卖点（github.com/RLE-Foundation/rllte）。

## 适用边界（什么时候管用 / 什么时候不管用）
- **管用**：稀疏/硬探索且需要泛化的视觉控制任务（程序生成关卡、带干扰背景），且**手头已有一组各有所长的现成内在奖励**可供挑选；尤其当"不同阶段需要不同探索强度、或某些阶段根本不该探索"时收益最大。
- **依赖强基线对比**：Procgen 上的对手（DrAC/DAAC/IDAAC、以及单一内在奖励变体）都是较强基线，结论不是相对弱基线刷出来的——这点可信度较高。
- **不太管用/收益小**：当池里某个内在奖励本就主导（如 Chaser/StarPilot 几乎只选 RE3），AIRS 相对"直接用那个奖励"几乎无差别（原文：AIRS 与 DAAC+RE3 在这些游戏"final performance almost the same"）；对 IDAAC 的整体优势也只是边际。
- **早期收敛偏慢**：原文承认 AIRS"早期收敛率较低，主要受价值网络估计精度限制"——赌博机要"足够多次尝试才能估好上界"，会带来额外开销、拉低收敛速度。

## 核心贡献
1. 把内在奖励选择形式化为**多臂赌博机 + UCB**，能在不同学习阶段自动选最合适的 shaping 函数（含"不 shaping"），给出可靠探索激励并缓解有偏目标问题。
2. **解耦的双分支价值网络**：分别估计任务回报 V^E 与混合回报 V^{E+I}，让臂选择只依据纯净的外在回报。
3. 开源**内在奖励工具箱 rllte**（PyTorch，即插即用），统一多种内在奖励实现，便于复现与后续研究。
4. 在 MiniGrid / Procgen（16 游戏）/ DMC（带干扰）三套基准上做了系统验证。

## 局限与我的质疑
- **作者自述局限**（§6）：① 依赖预定义奖励池，模块质量直接决定上限，且"如何构建有效奖励集"本身没解决；② 不同内在奖励可能**互相干扰、引发意外的学习崩溃**；③ 决策依赖对任务回报的估计，估计精度决定 AIRS 可靠性，额外模块增加部署复杂度；④ UCB 需足够多次尝试估上界 → 增计算开销、降收敛速度。
- **我的质疑1（非平稳赌博机）**：UCB 的遗憾界建立在臂收益平稳的假设上，但这里每个臂的"价值"随策略一起变化（策略越好，任何 shaping 后回报都更高），是典型的**非平稳赌博机**。论文用长度 W 的 FIFO 窗口做了启发式缓解，但没有任何理论分析说明这套选择在非平稳下仍合理——属工程权宜。
- **我的质疑2（信用分配混淆）**：臂的 Q 值是"选它并更新策略之后"测到的回报，无法干净地把回报提升归因到"这个臂选得好"还是"策略本来就在变好"，选择信号可能被训练本身的进步带偏。
- **我的质疑3（"保证策略不变性"被过度解读）**：摘要/讨论称 AIRS"保证 policy invariance"，但全文没有给出形式化定理，这一性质只是靠"池里有 ID 臂 + 用纯外在回报选择"在直觉上论证，并非证明。读者不应把它当作已证结论。
- **我的质疑4（对 IDAAC 优势边际）**：图6 显示优于 IDAAC 仅 61%、优于 DAAC 67%，逐游戏只在约半数最优；Mean/OG 上的领先也不如 Median/IQM 醒目。"superior performance / outperform"的措辞相对这组数字偏强。
- **我的质疑5（演示规模偏小）**：最能体现"多臂自动选择"的设定其实是 Procgen 的 4 臂；MiniGrid 的池只有 2 个臂、DMC 任务仅 4 个，"从众多内在奖励里自动挑"的能力验证得并不充分。
- **与本研究主题（RL 工具箱/奖励设计）的契合与不足**：方向高度契合——它既给了"自动 reward shaping"的方法，又附了可直接用的内在奖励工具箱，实战可取。但它**只解决"在已有内在奖励里选"，不解决"设计/构造新内在奖励"**；且把选择问题外包给一个需要额外估计模块、收敛偏慢的赌博机层，落地时要额外掂量开销与估计精度。
