# Reproducibility of Benchmarked Deep Reinforcement Learning Tasks for Continuous Control
> Riashat Islam, Peter Henderson, Maziar Gomrokchi, Doina Precup · 2017 · arXiv (Cornell University) · 引用 187 · DOI 10.48550/arxiv.1708.04133

## 一句话
对连续控制中两大策略梯度基线 TRPO(on-policy)与 DDPG(off-policy)做复现性实证研究,系统展示它们对超参数、随机种子、环境随机性高度敏感,并据此给出"如何报告基线对比结果"的一组可操作准则(supported)。

## 解决了什么问题
- 新方法发表时普遍拿 TRPO、DDPG 当基线对比,但各篇用的超参数各不相同、报告口径不一,导致基线复现困难、横向比较不公平(supported)。
- 本文要回答:在连续控制任务上,这两个基线的结果到底有多大程度由超参数 / 随机种子 / 环境随机性决定,而非算法本身——以及该如何报告才让后人能做出可信比较(supported)。

## 用什么方法解决的（含直觉：为什么 work）
- 不是提新算法,而是做**受控对照实验 + 统计检验**:每次只改一个超参数、其余固定在默认值,观察学习曲线差异;对差异做双样本 t 检验给出 t/p 值,从而把"看上去的差异"与"统计显著的差异"区分开(supported)。
- 直觉:复现性问题的根源是"报告里只给一组挑好的数字、不给方差和超参"。要证明这一点,就必须把每个旋钮单独拧一遍、并多次重复跑(改种子)看分布是否重叠——只有量化方差,才能说明"两条曲线不同"可能纯属随机而非方法优劣(supported)。
- 关键设计:用**最稳的指标**(Average Return、Std Return)而非高偏指标(Maximum Return / Maximum Average Return)来比较;并用相同的他人开源实现(TRPO 用 rllab、DDPG 用 Q-Prop 的实现)以贴近真实"被当基线"的场景(supported)。

## 动机 & 背景
- 策略梯度法在连续控制上成为 SOTA,分两类:off-policy 的 DDPG、on-policy 的 TRPO(背景)。
- 作者指出"据我们所知,很少有工作去复现已有策略梯度方法,但很多工作都拿它们当基线来对比自己的新方法"(supported)——这是本文的切入点。
- 作者明确用了他人开源实现:TRPO 来自 Duan 等的 benchmarking 工作(参考文献[9],即 rllab),DDPG 来自 Q-Prop 的实现(参考文献[10]),因为这些实现正是众多论文直接拿来做对比的(supported)。

## 方法细节
- **任务**:OpenAI Gym 的两个 MuJoCo 连续控制环境——Hopper(状态空间 R^20,动作 R^3)和 Half-Cheetah(状态 R^20,动作 R^6)(supported)。
- **算法**:DDPG(off-policy)与 TRPO(on-policy)两个基线(supported)。
- **实验协议**:所有变体跑 5000 次迭代;每个配置的结果对 5 次运行取平均;考察单个超参数时其余全部固定为默认值;最后用"整体最优的超参数组合"额外跑 10 个不同随机种子的试验,专门检验种子带来的方差(supported)。
- **TRPO 默认超参**:网络结构 (100,50,25)、ReLU、高斯 MLP 策略;step size = 0.01;正则系数 = 1e-5;GAE λ = 1.0(见 §2 实验细节)。
- **DDPG 默认超参**:同结构 (100,50,25)、ReLU;actor/critic 学习率分别 1e-4 / 1e-3;batch size = 64;reward scale = 0.1(见 §2 实验细节)。
- **考察的超参数**:两者共有的——策略网络结构、batch size;TRPO 专属——step size、正则系数(共轭梯度阻尼)、GAE λ;DDPG 专属——reward scale、actor-critic 学习率(supported)。
- **正则系数的数学含义**:在共轭梯度步骤里给 Fisher 矩阵(在 rllab 实现里是有限差分 HVP)加上一个单位矩阵的倍数作为正则项,起阻尼作用(原文 §2.2)。
- **step size 的数学含义**:TRPO 的 step size 等价于学习率,但它实际是共轭梯度步骤的 **KL 散度约束上界**——通过约束而非学习率来限制更新幅度,但调起来效果类似(原文 §2.3)。
- **指标选择**:文中明确只用 Average Return 作主比较指标(最终结果表给出全部指标);认为 Maximum Return / Maximum Average Return 是"高偏指标",高方差策略/环境可能在某次离群试验里给出极大的最大回报(supported)。

## 数据集 & 实验设置
- 两个环境:Hopper、Half-Cheetah;物理引擎 MuJoCo,环境来自 OpenAI Gym(supported)。
- 每配置 5 次运行取平均、5000 迭代;最终方差实验用 10 个种子分两组各 5 次平均做对比(supported)。
- 表1(TRPO)、表2(DDPG)汇总了不同迭代点(500/1000/2500/5000 iters,对应约 12.5k/25k/62.5k/125k episodes)下作者复现的 Average / Max Average / Std Return,并与 rllab、Q-Prop、IPG、SDQN 等他人报告值并列对照(精确数值见原文表1、表2)。

## 主要结果 & 结论（写方向，不堆精确数字）
**超参数敏感性(逐项,均为 observed/supported,且强烈环境依赖):**
- 网络结构:在 Half-Cheetah 上 (400,300) 显著优于更小的 (64,64) 和 (100,50,25);TRPO、DDPG 皆如此(Half-Cheetah 上有 t 检验支撑,p 很小)。在 Hopper 上结构影响不显著(observed)。
- 一个尖锐发现:作者找到的最优结构 (400,300) **并不是**被引基线工作(参考文献[10][12])报告基线时所用的结构——暗示他人的基线可能没调到位(observed)。
- batch size(TRPO):更大更好,25000 最佳;小 batch 过早收敛到更低平台(observed)。直觉:TRPO 用带 KL 约束的共轭梯度,小 batch 在高方差环境下相邻步梯度差异大、训练更不稳(作者给出的机制性解释)。
- batch size(DDPG):32 与 64 表现相近,128 能带来明显提升(在 Half-Cheetah);在 Hopper 上不同 batch 结果相近(observed)。
- 正则系数(TRPO):整体看不到显著差异(t 检验 p 均不显著),对 Hopper 影响相对略大些(observed)。
- GAE λ(TRPO):较低的 λ=0.97 在长训练下对 Half-Cheetah 有改善、对 Hopper 改善轻微(observed,且多数 p 值并不显著)。
- step size(TRPO):默认 0.01 对两个环境总体最好(observed)。
- **reward scale(DDPG)——反直觉的关键结果**:虽然 Q-Prop/benchmark 工作[9][10]声称 0.1 是最优、DDPG 对 reward scale 极敏感,但作者发现 DDPG 并不因 rescale 而改善;在 Half-Cheetah 上**不做缩放(RS=1)反而回报高得多**(observed)。这是对既有"调参经验"的直接反例。
- actor-critic 学习率(DDPG):对 Half-Cheetah 影响比对 Hopper 大;说明在固定其他参数下,DDPG 的表现不只受学习率影响,还有其他随机性来源(observed)。

**随机种子 / 方差(本文最重的结论,supported):**
- 用**完全相同的超参数**、只改随机种子,把 10 次试验随机分成两组各 5 次平均,得到的两条学习曲线可以"完全不落在同一分布里"——尤其在 Half-Cheetah 上(Half-Cheetah 整段训练分布的 t≈−9.09,p≈0.0016,显著;Hopper 不显著)(supported)。
- 推论(作者明确点出的"危险操作"):因此**仅靠挑随机种子,就有可能把某个基线报告得显著更差、或把自己的方法报告得显著更好**(observed,作者作为警示提出)。
- DDPG 即便用调好的超参,在两个环境上也得不到稳定结果,提示存在算法/环境之外的随机源(observed)。

**环境间不一致(supported):**
- Half-Cheetah 对超参数调节更敏感,Hopper 则相对不敏感。作者推测因为 Half-Cheetah 动力学更稳定、失败模式少,而 Hopper 易快速进入失败模式、引入更大外部方差使调参困难(作者的 posit/猜测,非证明)。

**给后人的报告准则(本文核心交付物,supported):**
1. 报告所有指标来刻画自己算法与 TRPO/DDPG 的对比(尤其 Average Return 和 Std Return);
2. 报告优化用的全部超参数;
3. 尽量用一组接近最优的超参数(别拿没调好的基线);
4. 对**多于 5 次**试验取平均、且写明平均了多少次、每次用不同随机种子。
- 同时呼吁社区提供"调好且带超参预设、跨多任务有基准结果"的标准实现。

## 适用边界（什么时候管用 / 什么时候不管用）
- 结论的直接适用范围:**MuJoCo / OpenAI Gym 上的连续控制、策略梯度类基线(TRPO、DDPG)**,且基于特定开源实现(rllab、Q-Prop)。超出这两环境、两算法、这些实现的泛化未被证明。
- 强烈的**环境依赖**:几乎所有"敏感/不敏感"结论都随 Hopper vs Half-Cheetah 翻转——不能把单一环境的结论当作普适。
- 与之对比的是**强基线本身**(TRPO、DDPG 当年的 SOTA),不是弱基线;但比较对象是"他人报告的基线数字",本文论点恰是这些数字口径不一。
- 报告准则(报方差、报超参、多种子多试验)具有跨任务的方法论普适性,但"具体哪个超参重要""多大 batch 好"等结论不可外推。

## 核心贡献
- 系统性实证地把连续控制策略梯度的"复现难"归因到三类来源:超参数敏感、随机种子方差、环境随机性(supported)。
- 给出一个有说服力的具体证据:**同超参、仅换种子即可造出统计上不重叠的学习曲线**——直接说明"种子挑选"可被(有意或无意)用来操纵基线对比(supported)。
- 提出一组可操作的报告/实验准则,并提供 Hopper、Half-Cheetah 上多迭代点的参照数值表,供新手判断自己的结果是否在合理范围(supported)。
- 推翻/质疑了既有关于 reward scale 的调参经验(observed)。

## 局限与我的质疑
1. **样本量极小,统计基础脆弱**:多数对照只有 5 次运行,而文章自己的核心论点正是"5 次不够、要多于 5 次"——这使它许多"显著/不显著"的 t 检验结论本身也建立在小样本上,可信度受限。文中相当多 p 值其实不显著(如正则系数、多个 GAE/step size 对比、Hopper 的种子实验 p≈0.18),作者措辞上有时偏向"有差异",需读者自行对照脚注里的 p 值。
2. **覆盖面窄**:只有 2 个环境、2 个算法、各自单一开源实现。把结论当成"DRL 普遍如此"会过度解读;本文证明的是"在这套设定下如此"。(后续 Henderson 等 2018《Deep RL that Matters》才把范围扩大——本文是其前身性质的工作。)
3. **"最优超参组合"的选取不透明**:用于种子实验和汇总表的"best cross-section of hyper-parameters"如何确定、是否本身就有过拟合到这两个环境的风险,文中未充分交代;若挑选过程也受方差影响,则"最优组合"也不稳。
4. **机制解释多为猜测**:如"Hopper 失败模式多→方差大""小 batch 下 KL 约束更不稳"等是作者 posit/intuition,未做针对性实验验证,属于合理推测而非证明。
5. **无 episodes 对齐问题**:不同工作有的按 iters、有的按 steps/episodes 报告,表1/表2 的横向对照本身就受口径差异影响——这既是本文要揭示的病,也在一定程度上削弱了表内"我们 vs 他人"对照的严谨性(作者已注明,但读者易误读为直接可比)。
6. **对本研究主题(RL 实证/复现方法论)而言**:本文偏"现象展示 + 准则建议",没有给出量化的"需要多少次试验 N 才能保证公平比较"的答案(作者自己在脚注里把它列为未来工作);也未提供统计功效分析或更稳健的比较协议(如自助置信区间、配对检验设计),方法论工具相对初级。
