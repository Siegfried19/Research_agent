# Mastering Complex Control in MOBA Games with Deep Reinforcement Learning
> Deheng Ye, Zhao Liu, Mingfei Sun, Bei Shi, Peilin Zhao, Hao Wu, Hongsheng Yu, Shaojie Yang, Xipeng Wu, Qingwei Guo, Qiaobo Chen, Yinyuting Yin, Hao Zhang, Tengfei Shi, Liang Wang, Qiang Fu, Wei Yang, Lanxiao Huang · 2020 · Proceedings of the AAAI Conference on Artificial Intelligence · 引用 271 · DOI 10.1609/aaai.v34i04.6144

## 一句话
腾讯用一套大规模、低耦合、off-policy 的分布式 DRL 系统,配合 actor-critic 网络与四项算法技巧(控制依赖解耦、action mask、target attention、dual-clip PPO),在《王者荣耀》MOBA 1v1 模式上训出能击败顶尖职业选手的 AI。

## 解决了什么问题
- 论文研究的是 MOBA 1v1 游戏中"复杂动作控制(complex action control / 电竞里的 micro-management)"的强化学习问题,而非 5v5 的团队宏观策略。
- 作者主张 MOBA 1v1 的状态/动作空间远大于围棋、Atari:文中给出量级估计——状态约 10^600、动作约 10^18000,而围棋约为 10^170 与 10^360(见 Table 1)。
- MOBA 1v1 的难点在文中被归纳为:部分可观测、需规划/进攻/防守/连招/诱骗、除双方英雄外还有 creeps(小兵)与 turrets(防御塔)等大量单位导致目标选择困难、不同英雄玩法差异极大需统一建模、以及缺乏高质量人类 1v1 数据导致监督学习不可行。

## 用什么方法解决的（含直觉：为什么 work）
- 整体是"系统 + 算法"两条线:系统负责大规模高吞吐采样,算法负责让超大动作空间下的训练能稳定收敛。
- 系统(System Design):四模块解耦——AI Server(自对弈产生 episode)、Dispatch Module(样本收集/压缩/传输)、Memory Pool(循环队列存样本)、RL Learner(分布式训练)。经验生成与参数学习解耦,因此可横向扩展。直觉:复杂控制带来梯度高方差,需要大 batch,而大 batch 需要海量并行采样,所以把"产数据"和"学参数"拆开各自扩容。
- actor-critic 网络对多模态输入分别编码:图像特征用卷积、单位向量特征与游戏状态特征用全连接;同类单位用 max-pooling 压成定长向量以应对单位数目变化;再经 LSTM 得到 h_LSTM 输出动作与 value。
- **Target attention(目标选择)**:把 h_LSTM 的一个 FC 输出当 query、所有单位编码堆叠当 keys,算注意力分布 `p(t|a) = Softmax(FC(h_LSTM) · h_keys^T)`(式1)选择攻击目标。直觉:MOBA 战斗里"打谁"是关键决策,用注意力显式建模单位选择。
- **控制依赖解耦(decoupling of control dependencies)**:一个动作含多个标签(按钮 Button、Move X/Y、Offset X/Y、目标单位),标签间相关(如技能方向与技能类型)很难显式建模。作者把各标签视为独立,把无 clip 的 PPO 目标(式2)改写成各标签求和的多标签目标(式3 `max_θ Σ_{i=0}^{N_a−1} Ê[ (π_θ(a_t^(i)|s_t)/π_θold(a_t^(i)|s_t)) Â_t ]`)。直觉:解耦简化了策略结构(相关性可后处理),且各分量有独立输出通道使动作更多样、探索更充分。
- **Action mask(探索剪枝)**:在策略输出层用人类先验知识屏蔽不合理动作——地图障碍方向、技能在 CD 内/不可用、被敌方控制、英雄/装备特定限制。直觉:超大动作空间里靠规则砍掉明显无效分支,把探索预算花在有意义的动作上,加速训练。
- **Dual-clip PPO(收敛保证)**:标准 PPO clip(式4)在 off-policy、轨迹来自多种旧策略时会失效——当 r_t(θ) 极大且 Â_t<0 时 r_t(θ)Â_t 趋于很大的负值、方差无界。作者对 Â_t<0 的情形再加一个下界 c(c>1):`Ê[ max( min(r_t(θ)Â_t, clip(r_t(θ),1−ε,1+ε)Â_t), c·Â_t ) ]`(式5)。直觉:给"坏动作"的负向更新设地板,防止偏离很远的样本把策略推爆,从而在大规模偏 off-policy 的 batch 上仍能收敛(见 Fig.3 示意)。
- LSTM 还被用于让英雄学会连招(skill combos);训练开始时随机化双方位置以强制探索多样性。

## 动机 & 背景
- 定位为竞争式(competitive)多智能体 RL,延续 AlphaGo/Atari/Chess-Shogi 等 1v1 testbed 路线,但选了复杂度更高的 MOBA 1v1。
- 选 1v1 而非 5v5 的理由:5v5 更强调团队协作策略,1v1 更纯粹地考验单个 agent 的动作控制,更适合研究"复杂控制"问题。
- 相关工作里点名两条 MOBA 对照线:Jiang, Ekwedike, Liu (2018) 的基于 MCTS 的 RL 方法(同样用《王者荣耀》),以及 OpenAI 的 DOTA2 AI(当时技术细节未公开)。作者称本文是"首个系统性聚焦复杂游戏中 agent 动作控制(电竞 micro-management)的研究"。

## 方法细节
- 状态 s=[f_i, f_u, f_g]:局部图像信息(如 2D 障碍)、可观测单位属性(英雄类型、血量等)、可观测游戏状态(游戏时间、已摧毁防御塔等)。
- 动作 a 含两部分:内容(要按的动作按钮、Move X、Move Y、Offset X、Offset Y)与目标游戏单位;按钮含移动、攻击、放技能等(见 Fig.2)。
- 动作采样用 Boltzmann exploration(对 softmax 分布采样);自对弈用 mirrored policies,对手策略采样方式类似 Bansal et al. 2017。
- 推理在 CPU 上做(因游戏逻辑也跑在 CPU,省 IO),并自研 CPU 版快速推理库 FeatherCNN,可转换 TensorFlow/Caffe 模型。
- 梯度用 ring allreduce 平均(Horovod);RL Learner 与 Memory Pool 用共享内存而非 socket 通信,作者称提速 2–3 倍;模型以 P2P 方式从 master learner 同步到 AI Server。与 IMPALA 的区别:IMPALA 把参数分布在多 learner 上、actor 并行向各 learner 取参。
- 奖励设计(Appendix Table 6):受 OpenAI Five 启发,zero-sum(自身均值减去对手均值);含 dense 项(英雄血量、金钱、蓝量 ep_rate、经验)与 sparse 项(防御塔/基地血量、death、kill、last hit),各带权重(如 tower hp point 权重 10.0、hp point 2.0,具体见 Table 6)。

## 数据集 & 实验设置
- testbed:《王者荣耀》1v1 模式;1v1 正式赛为镜像对局(双方同英雄),目标是摧毁对方防御塔与基地、玩到基地被毁(full game)。
- 规模:约 600,000 CPU 核(Docker 封装)+ 1,064 块 Nvidia GPU(P40/V100 混合);训练单个英雄用 48 块 P40 + 18,000 CPU 核,每 GPU mini-batch 4096,每 GPU 约 80,000 samples/秒;数据传输用 FP16、训练用 FP32;LSTM time step=16、unit size=1024;全 rollout、zero-start(从第 0 帧开始)。作者称每英雄每天采集的经验约相当于 500 年人类 1v1 数据。
- 超参:Adam,初始学习率 0.0001;dual-clip PPO 的 ε=0.2、c=3;折扣 γ=0.997(文中说对《王者荣耀》约相当于 46 秒半衰期);GAE λ=0.95。
- 评测:部署进游戏与职业/顶尖业余选手对战,AI 每 133 ms 预测一次动作(约顶尖业余选手反应时间);用 Elo 比较不同模型版本;与已有方法对比含 behavior-tree(游戏内置 AI)、MCTS 及其变体。

## 主要结果 & 结论（写方向，不堆精确数字）
- AI 在多种英雄类型上击败对应领域的顶尖职业选手(5 名职业选手 BO5),覆盖 Mage/Marksman/Warrior/Assassin/Warrior+Mage 等(见 Table 3);如法师 DiaoChan 对当时职业联赛最佳法师选手 3:0。supported(系统对战 + 多英雄,但样本为 BO5、对手各人主玩一种英雄)。
- 大型公开赛(ChinaJoy 2019,参赛者门槛为《王者荣耀》排名 top 1% 起)中,AI 在 2100 场对各路顶尖人类玩家里取得约 99.81% 胜率、仅负 4 场,8 个英雄中 5 个 100% 胜率(Table 4)。supported(样本量大,但对手并非全是职业选手)。
- 与基线对比:对照 Jiang et al. (2018) 的四个 MCTS 系 AI(FBTS、NR、DPI、AVI)及内置 AI。由于原对照工作只报"哪个 agent 更快击败同一基线对手"、未公布详细对战统计,本文沿用同一设置,比较"我方 AI 击败同一基线对手所需的平均时长"。该**基线对手由六个可被内置「DiRenJie」AI(行为树实现)击败的 Marksman 英雄组成**;结果(Fig.4)显示本文 AI 用时显著优于 FBTS/NR/DPI/AVI 与内置 AI。observed(间接指标"击败固定基线的耗时",非与这些基线直接对打)。
- 训练进程(Fig.5,以 Marksman 英雄 DiRenJie 为例):Elo 随训练上升、约 80 小时后趋稳;约 6 小时即 100% 胜内置行为树 AI;约 30 小时达"王者(top 1%)"水平;约 70 小时与职业选手可比。observed(单英雄个案)。
- 消融(Table 5,DiRenJie AI 版本间锦标赛,同等训练资源):action mask 能大幅缩短训练时间且与 Base 同等强度(对 Base 胜率约 50.5%);target attention 与 LSTM 都提升能力(对 Base 胜率分别约 75%、73%);Full version 对 Base 约 90%。supported(有受控消融)。
- 超参消融:full rollout(FR)相比 partial rollout(1000/2000/3000 帧)大幅提升能力(胜率升到约 70%~80%);random initial frame(RIF)相比 zero-start 可加速收敛约 15% 但略损能力(对 ZS 胜率约 40%)。observed。

## 适用边界（什么时候管用 / 什么时候不管用）
- 适用:MOBA **1v1**(单英雄微操控制)且能拿到游戏核心做超大规模自对弈采样的工业级算力场景;作者明确说本文不针对 5v5 团队宏观策略。
- 方法的几项技巧有更一般的迁移价值:dual-clip PPO 针对"大规模偏 off-policy、batch 偏离当前策略"的训练稳定性问题;action mask 针对"动作空间巨大且有强先验可剪枝";控制依赖解耦针对"一个动作含多个相关标签"的多标签策略。这些是本文对 RL 工具箱最可复用的部分。
- 不适用/未验证:无大规模算力时方法的可行性未讨论;5v5、跨游戏泛化、与同期更强系统(如 OpenAI Five、AlphaStar)的直接对比均未做。
- 比较强度:对人类是与**职业/顶尖业余选手**实打实对战(强对手);对算法基线(MCTS 系)则是**间接指标**(击败同一固定基线的耗时)而非直接对战,基线本身(可被内置行为树 AI 击败的六个 Marksman 英雄)偏弱。

## 核心贡献
- 一套低耦合、高可扩展、off-policy 的分布式 DRL 系统,经验生成与参数学习解耦,作者称可扩到百万级 CPU 核与上千 GPU。
- 一个面向 MOBA 动作控制的 actor-critic 多标签网络,集成 target attention、控制依赖解耦、action mask、LSTM 连招建模。
- dual-clip PPO:对负优势样本加下界裁剪,以在大规模偏 off-policy 训练下保证收敛(本文最易迁移的算法点之一)。
- 在《王者荣耀》1v1 上实证能击败顶尖职业选手,并跨多种英雄类型验证鲁棒性。

## 局限与我的质疑
1. 算法新点的"隔离贡献"不够干净:dual-clip PPO 是文中卖点之一,但消融表(Table 5)只拆了 action mask / target attention / LSTM 三项,**没有单独消融 dual-clip PPO**——它对最终性能/收敛到底贡献多少,论文用直觉论证而非对照实验证明。
2. 算法基线对比是间接的:与 MCTS 系(FBTS/NR/DPI/AVI)不是直接对打,而是比"击败同一固定基线对手的耗时",且该基线(可被内置行为树 AI 击败的六个 Marksman 英雄)较弱;Fig.4 缺误差棒/方差,难判显著性。这类间接指标容易被读者过度解读成"算法全面碾压基线"。
3. 对人类的强结论建立在小样本上:对职业选手是 BO5(每英雄几局),且每位选手只玩自己最擅长的一个英雄,镜像 1v1 又把局面限定得很窄;99.81% 的大样本胜率来自公开赛而非职业选手,两者强度不同,不应混为"全面超越人类"。
4. 资源不可复现:600k CPU 核 / 千级 GPU、单英雄 48 P40+18k 核的体量使学术界几乎无法复现,论文承诺开源框架与游戏核心(Appendix 注脚提到 Beta 已向 4 所高校开放),但本文本身不含可复现细节(网络层数、完整超参表等多数未在正文给出,需依赖后续开源)。
5. 泛化未被证明:状态/动作空间 10^600、10^18000 的量级是作者的估算口径,且"打不同英雄像打不同游戏"的统一建模主张,只在有限几个英雄上展示;跨英雄/跨游戏/对更强 AI 的泛化均属未验证。
6. 与本研究主题(RL 工具箱)的契合度:真正可直接拿走复用的是 dual-clip PPO 与 action mask 的工程化做法,但论文对这些技巧的超参敏感性、在非 MOBA 任务上的有效性都未涉及,迁移时需自行验证。
