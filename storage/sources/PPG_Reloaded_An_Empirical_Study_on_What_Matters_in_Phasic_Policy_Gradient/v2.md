# PPG Reloaded: An Empirical Study on What Matters in Phasic Policy Gradient
> [, ", K, a, i, x, i, n,  , W, a, n, g, ", ,,  , ", D, a, q, u, a, n,  , Z, h, o, u, ", ,,  , ", J, i, a, s, h, i,  , F, e, n, g, ", ,,  , ", S, h, i, e,  , M, a, n, n, o, r, ", ] · 2023 · International Conference on Machine Learning · 引用 1 · DOI title:9cc1357c09c7e8e7

## 一句话
一篇在 Procgen 全 16 游戏上做的大规模消融实证研究：作者把过去被认为是 PPG（Phasic Policy Gradient）成功关键的两个因素（"高 value 样本复用"和"低频率特征蒸馏"）逐一拆开、控制混淆变量重测，结论是**这两个其实都不是关键，真正起决定作用的是策略正则化（policy regularization）和数据多样性（data diversity）**。

## 解决了什么问题
- PPG 相比 PPO 在 Procgen 上样本效率和零样本泛化更好，社区普遍把功劳归给"蒸馏阶段的高样本复用 + 低蒸馏频率"两个设计；本文质疑这个归因。(supported)
- 作者指出过去得出这个结论的消融实验**没有解耦混淆变量**：例如在原 PPG 论文里，提高蒸馏频率的同时也缩小了 off-policy buffer、从而降低了数据多样性，分不清到底是哪个因素在起作用（"increasing the distillation frequency also shrinks the size of the off-policy buffer"，§1）。(supported)
- 本文的目标是**在严格控制其它超参的前提下**，逐一隔离三个被怀疑的因素（蒸馏频率、数据多样性、样本复用），弄清"PPG 里到底什么最重要"。(supported)

## 用什么方法解决的（含直觉：为什么 work）
- 方法不是提出新算法，而是**受控的大规模消融实验**：固定其它变量，单独变动一个因素，观察 Procgen 全 16 游戏归一化平均得分的变化方向。
- 核心直觉链条（也是全文最重要的发现）：**频繁蒸馏之所以掉点，根因是蒸馏把 value 学到的特征灌回 policy 时对策略造成"扰动"（policy distortion）；蒸馏越频繁，扰动累积越多。而扰动可以用更强的策略正则化 β_π 直接压住** —— 所以"低蒸馏频率"只是治标，"足够强的策略正则化"才是治本。(supported)
- 对数据多样性的直觉：buffer 越大（T_off 越大）/ 并行环境越多（N_env 越大），训练数据越多样，越有利；反之只用 on-policy 数据会显著掉点。多样性可以来自 off-policy buffer，**也可以等价地来自更多并行环境**。(supported)
- 对样本复用的直觉：过去通过"固定 minibatch、增加更新次数 K_V"来提样本复用，性能提升可能是"更多梯度步"带来的，而非"复用本身"。作者改为**固定 K_V、只缩小 minibatch（M_V）来降低样本复用**，发现性能不掉甚至更好，从而把"复用"和"更新次数"解耦。(supported)

## 动机 & 背景
- Actor-critic（PPO/A3C/IMPALA 等）在图像观测下，policy 和 value 常共享一个 torso 编码器以共享特征；但**联合训练可能带来 policy 与 value 的优化干扰，并人为限制了样本复用**（PPO 要求二者用同一批 on-policy 数据、同样的复用水平、同样的更新频率）。(supported)
- PPG（Cobbe et al. 2021）通过**把训练拆成两个交替阶段**来缓解：policy phase 和 distillation phase，使共享编码器在每个阶段只被一种目标更新，减少干扰。(supported)
- 本文聚焦 **single-network PPG**（单网络版，图 1：共享编码器 θ_φ + 策略头 θ_π + value 头 θ_V），并明确说明原 PPG 论文中单网络版与双网络（disjoint）版性能相当，所以单网络版不是性能瓶颈（"using the single-network version can achieve comparable performance"，§2.2）。(supported)
- value 训练（蒸馏阶段）相对 policy 训练在三方面不同：**频率更低、用额外 off-policy 数据、样本复用更高**（§3 开头）。本文就是逐一检验这三点。(supported)

## 方法细节
- **PPO 基础**：clip 目标 L^clip = Ê[min(r_t Â_t, clip(r_t,1−ε,1+ε)Â_t)]，r_t=π_θ(a|s)/π_θold(a|s)；策略总损失 L_π = L^clip + β_H·Ê[H[π_θ]]；value 损失 L_V = Ê[½(V_θ − V̂_t^targ)²]，Â 和 V̂^targ 用 GAE 估计。(supported)
- **PPG 两阶段损失**（§2.2）：
  - policy phase 优化 **L_π + β_V·R_V**：训 policy 的同时用 R_V 正则化 value 头，避免破坏共享编码器。
  - distillation phase 优化 **L_V + β_π·R_π**：训 value 的同时用 R_π 约束 policy 别偏离太多，其中 **R_π = Ê[D_KL[π_θold(·|s) ‖ π_θ(·|s)]]**（蒸馏前后策略的 KL 散度）。(supported)
- **R_V 的两种实现**：原 PPG 用"L_V 但在共享编码器最后一层 detach 梯度，只更新 θ_V"；Moon et al. 2022 改为 **R_V = Ê[½(V_θ(s) − V_θold(s))²]**（约束 value 相对蒸馏前的偏移）。本文采用后者（Moon 版），因实测更好（§3.1.1）。β_V、β_π 是平衡系数。(supported)
- **Algorithm 1（单网络 PPG）**：维护大小 T_off×N_env×M 的 FIFO off-policy buffer B；每次迭代先收 on-policy 数据 D 入 B，做 K_π 次 policy 更新（用 L_π+β_V R_V）；**每隔 T_freq 次迭代**做一次蒸馏，K_V 次 value 更新（用 L_V+β_π R_π，数据从 B 采）。关键超参：T_off（buffer 容量=保留多少近期迭代）、T_freq（蒸馏间隔）、N_env（并行环境数）、M（rollout 步数）、K_π/K_V（更新次数）、M_π/M_V（minibatch 大小）、β_V/β_π（两个正则强度）。(supported)
- 一个表述上的小改动：作者把"epoch 数"改成用"梯度更新次数"来描述算法，便于后续讨论（§3.1.1）。**当 T_freq 减小时，K_V 同比减小以保持总梯度更新次数不变**（例如 T_freq=1 时 K_V=3072/32=96，见附录 A）。(supported)

## 数据集 & 实验设置
- 测试床：**Procgen 全 16 个程序化生成游戏**，关卡随机生成、难度分 easy/hard。(supported)
- 两种标准设定：
  - **sample efficiency**：在完整关卡分布上训练并测试（用 hard 难度，训 100M 步，all levels）。
  - **generalization**：在有限关卡上训、在完整分布上测；easy（25M 步 / 200 训练关卡）与 hard（200M 步 / 500 训练关卡）都做。(supported)
  - 作者强调以往工作（Cobbe 2021、Moon 2022）只看其中一种设定，本文两种都覆盖。(supported)
- 默认值：T_off=32、T_freq=32、β_π=1；其它（附录 A）：IMPALA 残差卷积网、Adam、γ=0.999、λ=0.95、ε=0.2、entropy 系数 0.01、lr 5e-4、max grad norm 0.5、N_env=256（easy 为 64）、M=256、K_π=8、K_V=3072。每个实验 3 个随机种子，画标准差阴影；附录 B.4 另用 rliable 库（Median/IQM/Mean/Optimality Gap）复核。(supported)
- 主指标：**全 16 游戏的归一化平均回报**。(supported)

## 主要结果 & 结论（写方向，不堆精确数字）
- **蒸馏频率本身不是关键，策略正则化才是。**
  - 在固定 buffer、默认 β_π=1 时，蒸馏越频繁确实越掉点（图 2），看起来支持旧观点。(supported)
  - 但**当蒸馏变频繁时同步调高 β_π，就能恢复到接近的性能**（图 3）；甚至可以做到 T_freq=1（每次迭代都蒸馏，等于删掉 Algorithm 1 的第 11 行 → 一个更简化的 PPG），配合高 β_π 仍达到相近水平。(supported)
  - 反证：在**不频繁蒸馏（T_freq=32）下调高 β_π 并不带来提升、甚至更差**（图 4）。说明高 β_π 不是靠"自身"提性能，而是**专门用来抵消频繁蒸馏造成的策略扰动**。(supported)
  - 简化收益：去掉"低频蒸馏"要求后，PPG 更易分析、还少了一个可调超参 T_freq。(supported)
- **数据多样性是真正重要的因素之一。**
  - 减小 T_off（buffer 变小、数据更不多样）会显著掉点，且降幅与 T_off 的减小大致相关；T_off 从 32 降到 1 降幅最大（图 5、图 6）。(supported)
  - 极端情况 T_off=1（只用 on-policy 数据）有相当明显的掉点。(supported)
  - 多样性可来自另一条路：固定 T_off=1、但**增大并行环境数 N_env**（并下采样保持每次样本量不变），也能获得与用 off-policy buffer 相近的提升（图 7）——印证"多样性"本身才是关键，而非"off-policy"这一具体形式。(supported)
  - 数据多样性对**测试**性能的影响比对训练性能小，作者推测因为无论 T_off 高低，buffer 里的数据都来自有限的训练关卡；在 gen(hard) 上测试端提升尤其小，可能是默认 N_env=256 已足够多样。(observed)
- **高样本复用不是关键。**
  - 固定更新次数 K_V、只缩小 minibatch M_V（降低复用），性能不掉，有时（尤其 sample efficiency）甚至更好；只有 minibatch 过小（M_V×1/8=128）时在 gen(easy) 有明显掉点（图 8）。(supported)
  - 实用副产物：**更小的 minibatch → 更短训练时间**。Table 2 显示 M_V×1/8 把每次迭代墙钟时间砍到约一半、接近 PPO 水平；即"可以在不牺牲多少速度的前提下保住 PPG 的高性能"。(supported)
- **value 正则化与 policy 正则化角色不对称（§4 讨论，图 10/11）：**
  - β_V 过大反而压制 policy 学习、整体掉点（图 10）。(supported)
  - **在频繁蒸馏（T_freq=1、β_π=16）下，完全不做 value 正则（β_V=0）只造成很小的掉点**：在 generalization(hard) 设定下影响很小，而在 sample efficiency(hard) 设定下 β_V=0 / β_V=0.3 反而是表现最好的几条曲线（图 10）。(observed)
  - 与之**形成鲜明对比**：在不频繁蒸馏（T_freq=32）下，β_V=0 会大幅掉点（图 11）——即"不频繁蒸馏时反而更需要强 value 正则"，这与 policy 正则化的规律恰好相反。结论：尽管两阶段结构对称，**policy 正则化和 value 正则化在训练中扮演的角色不同**。(supported)
- **总结论**：被认为关键的两点（高样本复用、低蒸馏频率）都不是决定因素；**策略正则化 + 数据多样性才是**；并且能在把计算成本降到 PPO 量级（省一半以上）的同时保住 PPG 的高性能。(strong，作者在 Abstract/Conclusion 明确主张且有系统实验)

## 适用边界（什么时候管用 / 什么时候不管用）
- 所有结论都建立在 **Procgen + 单网络 PPG + IMPALA 卷积网** 这一具体设置上；作者只外推说"由于 Procgen 多样性高、PPG 在 Minecraft 等也成功过，结论可能在别处也有用"，但这只是推测、未在 Procgen 之外验证。(observed)
- "频繁蒸馏靠调高 β_π 救回来"的前提是**频繁蒸馏 + 高 β_π 搭配**；把高 β_π 用在不频繁蒸馏上没用甚至有害（图 4）。两者必须配套。(supported)
- "不做 value 正则也行"只在**频繁蒸馏**下成立；不频繁蒸馏下仍需要较强 β_V（图 11）。(supported)
- 缩小 minibatch 提速有下限：过小（如 M_V×1/8）会在 gen(easy) 掉点（图 8）。(supported)
- 比较对象是**强基线**：PPG（原版）本身已优于 PPO，本文是在"保住 PPG 已有高性能"的意义上做的，不是跟弱基线比。(supported)

## 核心贡献
- 在严格控制混淆变量（尤其把"蒸馏频率"与"buffer 大小/数据多样性"解耦）的前提下，**推翻了 PPG 社区关于"高样本复用 + 低蒸馏频率是关键"的既有归因**。(strong)
- 指出并用实验支撑了**真正起作用的两个因素：策略正则化（治频繁蒸馏的策略扰动）与数据多样性（可由 buffer 或并行环境数提供）**。(supported)
- 给出一个**更简化、计算更省（接近 PPO）的 PPG 变体**（T_freq=1 删第 11 行 + 高 β_π + 小 minibatch），且覆盖 sample efficiency 与 generalization 两套设定、用 rliable 复核。(supported)
- 附带分析了 stiffness（梯度刚度）与蒸馏频率/过拟合的关系（§4、附录 B.3）。(observed)

## 局限与我的质疑
1. **stiffness 的解释链条偏弱、作者自己也承认存疑**：Moon et al. 认为延迟 value 更新→更高 stiffness→缓解过拟合；本文测出"不频繁蒸馏大致对应更高 stiffness"（图 12），但又说 stiffness 与性能**并不紧密相关**（对比图 13），最后只能"需要更多工作"收场。这一节更像旁证而非有力机制解释。(作者自述局限 + 我的质疑)
2. **"为什么 work"的机制大多是合理叙述而非因果证据**：核心因果故事（频繁蒸馏→策略扰动→β_π 压扰动）主要靠"调高 β_π 能恢复性能"这一相关性支撑，论文没有直接测量"策略扰动"这个中介量并证明它就是中介，属于行为级证据而非机制级证据。(我的质疑)
3. **只有 3 个随机种子**：在 Procgen 这种方差大的基准上，3 seeds 偏少；作者补了 rliable 的区间估计（附录 B.4）缓解，但很多结论方向落在"差不多/略好"区间，"low sample reuse 有时更好"这类弱方向结论稳健性存疑，宜按 observed 看待。(我的质疑)
4. **结论的外推未经检验**：全部实验在 Procgen 上，"可能对其它 RL 环境有用"纯属推测；不同观测模态、连续控制、是否共享编码器等都可能改变结论，不应据此当成 PPG 在所有场景的通用定论。(我的质疑)
5. **新算法价值有限**：本文是"实证拆解 + 给个更省的配方"，没有提出方法上的实质创新，工程意义（省一半算力、少一个超参）大于理论意义；对一个想"找新方法"的读者，可提取的是经验法则而非可直接迁移的新机制。(我的质疑)
6. **β_π/β_V 的最优取值如何随 T_freq/任务变化缺少可操作的指引**：实验给的是离散点（β_π∈{1,4,8,12,16}、β_V∈{0,0.3,1,3,6}）和"频繁蒸馏配大 β_π"的定性规律，但换个环境/网络该怎么定，论文没给可迁移的调参法则，落地仍要自己重扫一遍。(我的质疑)
