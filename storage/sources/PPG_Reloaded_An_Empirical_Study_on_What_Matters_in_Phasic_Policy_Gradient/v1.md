# PPG Reloaded: An Empirical Study on What Matters in Phasic Policy Gradient
> Kaixin Wang, Daquan Zhou, Jiashi Feng, Shie Mannor · 2023 · International Conference on Machine Learning · 引用 1 · DOI title:9cc1357c09c7e8e7

## 一句话
这是一篇对 Phasic Policy Gradient（PPG）做控制变量消融的纯实证研究：它在 Procgen 上系统拆解后主张，原 PPG 论文认定的两个关键因素（高 value 样本复用、低频特征蒸馏）其实**不是决定性的**，真正起作用的是**策略正则化强度（β_π）和训练数据多样性**——只要保住这两者，就能用低样本复用、高频蒸馏达到同等性能，并把计算量降到与 PPO 相当。

## 解决了什么问题
原 PPG 论文（Cobbe et al., 2021）把 PPG 相对 PPO 的优势归因于两个设计：①蒸馏阶段对 value 的高样本复用，②低频做特征蒸馏（distillation）。本文指出这些结论来自"没有把混杂因素拆干净"的消融——例如调高蒸馏频率的同时也缩小了 off-policy buffer、连带降低了数据多样性，因此分不清到底是哪个因素在起效（"the conclusion is drawn from ablation experiments that do not carefully disentangle different factors"，§2.2）。本文要在严格控制其它（可能混杂的）超参的前提下，重新查清"PPG 里到底什么最重要"。

## 用什么方法解决的（含直觉：为什么 work）
方法是**大规模控制变量消融实验**（不提新算法），围绕三个轴逐一隔离：蒸馏频率 T_freq、数据多样性（buffer 大小 T_off / 并行环境数 N_env）、样本复用（value 更新数 K_V / minibatch 大小 M_V）。
核心直觉（本文给出的机制解释）：在蒸馏阶段把 value 学到的特征蒸给 policy 时，会**扰动 policy**；蒸馏越频繁、累计扰动越大，这才是性能下降的根因，而不是"频繁蒸馏本身有害"。策略正则化 β_π（蒸馏阶段对 policy 偏离旧 policy 的 KL 约束）正是用来压住这种扰动的——所以把蒸馏频率调高、同时把 β_π 调大，就能抵消扰动、把性能拉回来（§3.2）。同理，"高样本复用"在原文里和"更多梯度更新次数"纠缠在一起，拆开后发现起作用的可能只是更新次数而非复用率本身（§3.4）。

## 动机 & 背景
- PPO（actor-critic）里 policy 和 value 常共享一个 torso 编码器，联合训练会带来两者优化上的相互干扰，并人为限制了样本复用方式（§1、§2.1）。
- PPO 的策略损失为带 clip 的代理目标 L^clip = Ê_t[min(r_t(θ)Â_t, clip(r_t(θ),1−ε,1+ε)Â_t)]，其中 r_t(θ)=π_θ(a_t|s_t)/π_{θ_old}(a_t|s_t)；总策略损失 L_π = L^clip + β_H Ê_t[H[π_θ(·|s_t)]]（带熵奖励）；value 损失 L_V = Ê_t[½(V_θ − V̂_t^targ)²]（§2.1）。
- PPG（Cobbe et al., 2021）把 policy 与 value 的训练**解耦成两个交替的阶段**来缓解干扰（§2.2，Figure 1 为单网络 PPG 架构）。本文专注**单网络版 PPG**（原文 §3.6 已证单网络版可达双网络版可比性能）。
- PPG 与 PPO 的差别集中在 value 训练（蒸馏阶段）上：更新更不频繁、用额外 off-policy 数据、更高样本复用（§3 开头的三点表述，对应 Table 1）。原文与 Moon et al.(2022) 把"低频 + 高复用"当成 PPG 优越的关键。

## 方法细节
- **算法骨架（Algorithm 1，单网络 PPG）**：维护一个 FIFO off-policy buffer B，容量 T_off × N_env × M。每个 iteration：先用当前 policy 收集 on-policy 数据 D（N_env × M），加入 B；**策略阶段**做 K_π 次更新，从 on-policy D 采 minibatch（大小 M_π），用损失 **L_π + β_V R_V** 优化 θ_φ,θ_π,θ_V；每隔 T_freq 个 iteration 触发一次**蒸馏阶段**，做 K_V 次更新，从 off-policy buffer B 采 minibatch（大小 M_V），用损失 **L_V + β_π R_π** 优化。
- **两个正则项**：
  - 蒸馏阶段的策略正则 R_π = Ê_t[D_KL[π_{θ_old}(·|s_t) ‖ π_θ(·|s_t)]]，约束更新后 policy 与蒸馏前旧 policy 的 KL 偏离；β_π 为其强度系数（§2.2）。
  - 策略阶段的 value 正则 R_V：原 PPG 用"梯度在共享编码器最后一层 detach 的 L_V"（只更新 θ_V）；Moon et al.(2022) 改为惩罚更新后 value 与旧 value 的偏离 R_V = Ê_t[½(V_θ(s_t)−V_{θ_old}(s_t))²]；本文采用后者（§3.1.1 称其表现更好）；β_V 为其强度系数。
- **一个表述上的小改动**：本文把"epoch 数"改述为"梯度更新次数"，便于讨论（§3.1.1）。
- **简化版 PPG（本文提出的实践收益）**：因为发现高频蒸馏可被 β_π 救回，可去掉 Algorithm 1 的 Line 11（频率判断），让每个 iteration 都先做策略损失+value 正则、再做 value 损失+策略正则——即 T_freq=1，**少一个可调超参 T_freq**，也更便于分析（§3.2）。

## 数据集 & 实验设置
- **基准**：Procgen 全部 16 个游戏（程序生成关卡，关卡近乎无限，难度有 easy/hard）（§3.1.2，Cobbe et al., 2020）。
- **两种 setup**（本文同时覆盖，原 PPG/ Moon et al. 各只测其一）：①**样本效率**（在全关卡分布上训练+测试，hard 难度，100M 步）；②**泛化**（限定关卡数训练、全分布测试，easy 25M 步 / hard 200M 步）（§3.1.2）。
- **指标**：所有游戏上的 mean normalized return（原文规定的归一化），每个实验 3 个随机种子、画标准差阴影；附录 B.4 另用 rliable 库（Agarwal et al., 2021）报 Median/IQM/Mean/Optimality Gap（Figure 14–38）。
- **默认超参（Appendix A，Table）**：T_off=32, T_freq=32, N_env=256（gen-easy 为 64）, M=256, K_π=8, K_V=3072, M_π=8192（gen-easy 2048）, M_V=4096（gen-easy 1024）, β_V=1, β_π=1；γ=0.999, GAE λ=0.95, PPO clip ε=0.2, 奖励归一化开, 熵系数 0.01, lr 5e-4, 最大梯度范数 0.5；网络用 IMPALA 残差卷积，Adam；无 LSTM、无 frame stack。**关键控制手法**：改 T_freq 时同步改 K_V，使总梯度更新次数不变（如 T_freq=1 时 K_V=3072/32=96）（Appendix A）。

## 主要结果 & 结论（写方向，不堆精确数字）
- **蒸馏频率不是关键，前提是配上更强的策略正则**：固定 buffer、固定 β_π=1 时，蒸馏越频繁性能确实越差（Figure 2，supported）；但随蒸馏变频同步调大 β_π 后，高频蒸馏（含 T_freq=1 每轮都蒸馏）能达到与低频几乎一样、几乎无掉点的性能（Figure 3，supported）。
- **高 β_π 本身不是"性能增强剂"，只是"修复剂"**：在低频蒸馏（T_freq=32）下单纯调大 β_π 反而带来相近或更差的性能（Figure 4，supported）——说明 β_π 的作用是抵消频繁蒸馏造成的策略扰动，而非独立提升性能（§3.2，作者明确主张）。
- **数据多样性确实重要**：固定 β_π=1、减小 buffer T_off 会显著掉点，T_off 从 32 降到 1（只用 on-policy 数据）降幅最大（Figure 5，supported）；在高频蒸馏（T_freq=1,β_π=16）下，T_off 越大一般越好，只用 on-policy（T_off=1）有明显下降（Figure 6，supported）。
- **多样性可由别的途径补回**：固定 T_off=1（仅 on-policy）、改为扩大并行环境数 N_env，能取得与用 off-policy buffer 相近的性能提升（Figure 7，supported）——佐证"起作用的是数据多样性，而非 off-policy 复用本身"。在 generalization(hard) 上多样性带来的提升相对较小，作者推测因默认 N_env=256 已足够多样（§3.3，observed/作者推测）。
- **高样本复用不是关键**：固定 K_V、缩小 value minibatch M_V（即降低样本复用）并不掉点，某些情况下（尤其样本效率 setup）更小的 minibatch 甚至更好；只有 minibatch 过小（M_V×1/8=128）时在 generalization(easy) 有可察觉的下降（Figure 8，supported）。
- **可降算力到 PPO 量级**：用 M_V×1/8 把每 iteration 训练墙钟时间减半，使总训练时间接近 PPO（Table 2，supported；作者称"relative gain in training speed is clear"，对绝对数字持谨慎）。
- **value 正则与策略正则角色相反（讨论区）**：过强 β_V 会妨碍策略学习（Figure 10，supported）；有趣的是高频蒸馏下 β_V=0（不做 value 正则）只在 generalization(hard) 略掉点，但**低频蒸馏下不做 value 正则会大幅掉点**（Figure 11，supported）——即低频蒸馏需要更强 value 正则，与策略正则的规律相反，二者尽管结构对称却扮演不同角色（§4，作者主张）。
- **刚度（stiffness）与性能关联不清**：测得越低频蒸馏一般对应越高的 value 梯度刚度（Figure 12，observed），但对照逐游戏性能（Figure 13）刚度差异与性能并不紧密相关，作者认为需更多研究（§4，观点谨慎，未下定论）。

## 适用边界（什么时候管用 / 什么时候不管用）
- 结论建立在 **Procgen + 单网络 PPG + IMPALA 卷积网络 + 无 LSTM/无 frame stack** 的图像类离散动作任务上；作者只"相信"（believe）结论可能对其它 RL 环境有用（§3.1.2 提到 Procgen 16 游戏多样性高、§6 提到 PPG 也用于 Minecraft，Baker et al., 2022），但**本文未在 Procgen 之外验证**。
- "高频蒸馏不掉点"成立的前提是**同步提高 β_π**；若不调 β_π，高频蒸馏仍然掉点（Figure 2）。
- "降样本复用不掉点"有下限：minibatch 过小（M_V×1/8）在 generalization(easy) 会掉点（Figure 8）。
- 在 generalization setup 下，数据多样性主要影响**训练**性能、对**测试**性能影响较小——作者解释 buffer 数据本就来自有限训练关卡，故多样性变化对测试影响有限（§3.3，observed）。
- 比较基线是**强基线**：对照对象是 PPG 自身的默认配置（来自 Cobbe et al., 2021 / Moon et al., 2022 的高性能设定），并用 rliable 做了统计稳健性报告（附录 B.4），不是弱基线。

## 核心贡献
- **推翻一个流行归因**：系统证据表明 PPG 中"高 value 样本复用"与"低频特征蒸馏"并非决定性因素（supported）。
- **指出真正重要的两个因素**：策略正则化强度 β_π 与训练数据多样性（supported）。
- **给出机制解释**：频繁蒸馏的危害来自对 policy 的累计扰动，β_π 是对症的修复手段（作者主张，配 Figure 3/4 支撑）。
- **一个实用简化**：可去掉 T_freq（用 T_freq=1）少调一个超参，并通过缩小 value minibatch 把算力降到 PPO 量级而基本不掉性能（supported）。
- **覆盖更全**：同时在样本效率与泛化两种 setup、全 16 游戏上做消融（此前工作各只测一种 setup）。

## 局限与我的质疑
1. **纯单一基准、无外部验证**：所有结论仅在 Procgen 上得到，"可能推广到别的环境"是作者的信念而非证据（§6 自述未来工作仍是开放问题）。对连续控制、稀疏奖励、长 horizon、带记忆（LSTM）任务是否成立完全未知——这恰是本研究主题更关心的可交互场景。把这些结论迁移到非 Procgen 任务时应当成假设而非定论。
2. **种子数偏少**：每配置仅 3 个随机种子（§3.1.2）。Procgen 已知方差大，作者虽用 rliable 缓解，但 3 seed 下许多曲线（如 Figure 3 不同 β_π）差距落在阴影带内，"达到相近性能"的判定对种子敏感，结论的统计力度有限。
3. **机制解释多为相关性、未做因果验证**："策略扰动是性能下降根因"这一核心叙事主要靠"调大 β_π 能救回性能"间接支撑，并未直接测量策略扰动量并证明它与掉点呈因果关系；而对 stiffness 这条更可量化的机制线索，作者自己也承认与性能"并不紧密相关、需更多研究"（§4）——即本文给出的机制故事说服力强于其实证强度。
4. **"数据多样性"缺乏直接度量**：全文用 T_off / N_env 作为多样性的代理变量，但从未直接量化"多样性"本身（作者在 §6 把"data diversity can be measured and improved consciously"列为未来工作），因此"多样性才是关键"在严格意义上是"buffer 大小/环境数才是关键"，二者是否等价于多样性未被独立验证。
5. **β_π 与多样性的相互作用未充分展开**：两大关键因素基本是分轴单独研究的；当蒸馏极频繁、buffer 又很小时，β_π 的修复能力是否仍足够、两因素是否会叠加恶化，缺少联合扫描（虽 Figure 6 在 T_freq=1,β_π=16 下扫了 T_off，但 β_π 固定、未与 T_off 交叉）。
6. **"算力降到 PPO 量级"的证据偏软**：Table 2 是特定硬件（Xeon 8260 + V100）的墙钟时间，作者自己也提示"numbers are influenced by various things"，只敢主张相对趋势；其绝对可复现性和在其它硬件/实现上的成立度需谨慎对待，不宜当成强结论卖点。
