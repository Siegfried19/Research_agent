# DreamControl: Human-Inspired Whole-Body Humanoid Control for Scene Interaction via Guided Diffusion
> Dvij Kalaria, Sudarshan S. Harithas, Pushkal Katara, Sangkyung Kwak, Sarthak Bhagat, Shankar Sastry, Srinath Sridhar, Sai Vemprala, Ashish Kapoor, Jonathan Huang · 2025 · arXiv.org · 引用 12 · DOI 10.48550/arxiv.2509.14353

## 一句话
用一个**预训练的人体动作扩散模型**(OmniControl)按文本+时空约束生成参考轨迹、重定向到人形机器人,再让 RL 在仿真里**一边跟踪这条"梦境轨迹"一边完成任务**,从而学到全身、自主的场景交互技能(开抽屉、拾物、按按钮等),并迁移到真实 Unitree G1。

## 解决了什么问题
- 人形机器人要做全身 loco-manipulation(弯腰捡物、下蹲搬箱、开抽屉/门、按按钮),需要上下肢在多时间尺度上协调,既要秒级以下的平衡稳定,又要长时程(数秒到数十秒)的运动规划。
- 直接用 RL + 稀疏任务奖励学这类任务**几乎学不出来**:探索空间太大,容易陷入不自然、难以 sim-to-real 的行为。
- 主流替代是遥操作数据 + 模仿学习,但**遥操作数据稀缺、昂贵、难规模化**(作者引 Goldberg 的"机器人 10 万年数据鸿沟")。
- 任务自主执行(autonomous skills)时**测试阶段没有参考轨迹可跟**,要么靠 RL 硬探索(难),要么得在线生成一个运动规划——本文走后者。

## 用什么方法解决的(含直觉:为什么 work)
两阶段方法(见 Fig.2):
- **Stage 1 — 用人体动作先验生成参考轨迹**:基于 OmniControl(一个能同时被文本和时空约束引导的动作扩散 transformer,在 HumanML3D 上训练)。给定文本(如"a person walks to cup, grabs the cup from side and lifts up")+ 时空引导(强制某个关节在某时刻到达某空间点,类似图像/视频 inpainting),生成一段 SMPL 人体轨迹;再用 IK 优化(PyRoki 库)**重定向**到 27-DoF 的 G1 机器人形态,优化目标包括关键点相对位置、相对角度、连杆长度缩放,外加足部接触、自碰撞、足朝向等残差项以提升物理合理性。
- **Stage 2 — 带参考轨迹的 RL**:把生成轨迹当作 RL 奖励里的稠密跟踪信号(关节角/关键点/根位姿/手状态跟踪 + 平滑项),**再叠加稀疏 + 稠密的任务专属奖励**显式鼓励完成任务。用 PPO 在 IsaacLab 训练。
- **核心直觉(为什么叫"Dream")**:生成的运动规划只**隐式**地通过奖励影响策略,**不作为策略的显式输入**——所以测试时无需参考轨迹即可自主执行。人体动作先验把 RL 的探索从"在巨大空间里盲找"变成"在一条人类示范的合理轨迹附近精修",于是 RL 能发现**直接 RL 够不到的解**(observed:如 Pick from Ground 需协调下蹲、Jump 需先屈膝再蹬地)。
- **第二个直觉(自然性 → sim2real)**:扩散先验天然倾向生成不含极端动作的、像人的运动,平滑、低 jerk,有助于缩小 sim-to-real 差距(supported,见下文 FID/jerk/用户研究)。
- **数据论点**:只依赖**人体动作数据**训练扩散先验(mocap/视频里很多),不依赖机器人遥操作轨迹;且 rollout 时不依赖显式参考,故可全自主执行任务。

## 动机 & 背景
- 现有全身操作方法常**简化问题**:固定下半身、上下身分开训练(下身被动响应上身)、或只做计算机图形里的仿真角色(无 sim2real)。本文要的是上下身**同时**协调的真实部署。
- 与相关工作的定位:HumanPlus[48]、AMO[5] 能做全身自主任务但**需要遥操作轨迹做模仿学习**;R2S2[50] 训练有限的"primitive"技能并用 IL+RL 拼装;BeyondMimic[49] 也结合引导扩散与 RL,但其扩散引导是"粗"的、不处理物体交互或长程规划。作者称本文用更**细粒度**的引导,且去掉了对参考轨迹的显式依赖,能上真机。
- 受 Omnigrasp[8]、CLoSd[7]、TokensHSI[6] 等"动作先验/扩散做交互"工作影响;本文稠密任务奖励借鉴 Omnigrasp[8] 的 pre-grasp/pre-approach 思想。

## 方法细节
- **场景合成(eq.1–2)**:按生成轨迹里关节 k 在时刻 t_g 的位姿,把待操作物体放到对应位置——`t^{o,world} = t^{b,world}_{t_g} + R^{b,world}_{t_g} t^{o,b}`,`R^{o,world}=R^{b,world}_{t_g} R^{o,b}`。即把物体"种"在手要去的地方,**保证 rollout 中轨迹一定会接近物体**,极大缓解 RL 探索难题。随机化物体位置、质量、摩擦(见附录 Table XII)。
- **参考轨迹表示**:序列 α_i=[α_{i,0},...,α_{i,(L-1)Δt}],Δt=0.05s,L=196(约 9.8s);每帧含根位置、四元数朝向、27 维关节角、左右手开/合(0/1)状态。t_g = 任务交互发生时刻(物体被拾起/按钮被按)。
- **动作 & 观测空间**:仿真为 27-DoF G1 + 两只 7-DoF DEX 3-1 手(真机用 Inspire 手),手只允许离散开/合;动作 a_t∈ℝ^29(27 身体目标关节角 + 左右手各 1)。观测含本体感知(关节角/速、根线速/角速、投影重力、上一步动作)、未来若干帧目标轨迹参考 γ_t、以及特权任务观测(物体相对位姿、质量、摩擦)。特别地用**特权全局根位置**而非根速度作观测,以"精确跟踪"轨迹(区别于 GMT[40] 那类只跟速度、会漂移的可部署策略)。
- **奖励(Table I)**:跟踪项=关节角/关键点(世界系 3D 位置)/根位置/根朝向/手状态偏差;平滑项=力矩与加速度、动作变化率、足在触地时的滑动、足-地接触数(抑制"碎步")、双足与地面平行(抑制脚跟滑)。总奖励 `r_t = Σ_{i=1..10} w_{r_i} r_{t,i} + w_{task,sparse} r^{task,sparse}`(权重见附录 Table XIV)。稠密任务奖励 `r^dense_t = ||p^b_{t-Δt} - p^{ref,b}_{t_g}||_2 - ||p^b_t - p^{ref,b}_{t_g}||_2`(鼓励身体部位逐步逼近目标,借鉴[8])。
- **PD 控制**:`τ_t = k_p(q^{commands}_t - q^{robot}_t) - k_d q̇^{robot}_t`(增益见附录 Table VI)。
- **OmniControl 零样本使用**:用原权重/超参,不微调,直接重定向到 G1。对数据集覆盖差的任务(如 Open Drawer,HumanML3D 里仅 18 条含"drawer/open"且质量差)改用**对一条基础轨迹做 IK 优化**生成参考(如让"站立空闲"的人弯腰拉抽屉),并给出闭式目标轨迹 + 梯度下降对齐手腕(见附录 IX,公式较长)。
- **轨迹过滤与精修(附录)**:扩散生成的轨迹有的动力学不可行/会撞场景,用启发式过滤(躯干扭转过大、骨盆过低、与场景碰撞则丢弃;Table XI 给出过滤前后条数)。每条轨迹前置 N_init=20 帧从默认位姿插值到起始位姿(RL 需要固定起点);并把任务无关的手臂关节锁到默认值(如单手 Pick 时左臂)。作者明说:**"基于启发式的过滤之所以需要,是因为扩散生成的轨迹不适合直接跟踪……数据更多时也许可消除"**(诚实自陈)。

## 数据集 & 实验设置
- 扩散先验:OmniControl 在 **HumanML3D**[68] 上训练(本文不重训)。
- 仿真:**IsaacLab**,PPO 训练;每任务 2000 iterations、8192 并行环境,单卡 NVIDIA RTX A6000(48GB)。策略/价值网为 MLP,隐层 (512,256,256),actor-critic 共享观测(非对称)。
- 任务库:11 个——Pick、Bimanual Pick、Pick from Ground(Side/Top Grasp)、Press Button、Open Drawer、Open Door、Precise Punch、Precise Kick、Jump、Sit。
- 评测:每任务在 **1000 个随机环境**上算成功率(Table II);成功判据各任务在附录定义。
- 基线三种:(a) **TaskOnly**(仅稀疏任务奖励)、(b) **TaskOnly+**(稀疏 + 借鉴[8]的工程化稠密项)、(c) **TrackingOnly**(仅跟踪奖励)。本文 = 跟踪 + 任务奖励。
- 真机:Unitree G1(27-DoF,腰锁只留 yaw)+ Inspire 手(二值开合),IMU 给根姿态,RealSense D435i 在脖子上估物体 3D 位置;用开放词表检测器 **OWLv2**[72] 做 2D 定位再用深度抬到 3D。

## 主要结果 & 结论(写方向,不堆精确数字)
- **TaskOnly(仅稀疏奖励)在全部 11 个任务上成功率为 0**(supported,Table II)——印证稀疏奖励无法引导发现有意义动作。
- **TaskOnly+(加工程化稠密项)只在简单任务上成功**(如 Press Button、Precise Punch),在需要全身协调的任务(Pick from Ground、Jump)上失败(observed):例如 Jump 时策略只"将就"地伸膝,学不出真正的起跳(见 Fig.3)。
- **TrackingOnly 整体表现不错,但在精细交互任务(如 Pick)上吃力**(observed);说明只跟踪不足以保证任务完成。
- **DreamControl(跟踪+任务)在 11 个任务中的 9 个上取得最佳成功率**(supported,Table II),作者据此主张"两种信号结合 → 鲁棒控制"。注意:在若干任务上 TrackingOnly 也已达 100%,DreamControl 的优势主要体现在**精细交互类任务**(如 Pick:本文 95.4% vs TrackingOnly 87.5%,见 Table II)。
- **自然性(human-ness)**:在 5 个有非零成功率的任务上,DreamControl 比 TaskOnly+ 的 **FID 更低、jerk(平滑度)更低**(supported,Table III),且 40 人用户研究中参与者**压倒性更偏好** DreamControl 的轨迹(如 Jump 95%、Precise Punch 92.5%)。直觉:扩散先验产出更像人、更平滑的运动。
  - **例外**:Pick 任务 DreamControl 的 FID 反而更高,作者归因于**领域差距**——人类示范多在腰高拾物,而较矮的 G1(1.32m)常在肩高拾物,导致与人类数据可比性差(诚实指出,observed)。
- **Sim2Real**:成功在真机部署 Pick(站立)、Bimanual Pick(不同重量箱子)、Press Button(站立)、Open Drawer、Precise Punch(站立)、Squat(不同深度)(observed,demonstration 级,无真机成功率统计)。部署时去掉参考观测/根线速/场景物理特权信息、加时间编码 (t, sin(2πt/T)),并把根的 (x,y,yaw) 参考做变换以避免特权输入。OWLv2 因推理延迟**只在首帧检测物体并冻结估计**,交互期间冻结下半身、给足部加零速度惩罚以稳住底座——作者强调这是**感知瓶颈所致,非方法本身**,未来可用 vision teacher-student 蒸馏解决。

## 适用边界(什么时候管用 / 什么时候不管用)
- **管用**:需要上下身协调、有明确空间目标(手腕/足/骨盆要到某点)、且该动作在人体动作数据分布内(走近-抓取-抬起、按按钮、踢/打、蹲、跳)的全身交互技能;尤其当**直接 RL 因探索难学不出来**时,人体先验提供了"脚手架"。
- **不太管用 / 需额外工程**:数据集覆盖差的任务(开抽屉/门)需另用 IK 生成参考、不能零样本靠扩散;扩散生成轨迹常**不可直接跟踪**,需启发式过滤 + 精修(人工设阈值)。
- **形态错配**:当机器人体型与人类示范差异大(矮 G1 vs 1.74m SMPL 模型),自然性与任务可比性下降(Pick 即例)。
- **比较的是中等强度基线**:对手是同组设的 TaskOnly/TaskOnly+/TrackingOnly 消融,**未与外部 SOTA 全身操作方法(如 HumanPlus、AMO、BeyondMimic)做直接定量对比**;故"更好"应理解为"相对自身消融",勿外推为"业界最强"。
- **真机为单任务分别部署、单次演示**,非长时程/多技能组合;不支持灵巧操作或复杂物体几何(作者明列为未来工作)。

## 核心贡献
- 提出 DreamControl:**用人体动作扩散先验(隐式入 RL 奖励、不作策略输入)** 来引导全身人形 RL 学自主场景交互技能的两阶段配方。
- 论证该先验(1)让 RL 发现直接 RL 够不到的解,(2)产出更自然/平滑的运动从而利于 sim2real——**且无需遥操作示范数据**(只需人体动作数据)。
- 在 11 个全身交互任务上做系统消融(TaskOnly/TaskOnly+/TrackingOnly),并把 6 个任务部署到真实 Unitree G1。
- 给出可复现的工程细节:奖励项设计、场景合成公式、轨迹过滤/精修启发式、各任务时空引导与超参(附录 Table IV–XIV)。

## 局限与我的质疑
1. **"发现直接 RL 够不到的解"被部分夸大为方法功劳,实则强烈依赖场景合成 trick**:eq.1–2 把物体直接放到生成轨迹手要去的位置,本身就极大降低了探索难度。要分清成功多少来自"扩散先验的自然轨迹",多少来自"把物体喂到手边"这个特权式场景构造——论文未做"随机/启发式参考轨迹 + 同样场景合成"的对照,无法干净归因。
2. **启发式过滤 + IK 改写 + 任务专属精修非常多**(逐任务阈值 β^torso/β^pelvis、锁非功能臂、N_init 前缀帧、Open Drawer 直接放弃扩散改用 IK),作者也自陈扩散轨迹"不适合直接跟踪"。这削弱了"通用、可规模化、少奖励工程"的叙事——本质上仍有大量逐任务手工调校。
3. **基线偏弱、无外部 SOTA 对比**:三个基线都是自家消融,缺与 HumanPlus/AMO/BeyondMimic 等的同条件定量比较;"9/11 最佳"只在自我封闭的比较里成立,泛化强度有限。
4. **真机评测无定量成功率**:sim2real 部分只给"成功部署了哪些任务"的定性演示 + 视频,没有真机成功率/试验次数/失败模式统计;而真机为绕过 OWLv2 延迟**冻结首帧物体估计 + 冻结下半身**,这等于把"全身自主交互"在真机上降级成了"开环近似",与论文主打的"whole-body""autonomous"卖点有落差。
5. **特权信息依赖**:仿真策略用了全局根位置、物体质量/摩擦等特权观测;真机虽做了移除/变换,但视觉策略(teacher-student 蒸馏)只是"留作未来",当前真机闭环感知能力未被证明。
6. **自然性指标的解释力**:FID/jerk/用户研究只在 5 个任务上报告,且 Pick 的 FID 反例显示该指标对体型错配敏感;"更像人"是否真的因果上帮助了 sim2real 成功率,论文未给出消融(没有"同样策略但更不自然 vs 更自然"对部署成功率影响的直接证据),属于合理但**未被证明**的因果主张。
7. **与本研究主题(扩散先验引导 RL 学全身交互)的契合度高,但可复用的"先验→RL"接口偏耦合**:扩散只产参考轨迹再退化为跟踪奖励,先验信息在 RL 中被"压扁"成跟踪误差,未利用扩散的分布/多模态信息(如不确定性加权、多样本引导),这点比 BeyondMimic 等"引导扩散"路线在方法新颖性上更保守。
