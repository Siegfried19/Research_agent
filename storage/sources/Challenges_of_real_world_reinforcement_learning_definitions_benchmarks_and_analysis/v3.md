# Challenges of real-world reinforcement learning: definitions, benchmarks and analysis
> ["Gabriel Dulac-Arnold", "Nir Levine", "Daniel J. Mankowitz", "Jerry Li", "Cosmin Pădu­raru", "Sven Gowal", "Todd Hester"] · 2021 · Machine Learning · 引用 563 · DOI 10.1007/s10994-021-05961-4

## 一句话
这篇 DeepMind/Google 的立场+benchmark 论文把"为什么 RL 在仿真里行、到真实系统就难落地"归纳为**九大挑战**,给其中 8 个挑战逐一下了形式化定义,并在一个开源的可参数化连续控制套件 `realworldrl-suite`(扩展 DeepMind Control Suite)里用两个 SOTA 算法(D4PG、DMPO)把每个挑战**单独打开**做实验,展示这些 SOTA 在每条挑战维度上、尤其在多挑战叠加时会"很快崩"。

## 解决了什么问题
- RL 在仿真环境里很强,但在真实世界落地慢;作者认为根因是"实验设置假设"与"真实系统现实"之间的大鸿沟,而这鸿沟此前缺乏统一、可复现的刻画。
- 论文要解决的是一个**方法学/基础设施问题**:把真实世界 RL 的困难讲清楚、形式化、并做成可复现的 benchmark,而不是提出某个新算法去打榜。

## 用什么方法解决的（含直觉：为什么 work）
- **九大挑战清单**(原文第 1 节列出):①从有限样本在真实系统上在线学习;②系统延迟(执行器/传感器/奖励);③高维连续状态与动作空间;④满足环境约束(安全);⑤部分可观测与非平稳;⑥多目标/欠定奖励;⑦实时推理(低延迟出动作);⑧从外部行为策略的离线日志做离线训练;⑨给系统操作员可解释的策略。
- **方法论直觉**:与其泛泛喊"真实世界很难",不如把每个困难抽成一个**可单独调强弱的旋钮**(delay 步数、噪声标准差、dummy 维数、安全系数等),装进同一套连续控制任务,这样研究者能在隔离条件下精确观察"某个挑战单独对学习算法做了什么",并据此校准难度。这是把"工程经验"变成"可控变量实验"的思路。
- **为什么用两个差异大的 SOTA**:作者特意选了**机制上互补**的两个算法——D4PG(确定性策略梯度、actor-critic、分布式 critic)与 DMPO(EM 式策略迭代、随机策略、分布式值函数)——目的不是分胜负,而是论证"即便是强且实现各异的 SOTA,也会在这些挑战上栽跟头",以此动员社区。(原文 2 节:"to show that SOTA algorithms do suffer from these challenges to encourage more research")

## 动机 & 背景
- 真实系统(无人机→数据中心→自动驾驶;手机调度→十亿用户推荐)普遍有延迟、噪声、非平稳、大状态/动作空间、带严重后果的安全约束、以及试错代价高,这与"零延迟、完美可见、可无限重置"的仿真截然不同。
- 论文用机器人操纵、医疗(EHR 辅助诊断)、推荐系统三个例子,逐条对应说明这九个挑战如何同时出现在一个真实应用里。
- 四项贡献(原文 1.2):(1) 挑战的识别与形式化定义;(2) 为每个挑战设计实验并分析其对 SOTA 的影响;(3) 定义并基线化"RWRL 组合挑战"benchmark;(4) 开源 `realworldrl-suite`(GitHub: google-research/realworld-rl_suite)。

## 方法细节
- **统一记号**:环境为 MDP ⟨S,A,p,r,γ⟩,目标 π* = argmax_π E[Σ_{t=0}^∞ γ^t r(s_t,π(s_t))]。注意多数环境里 agent 看到的是 MuJoCo 仿真器**预处理后的 observation**,不含完整内部状态;作者全文把 state/observation 互换使用。
- **评测算法**:D4PG(Barth-Maron 2018,DDPG 的改进:n-step 回报、分布式 critic、优先回放、分布式)与 DMPO(Abdolmaleki 2018b,MPO 的分布式值函数版)。超参在附录 Table 9/10,均通过在"no challenge"设置下网格搜索得到。每个实验跑 **30K episodes、5 个随机种子**,任务取 `cartpole:swingup / walker:walk / quadruped:walk / humanoid:walk` 四个(观测/动作维数见 Table 1:cartpole 5/1,walker 18/6,humanoid 67/21,quadruped 78/12)。为可复现**没用分布式训练**,且**不设 train/eval 分离**(训练用的策略直接评测)。
- **关键公式(忠实转写)**:
  - 约束 MDP(挑战④,Eq 1):`max_{π∈Π} R(π) s.t. C^k(π) ≤ V_k, k=1..K`。
  - 鲁棒 MDP(挑战⑤,Eq 2):`J(π) = inf_{p∈P} E^p[Σ γ^t r_t | P, π]`——nature 每步挑选使长期价值最小的转移,agent 学最大化该最坏情况价值的策略;作者指出此类解"往往过于保守"。
  - 多目标回报向量(挑战⑥,Eq 3):`J^multi(π) = (Σ_i r_j(s_i,a_i))_{1≤j≤K} ∈ R^K`。
  - 多目标混合奖励(Eq 4):`r_m = (1-α)·r_b + α·r_c`,r_b 为任务原奖励,r_c 为该时刻被满足的约束数,α 即 `multiobj_coeff`。
  - 挑战①的两个采样效率指标:**收敛前归一化遗憾** `L_pre = (1/R*_mean)[K·R*_mean − Σ_{i=0}^K R_i]`(收敛前因表现差而损失的累计回报);**收敛后不稳定性** `L_post`,按原文定义为"收敛后回报低于下置信界 R*_lower 的 episode 百分比"(衡量收敛后策略抖动)。

## 数据集 & 实验设置
- 套件含 7 类挑战 wrapper,覆盖 8 个 DM Control 任务;每个挑战可从"几乎无影响"调到"几乎不可能"。
- 各挑战的难度扫描参数集中在 Table 11(如延迟 0/3/6/9/12/15/18/20 步;奖励延迟到 100 步;Gaussian 噪声 SD 到 2.3;dummy 维数 0/10/20/50/100 等)。
- **组合挑战**(2.10):把多个挑战按 Easy/Medium/Hard 三档一起打开(参数见 Table 6),其中 Easy 档每个单挑战仍接近最优表现。离线 RL 用 Small/Medium/Large 三种数据量(Table 5),离线算法为 CRR 与离线版 D4PG。

## 主要结果 & 结论（写方向，不堆精确数字）
- **挑战①(有限样本)**:在四个任务上,DMPO 的收敛前归一化遗憾都高于 D4PG(即 D4PG 整体更样本高效,差距接近一个量级)〔supported〕。收敛后不稳定性方面,DMPO 也比 D4PG 更不稳定——**除了 `cartpole:swingup` 这一例外**(原文 2.1:"DMPO also has higher instability than D4PG, except for cartpole:swingup")〔observed〕。
- **挑战②(延迟)**:动作/观测/奖励延迟增大都会降性能;但两算法对**奖励延迟更鲁棒**——奖励延迟要加到约 100 步才看到明显下降,而动作/观测延迟在 0–20 步内就显著降〔supported〕。直觉:即便奖励迟到,它最终仍能被归因到当初那个动作;但对 `humanoid:walk` 这种复杂任务,大延迟下信用分配变难,性能快速崩〔observed〕。观测延迟与动作延迟效果相近,差别仅在 agent 当步收到的奖励是 `r(s_t,a_{t−n})`(动作延迟)还是 `r(s_{t−n},a_t)`(观测延迟)。
- **挑战③(高维状态/动作)**:用零均值单位方差的 **dummy 变量**增加观测维度,**不会显著损害** D4PG/DMPO 的收敛(最多略微影响收敛速度,算法能学会"无视噪声维")〔supported〕。作者还指出"动作维更高未必更难学"——决定性因素是**系统本身的稳定性**而非维数:`quadruped`(78 维)比 `walker`(18 维)更高维却收敛更快,因为它本质更稳定;`cartpole` 低维比 `humanoid` 收敛快〔observed〕。
- **挑战④(约束/安全)**:用 CMDP 形式加入一组二值安全约束(如 cartpole 的 `slider_pos / slider_accel / balance_velocity`),用 `safety_coeff∈[0,1]` 调难度(越接近 0 越难)。结果:约束违反在一个 episode 内**分布不均匀**(如 cartpole 在"摆起"与"平衡"两阶段违反频率不同)〔observed〕。作者主张**显式推理约束优于把约束塞进奖励**,且标准 MDP 没有自然方式表达约束。
- **挑战⑤(部分可观测/非平稳)**:这是两处易混点要分清——**给动作/观测加 Gaussian 噪声、传感器卡死(stuck)、传感器掉线(dropped)等"传感器故障"实验都归在本挑战(部分可观测)下讨论**(原文 2.5),而非挑战③。结论:加 Gaussian 噪声明显降性能〔supported〕;**少量条件下 stuck 传感器比 dropped 传感器危害小**,尽管两者底层信息相同(原文:"stuck sensors pose less of a problem than outright dropped signals")〔observed〕。非平稳方面:对一个**已收敛**策略扰动物理参数(Table 3,如摆长/关节阻尼)常导致**彻底失败**;训练期加扰动(uniform/cyclic)会拖慢学习,且效果"很大程度取决于到底是哪个物理量在变"〔observed〕。
- **挑战⑥(多目标)**:用 Eq 4 的朴素混合奖励演示——随 r_c(约束满足)权重上升,约束很快被满足,但**过度强调 r_c 会迅速拖垮基础任务表现 r_b**,体现真实任务里目标常相互矛盾、难同时满足〔observed〕。
- **挑战⑦(实时推理)**:把延迟建模为动作延迟、把吞吐瓶颈建模为**动作重复**(同一动作连发 k 步,Fig 13)。重复步数增多→性能下降;`quadruped`(状态/动作更大)反而比 `cartpole/walker` 更耐动作重复,原因仍是**任务固有稳定性**(humanoid 最不稳、quadruped 最稳)〔observed〕。
- **挑战⑧(离线 RL)**:从次优行为策略日志离线学。**离线版 D4PG 基本学不出可用策略**(结果被略去);**CRR** 在 `walker/quadruped` 上能学到尚可表现,但在 `humanoid/cartpole` 上失败〔observed〕。数据量从小到大对最终表现影响不显著(数据已"大到不构成 handicap、又难到 D4PG 学不动")。核心方向:**朴素把在线算法搬到日志上不够,需要离线专用算法**(原文 2.5 讨论:offline-specific 算法"哪怕很少数据也能处理")〔observed〕。
- **挑战⑨(可解释)**:**只做了文献综述、未做实验**;9 个挑战里这 1 个留作未来工作,作者只勾勒了用 options/分层动作、符号规划等可能方向。
- **组合挑战(关键卖点)**:即便每个单挑战都只取"Easy"档(单独看都接近最优),叠加到一起后两算法性能都**急剧下降**(Table 7=D4PG,Table 8=DMPO;Fig 17)。`humanoid:walk` 崩得最快——以组合挑战为例:DMPO 的 humanoid 在 **Easy 档就已塌到接近 0**(Table 8,约 1.33±1.14,相对其 no-challenge 约 788);而 D4PG 的 humanoid 在 **Easy 档仍保有约 100**(Table 7,约 102.92±22.47,相对其 no-challenge 约 934,已大幅下滑但未到 0),要到 Medium/Hard 才塌到约 1〔supported〕。作者据 Fig 16 雷达图补充:D4PG 在每条挑战维度的 hard 档都吃力,**唯独"增加观测维度"维度例外**,且对奖励延迟、Gaussian 动作噪声相对不敏感(humanoid 除外)〔observed〕。作者总结 D4PG 在 easy 扰动下"略微"比 DMPO 鲁棒,但除 `quadruped:walk` 外整体与 DMPO 一样很快变差〔observed〕。

## 适用边界（什么时候管用 / 什么时候不管用）
- **管用场景**:你想在一个受控、可复现的连续控制设定里,**隔离地**研究某一类真实世界困难对算法的影响(调延迟/噪声/维度/约束/扰动旋钮),或想要一组"故意很难"的组合 benchmark 作为真实世界 RL 算法的对照基线。
- **作为"训练坑清单"**:论文给出的方向性结论(奖励延迟比动作/观测延迟更可容忍;dummy 维度本身不致命、系统稳定性才是;stuck 比 dropped 轻;朴素在线算法不能直接当离线算法用;多挑战叠加远难于单挑战之和)可直接当实战 do/don't 用。
- **不管用/需谨慎**:结论都基于 **MuJoCo 四个连续控制任务 + D4PG/DMPO 两个算法**,任务全是物理仿真、动作连续;推广到大规模离散动作(推荐/语言)、视觉输入、真实硬件时,这些方向性结论**未被本文证明能迁移**。基线学习器是"朴素、并非为解这些挑战而设计"的,因此组合挑战上的低分是"现状下界",不代表该挑战不可解。

## 核心贡献
1. 把真实世界 RL 的困难收敛为**九大挑战**并对其中 8 个给出 MDP 框架下的形式化定义。
2. 为每个挑战设计**隔离实验**,在两个机制互补的 SOTA 上量化其影响,产出一批方向性洞见与可复现实验协议。
3. 定义并基线化 **RWRL 组合挑战**(Easy/Medium/Hard × 4 任务 = 12 个参考任务),作为真实世界 RL 算法的统一对照。
4. 开源可参数化的 **`realworldrl-suite`**(扩展 DM Control Suite),把每个挑战做成可调旋钮 + 代码示例。

## 局限与我的质疑
1. **覆盖面 vs 代表性的张力**:全部实验只在 4 个 MuJoCo 连续控制任务、2 个算法上做。论文标题谈"real-world",但推荐系统/EHR/真实机器人这些真正的真实场景只出现在动机举例里,**没有任何真实系统实验**;所有"真实世界"结论其实是仿真旋钮的代理,外部效度有限。
2. **挑战①的结论内部不自洽**:正文(2.1、Fig 1b)说"DMPO 比 D4PG 更不稳定(除 cartpole)",但讨论节(第 5 节)却写"DMPO ... significantly more stable once converged"。两处对 DMPO 稳定性的方向**相反**,读者若只读摘要/讨论会被误导;我以正文 Fig 1 描述为准,这点作者自己没对齐。
3. **基线偏弱、结论易被过度解读**:作者明说基线学习器"不是为解决这些挑战而设计的"。因此"SOTA 在组合挑战上崩"很大程度是**没用对症方法**的结果,不能反推这些挑战有多本质地难;把它当"现状下界"读才安全,论文措辞("surprisingly difficult")有点把工具的局限说成问题的难度。
4. **"稳定性决定难度"是观察、非机制**:论文反复用"任务本身稳定性"解释 quadruped 比 walker/humanoid 更耐高维/动作重复,但稳定性只是事后定性归因,没有可量化定义或控制变量去证因果,属于 observed 级直觉而非被证明的结论。
5. **可解释(挑战⑨)只字面占位**:9 个挑战里这条无任何实验,却仍计入"九大挑战"的叙事,使贡献清单看起来比实际实验覆盖更满。
6. **数字解读需回 PDF**:组合挑战表(Table 7/8)里同一档不同算法、不同任务差异很大(如 humanoid 在 Easy 档 D4PG≈103 而 DMPO≈1),用"都接近 0"一句概括会失真;要引用具体下滑幅度必须回 Table 7/8 按任务×算法分别取数,别跨表混用。
7. **对检索这篇的 agent 的提示**:本文是"问题地图 + benchmark",**不提供任何新算法**;若你的目标是"找一个能扛延迟/噪声/离线的具体方法",这篇只给方向和测试床,真正的解法要顺着它引用的工作(如 MPO、CRR、Robust MDP、RUDDER 等)去开 PDF。
