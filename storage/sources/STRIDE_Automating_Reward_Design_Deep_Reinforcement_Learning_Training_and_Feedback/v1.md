# STRIDE: Automating Reward Design, Deep Reinforcement Learning Training and Feedback Optimization in Humanoid Robotics Locomotion
> Zhenwei Wu, Jinxiong Lu, Yuxiao Chen, Yunxin Liu, Yueting Zhuang, Luhui Hu · 2025 · arXiv · 引用 0 · DOI arxiv:2502.04692

## 一句话
STRIDE 是一个用 LLM（GPT-4o mini）自动为人形机器人运动任务"写奖励函数 → 训 DRL → 读训练反馈再改奖励"的闭环框架，在"像博尔特一样冲刺"任务上据称比同类框架 EUREKA 表现更好。

## 解决了什么问题
- 人形机器人运动（行走/奔跑/平衡）是高自由度、动态稳定任务，DRL 的奖励函数设计是关键瓶颈。
- 手工设计奖励"需要大量人力、领域专业知识、反复调参"，且隐含人为偏见、难以跨环境/复杂任务扩展（原文 §1）。
- 已有自动化奖励方法（模仿学习、进化算法）"要么缺乏通用性、要么需要预定义的人类先验知识"（原文 §1 related work）；把 LLM 用于人形机器人这类低层控制、高维系统仍"largely underexplored / largely untapped"（原文 §2）。

## 用什么方法解决的（含直觉：为什么 work）
- 核心是一个 **agentic 闭环**（Figure 1/2）：把"环境代码 + 运动任务描述"喂给 LLM → LLM 生成 Python 奖励函数 → 在 Isaac Gym 里训 DRL 策略 → 用一个预定义 fitness 函数打分 → 把训练反馈（各奖励分量的最大/均值/最小值、成功率、episode 长度等）作为文本反馈回灌给 LLM，让它改写奖励 → 迭代。
- **直觉**：写奖励的人（LLM 一次性零样本生成）往往写不出最优甚至不可执行的奖励；但只要能拿到训练后的客观指标当反馈，LLM 就能像工程师 debug 一样"看哪个分量没梯度、哪个分量太大主导、成功率为何停滞"，据此重写——把"人来迭代调奖励"换成"LLM 读数据自迭代"。
- **为什么用环境代码当上下文**（原文 §4.3）：①LLM 是在代码上预训练的，直接喂原始环境代码能让它"用同样的语法/风格"生成奖励、提高代码可执行率；②环境代码显式定义了可用观测变量（关节速度、躯干姿态、步频等），让奖励"接地"在真实观测空间、不靠硬编码模板，从而能跨机器人形态/任务迁移。
- **梯度无关的人类反馈**（原文摘要 + §6）：允许用户用自然语言描述想要的改进（如"优先稳定性而非速度"），LLM 据此改奖励，**不需要额外重训/梯度优化**——作者称这能产生"更安全、更高质量"的奖励。

### 形式化（Problem Setting，§3）
- 沿用 Singh et al. 2009 的 Reward Design Problem，改写到程序合成场景，称为 **reward generation**。
- RDP 定义为元组 `P = ⟨M, R, π_M, F⟩`：`M=(S,A,T)` 是世界模型（状态/动作/转移），`R` 是奖励函数空间，`A_M(·): R → Π` 是学习算法（输入奖励 R、输出策略 π:S→Δ(A)），`F: Π → ℝ` 是 fitness 函数（只能通过 policy query 访问，即拿策略去评估）。
- 目标：输出 `R ∈ R` 使得策略 `π := A_M(R)` 取得最高 fitness `F(π)`。
- reward generation 版：给定描述任务的字符串 `l`，输出奖励函数代码 `R` 使 `F(A_M(R))` 最大化。

### 算法（Algorithm 1 STRIDE Framework）
> 输入：人形环境代码 M、运动任务描述 l、写代码的 LLM、fitness 函数 F、初始 prompt。
1. 初始化 `R_best`，`s_best = 0`
2. for 迭代 n = 1..N：
3. 用 LLM 采样 K 个奖励函数 `R_1,…,R_K ~ LLM(l, M, prompt)`
4. 评估 `s_1,…,s_K = F(R_1),…,F(R_K)`
5. 更新最优 `(R_best, s_best) = argmax_i(R_i, s_i)`
6. 用反馈精炼 prompt：`prompt ← Reflection(R_best, s_best)`
7. 返回最优奖励 `R_best`
- 这套"采样 K 个候选 → 训练打分 → 取最优 → 反思改 prompt → 迭代"的结构与 EUREKA 基本同构（本文没有声称算法骨架是全新的，主要贡献在人形机器人落地 + 环境代码上下文 + 梯度无关人类反馈）。

## 动机 & 背景
- 把人形机器人达到"运动员级冲刺（sprinting）"当作机器人控制与协调进步的 benchmark（原文 §1）。
- related work 三条线：①RL 奖励设计（手工 vs 自动，自动化里点名 Sarukkai et al. 的 progress-function 框架、Gen2Sim 等，但称它们"主要针对低维任务、对人形这类高维系统适用性受限"）；②人形机器人 RL（早期倒立摆模型不够，近期 Wasserstein 对抗模仿、DDPG 步态控制、MPC+导纳控制等）；③LLM 用于奖励设计（Auto MC-Reward、ChatPCG 等，但"多聚焦高层规划、低层控制探索有限"）。
- 作者定位：STRIDE 建立在这些工作之上，主打"全自动奖励设计 + 训练 + 反馈优化"，不需任务专用模板或人工干预。

## 方法细节
- **底层 LLM = GPT-4o mini**（Figure 2 标注，§5 正文确认）；EUREKA 基线用 GPT-4。
- **奖励函数形式**：被 `@torch.jit.script` 装饰的 `compute_reward(...) -> Tuple[torch.Tensor, Dict[str, torch.Tensor]]`，返回总奖励标量 + 各分量字典（附录 Prompt 1/2 模板里列了 speed / stability / energy_efficiency / trajectory_alignment / arm_leg_coordination 等分量）。
- **机器人**：在 SolidWorks 自定义、导出为 URDF，共 **16 自由度**——下肢髋 roll/pitch/yaw（每腿 3）、膝 pitch（每腿 1）、踝 pitch/roll（每腿 2）；上肢肩屈伸（每臂 1）、肘屈伸（每臂 1）。STRIDE 解析 URDF 动态抽取关节角、速度、躯干对齐等状态变量用于奖励（§4.3）。
- **任务描述示例**（Figure 2 / 附录）："Let humanoid robots run like Usain Bolt"。附录 Prompt 2 把博尔特跑姿拆成很具体的目标：髋前摆 60–80°、膝摆动期屈 90–120°、踝离地跖屈 10–15°、肩臂摆 45–60°、肘维持 90–120°、躯干前倾 20–25°、步长 2.5–3 米，并要求惩罚"内八（knock knees）"、手脚同向等不自然动作。
- **反馈/反思 prompt**（附录 Prompt 3）：要求 LLM 分析各奖励分量随 epoch 的趋势、找出低方差/近常数（无有用梯度）的分量、找出数值过大主导整体的分量、把成功率与分量趋势做相关、诊断停滞，然后重写奖励。
- 附录给出了完整的 4 段 prompt（系统 prompt / 初始 user prompt / 反思反馈 prompt / 代码格式提示），强调 TorchScript 兼容、向量化、归一化（torch.exp/tanh + 温度参数）、对比式奖励信号、动态权重等"创新策略"。

## 数据集 & 实验设置
- **仿真器**：Isaac Gym（GPU 并行训练）。
- **三种地形**（Figure 3）：Flat（平地，测最大冲刺速度）、Wave（波浪起伏面，测适应性）、Random Uniform（随机高度变化，测鲁棒性）。
- **基线**：EUREKA（用 GPT-4 生成奖励），称为 SOTA 奖励设计框架。
- **评估指标**：Max Success Score（评估最大任务完成率）、生成代码的成功率（success rate of generating code）。`[原文未提]` Max Success Score 的精确定义/量纲。
- **实验规模**：每个环境 10 次独立 run，每个 run 搜索 3 个 iteration，每 iteration 采样 K=10 个奖励。
- **三个对比对象**：EUREKA、STRIDE、STRIDE (Human Init.)（带人类初始化/人类自然语言反馈的版本）。

## 主要结果 & 结论（写方向，不堆精确数字）
- 在该冲刺任务的三种地形上，STRIDE 的 Max Success Score 高于 EUREKA（Figure 5–7 柱状图，方向一致）（observed）。
- 作者称随机均匀地形上 STRIDE 最优表现"超过 EUREKA 最优的约 250%"，平地上接近最优冲刺速度、波浪地形约为 EUREKA Max Success Score 的 3 倍（原文 §5.2）（observed，仅该任务/该自定义机器人）。
- 摘要把上面这个数字泛化为"平均约 250% 的效率与任务表现提升"——但正文 §5.2 的"250%"明确只针对随机均匀地形那一项，存在表述上的放大（见质疑）。
- 成功率（Table 1，按 iteration）：EUREKA 0.1→0.4→0.0；STRIDE 0.2→0.5→0.3；STRIDE (Human Init.) 三个 iteration 都稳定 0.7。作者据此说人类初始化版"成功率高且稳定"（observed）。
- 注意 EUREKA 第 3 iteration 掉到 0.0、STRIDE 第 3 iteration 也从 0.5 回落到 0.3——即迭代并非单调变好，作者称 STRIDE 进步在第 3 轮"停滞（stagnates at 0.3）"（原文 §5.2）（observed）。
- 定性观察（Figure 4 逐帧对比 + 文字）：EUREKA 跑姿"笨拙、低效、平衡协调差"，STRIDE"更自然、流畅、稳定"，关节协调和姿态更好（observed，主观/视觉判断）。
- 相关性分析（Figure 8）：STRIDE (Human Init.) 在"Max Success Score 高"的同时与人类设计奖励的相关性也高（右上角）；作者同时承认 STRIDE 生成的新颖奖励"不一定总与人类预期直接相关，但仍带来更优表现"（原文 §5.3）（observed）。
- 作者结论：STRIDE 在多地形/多形态上能自动生成有效奖励、让仿真人形机器人达到"冲刺级"运动，且能整合人类反馈再优化奖励，无需基于梯度的重训。

## 适用边界（什么时候管用 / 什么时候不管用）
- **管用场景**：有显式环境代码 + 可并行仿真器（Isaac Gym）+ 可定义客观 fitness/成功指标的高维人形运动任务；尤其当任务能用自然语言细致描述目标姿态（如博尔特跑姿那种逐关节角度规格）时。
- **依赖人类初始化才最强**：表现最好的是 STRIDE (Human Init.)，纯自动 STRIDE 的成功率仍偏低（0.2–0.5）且会停滞——说明"全自动"在该任务上还达不到稳定高成功率，人类先验/反馈贡献很大。
- **不管用/未验证**：只在单一任务（冲刺）、单一自定义 16-DoF 机器人、仿真环境里验证；没有真实机器人实验，没有其他运动任务（行走/转向/跳跃等）的横向验证，跨形态"可扩展性"是论点而非已证明的实验结果。
- fitness 函数本身仍需人定义；任务描述里大量博尔特跑姿的精确角度其实也是人工注入的领域知识，并非完全"零先验"。

## 核心贡献
1. 提出 STRIDE：把 agentic engineering + LLM 用于人形机器人运动的奖励设计→DRL 训练→反馈优化全闭环（不需任务专用 prompt/模板）。
2. 用"原始环境代码 + URDF 参数"作为 LLM 上下文，让生成的奖励接地于真实观测空间、可跨形态适配（论点）。
3. 引入梯度无关的人类反馈机制，可在不重训的情况下用自然语言精炼奖励，提升安全性/质量（论点）。
4. 在 Isaac Gym 三种地形上与 EUREKA 对比，报告 STRIDE（尤其带人类初始化）在 Max Success Score / 成功率 / 跑姿自然度上更优。
5. 附录公开了全部 4 段 prompt（系统/初始/反思/格式），具备一定可复现参考价值。

## 局限与我的质疑
1. **预印本、零引用、未经同行评审**：本文是 arXiv 预印本，所有结论（尤其"~250%提升""sprint-level locomotion"）都应保留，未被独立验证。
2. **"250%"被从单项放大为平均**：正文 §5.2 的 250% 明确只对应"随机均匀地形上 STRIDE 最优 vs EUREKA 最优"这一项，而摘要写成"average improvement of round 250% in efficiency and task performance"，这是把单条最好结果泛化成总体平均，属于结论被过度解读。
3. **核心指标定义缺失**：通篇用 "Max Success Score" 但从未给出其精确定义、量纲或成功判据（柱状图 y 轴从 0 到 ~3.5 不像"率"）；"success rate"（Table 1，0–0.7）与之又是两套口径，读者无法判断这些数字的可比性与可靠性。
4. **公平性存疑**：STRIDE 用 GPT-4o mini、EUREKA 用 GPT-4，模型不同；EUREKA 在第 3 iteration 掉到 0.0 这种"基线越迭代越差"的现象很反常，可能暗示基线实现/调参不充分，使对比偏向本文方法。
5. **样本与统计**：每环境仅 10 run、3 iteration、K=10，成功率分辨率粗（0.1 一档，等价 ~10 次试验），图 5–7 的误差条/箱体含义未说明，缺乏方差/显著性检验，难支撑"consistently exceeds / wide margin"这类强措辞。
6. **方法新颖性有限**：算法骨架（采样 K 候选→训练打分→取最优→反思改 prompt→迭代）与 EUREKA 几乎同构，真正增量是人形机器人落地 + 环境代码上下文 + 人类反馈，但这些增量大多以"论点"陈述，缺消融实验（例如没有"去掉环境代码上下文""去掉人类反馈"的对照来量化各组件贡献）。
7. **"全自动/无需人类先验"与事实张力**：表现最好的恰是 Human Init. 版；且任务 prompt 里注入了大量博尔特跑姿的精确关节角度规格——这本身就是密集的人工领域知识，"无需任务专用 prompt"的主张与附录里高度任务定制的 prompt 自相矛盾。
8. **纯仿真、单任务**：无真实机器人、无 sim-to-real、仅冲刺一个任务，"advance humanoid robotics""sets a new standard"等结论相对其证据范围明显偏大。
9. **与本研究主题（RL 训练可交互数字人 / RL 通用工具箱）的契合度**：方法层面（LLM 自动奖励设计闭环）很相关、实战导向，但其证据强度弱，引用时宜把它当作"方法范式参考"，而非"已被验证有效的结果来源"。
