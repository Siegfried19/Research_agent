# Comparing Deep Reinforcement Learning and Evolutionary Methods in Continuous Control
> Shangtong Zhang, Osmar R. Zaiane · 2017 · arXiv · 引用 0 · DOI arxiv:1712.00006

## 一句话
在 4 个低维向量状态的连续控制任务上，用并行实现把深度强化学习（CA3C/P3O/D3PG）与进化方法（CMAES/NEAT/NES）放在同一服务器上横向实测，结论是"没有一致赢家"（no consistent winner），但能总结出各自擅长的场景。

## 解决了什么问题
- RL 与进化策略（ES）两大阵营各自都在连续控制上快速进步，但缺一个把"当下最新技术"放在一起的系统对比，导致面对新任务不知该选哪类方法。
- 作者要补的正是这个空白：在统一设定下对比，给出"什么任务该选哪类方法"的经验直觉，而不是宣称某算法最强。

## 用什么方法解决的（含直觉：为什么 work）
- 选 6 个算法分两阵营对打：进化侧 CMAES、NEAT、NES；深度 RL 侧 CA3C、P3O、D3PG。
- 公平起见全部用神经网络作函数逼近、全部多进程并行实现、同一台服务器上跑、同时用"环境步数"和"墙钟时间"两把尺量（前者看数据效率，后者看实际速度）。
- 直觉层面作者给出的核心机制解释：进化方法靠"群体随机扰动 + 按适应度选择"来搜索，天然带全局探索，因此在"需要小心探索、容易陷局部最优"的任务上更不容易卡死、对随机性/初始化更不敏感（更稳）；而基于梯度的深度 RL 沿策略梯度方向逐步爬升，在"动力学丰富、需要精细连续调整"的任务上更能把信息用起来，也更能吃下大网络的表达能力。

## 动机 & 背景
- 类比自然界：RL 对应个体"试错"学习，ES 对应物种"随机变异 + 适者生存"的进化；两者在自然中是结合的，但工程上"还没有统一框架把 RL 和 ES 结合起来"，所以先得搞清各自优劣。
- 作者强调以往对比都"不够代表当下最强水平"：Taylor et al. 2006 / Whiteson et al. 2010 只比到原始（非深度）RL、且限于 Keepaway 这类简单离散任务；Duan et al. 2016 比了多种深度 RL 与部分进化方法，但"没有包含 NEAT 范式"，且其后 PPO（Schulman 2017）、ES-as-RL-alternative（Salimans 2017）等新进展尚未纳入。本文卖点之一就是把这些较新方法和并行实现一起纳入对比。

## 方法细节
六个被比较算法（公式按原文转写）：

**进化侧**
- CMAES：网络结构固定，θ 只表权重。每代候选 θ_i ∼ μ + σ·N(0,Σ)；用环境评估全部候选，按表现选一部分来更新分布参数 μ、σ、Σ，下一代从更新后的分布采样。
- NEAT：同时进化网络的"结构 + 权重"（θ 表两者）。用 genetic encoding 表示网络、用 historical markings 做合理交叉以避开昂贵的拓扑分析，并用 innovation number 保护新结构，使网络可从最简结构（实验里初始仅 1 个隐藏单元）逐步长大。
- NES：结构给定，θ 只表权重。设群体分布 p_φ(θ) 为均值 φ、固定协方差 σ²I 的高斯，目标 J(θ)=E_{ε∼N(0,I)} F(θ+σε)，梯度 ∇_θ J(θ)=(1/σ)·E_{ε∼N(0,I)} F(θ+σε)ε；更新式 θ ← θ + α·(1/(nσ))·Σ_{i=1}^n F(θ+σε_i)·ε_i（α 步长、n 群体大小、F 适应度函数）。

**深度 RL 侧**
- CA3C（连续版 A3C）：目标 J(θ)=v_π(s0)；按策略梯度定理 ∇_θ J(θ)=E_π[∇_θ logπ(A_t|S_t,θ)·(R_{t+1}+γv_π(S_{t+1})−v_π(S_t))]；价值函数用半梯度 TD 更新。连续动作下策略取多元高斯 π(a|s,θ)=N(μ(s,θ),Σ(s,θ))，并"令协方差 Σ(s,θ)≡I"以增稳、简化参数化。沿用 A3C 的异步多 worker（去相关、提速、降方差）。
- P3O（并行版 PPO）：基于 TRPO 的信赖域目标 maximize L(θ)=E[ (π_θ/π_θold)·A_t ] s.t. E[D_KL]≤δ；实践改罚项形式 L^KL(θ)=L(θ)−β·E[D_KL]。PPO 进一步用裁剪目标：令 r_t(θ)=π_θ(a_t|s_t)/π_θold(a_t|s_t)，L^CLIP(θ)=E[min(r_t(θ)A_t, clip(r_t(θ),1−ε,1+ε)A_t)]（如 ε=0.2）；优势用截断 GAE A_t=δ_t+(γλ)δ_{t+1}+…（δ_t=r_t+v_π(s_{t+1})−v_π(s_t)，如 λ=0.97）。并行参考 A3C + DPPO：每 worker 各有自己的 replay buffer、用 L^CLIP（原文称其被报告优于 L^KL）、用同步梯度更新（原文称同步可优于异步）；与 DPPO 不同处——同步协议更简单（A3C 式更新 + 一把共享锁，梯度永不丢弃），且每 worker 只基于 buffer 内全部 transition 做"一次"批更新（作者发现这样更稳）。
- D3PG（分布式 DDPG）：DDPG 目标 J(θ)=v_μ(s0)，按确定性策略梯度定理 ∇_θ J(θ)=E_{μ'}[∇_a q_μ(s,a)|_{a=μ(s|θ)}·∇_θ μ(s|θ)]；行为策略 μ'(s)=μ(s)+N，噪声用 Ornstein-Uhlenbeck 过程；靠 experience replay + target network 稳定。分布式做法类比 P3O，但 replay buffer 在 worker 间"共享"，更新同步、target network 共享。

## 数据集 & 实验设置
- 4 个任务（均来自 OpenAI Gym，低维向量状态 + 连续动作）：Pendulum（验证实现的玩具任务）；Continuous Lunar Lander（典型"需小心探索"任务，落地中持续给负奖励→易陷"啥也不做混到超时"的局部最优）；Bipedal Walker（动力学丰富）；Bipedal Walker Hardcore（加障碍、更难）。作者称三个 Box2D 任务复杂度与 MuJoCo 相当，且选 Box2D 是因社区已有大量 MuJoCo 结果。
- 评测：进化方法对每代最优个体跑 10 个测试 episode 取平均；CA3C/P3O 另开测试进程持续跑确定性测试 episode。每算法每任务 10 次独立运行、不固定随机种子；因各 run 的步数/墙钟不对齐，用线性插值跨 run 平均。
- 网络：除 NEAT 外都用两个两隐层网络分别参数化策略与价值函数；为看参数规模的可扩展性，测小网络（隐层 16 单元）和大网络（隐层 64 单元）；tanh 激活、两网不共享层、输出线性；P3O/CA3C 用单位协方差（熵罚=0）；NEAT 初始仅 1 个隐藏单元。
- 实现/算力：CMAES、NEAT 基于 Lib CMA / NEAT-Python 做多进程，其余在 PyTorch 从零实现以做对等比较；同一台 Intel Xeon E5-2620 v4 服务器、未用 GPU（多数算法不兼容 GPU）；代码公开。
- 超参：因任务多、超参多，未做全面网格搜索——只在 Pendulum 上对每算法 1–2 个关键超参做网格搜索，其余任务直接沿用 Pendulum 的参数不再调（顺带反映各算法对超参的鲁棒性）。搜得：CA3C/D3PG 学习率 10^-4 最好、P3O 为 10^-3（搜索范围 {10^-4…10^-1}，Adam）；NES 的 σ 与 α 同设 0.1 最好；CMAES 的 σ 取 1 最好。状态用运行均值/方差归一化（跨 worker 共享更新）；CA3C/P3O/D3PG 同样归一化奖励；NES/CMAES 用 Salimans 2017 的 reward shaping。
- 每 run 最大环境步 10^7；深度 RL 曲线方差大，故 CA3C/P3O/D3PG 曲线用窗口 50 滑动平滑。结果见 Figure 2（按环境步）、Figure 3（按墙钟，横轴对数）。

## 主要结果 & 结论（写方向，不堆精确数字）
- 总结论：没有一致赢家——"没有算法能在所有任务、所有度量上一致地胜过其他" `strong`（这是作者反复强调的主张）。
- 最终性能高度依赖任务 `supported`。
- NEAT 在三个 Box2D 任务上达到不错水平，却在最简单的 Pendulum 上失败（observed）。
- 在 Continuous Lunar Lander（需小心探索）上，所有进化方法都解出来了，而多数深度 RL 方法陷入局部最优——说明在需探索的任务上进化方法探索更强 `observed`。
- 在两个 Walker（动力学丰富）任务上反过来：多数深度 RL 更好，许多进化方法陷局部最优——说明深度 RL 更能处理丰富动力学 `observed`。
- 综合推荐：NEAT、D3PG、P3O 是较好的选择 `observed`（作者原话"good choices"，非强主张）。
- 学习速度：在 Pendulum 上深度 RL 在数据效率（环境步）和墙钟两方面都更快；该结论在 Bipedal Walker 上仍成立，但 D3PG 在该任务跑得很慢是例外 `observed`。（Lunar Lander 与 Walker Hardcore 因各有一阵营大面积失败，未纳入速度比较。）
- 稳定性：所有实验里深度 RL 方差都比进化方法大；这与"进化方法在需探索任务上更好"一致——更强探索→对初始化/随机性更不敏感→更稳 `observed`。
- 可扩展性：多数实验中深度 RL 性能随网络增大而提升；进化方法有时小网络反而更好（如 NES 小网在 Walker Hardcore 达到可用水平、大网几乎学不到东西）。总体看深度 RL 更能利用复杂参数化、对大网络扩展更好 `observed`。

## 适用边界（什么时候管用 / 什么时候不管用）
- 仅覆盖"低维向量状态 + 连续动作"的任务（4 个），不涉及图像输入/高维观测（作者把图像输入列为未来工作）。
- 偏好进化方法的场景：需要小心探索、奖励容易诱导局部最优（如 Lunar Lander）、看重稳定性/对超参与随机性鲁棒、算力受限只能用小网络。
- 偏好深度 RL（P3O/D3PG/CA3C）的场景：动力学丰富需精细连续控制（如 Walker 系列）、看重数据效率与墙钟速度、可用较大网络换性能。
- 注意墙钟比较"高度依赖实现"，作者自承只能给"基本直觉"；且全程未用 GPU，对本可 GPU 加速的 P3O/D3PG 不利。

## 核心贡献
- 在统一并行设定、同一服务器、同时用环境步与墙钟两把尺下，对当下两阵营 6 个代表算法做系统横向对比，给出"没有一致赢家 + 各自擅长场景"的经验结论。
- 提出并实现 PPO 的并行版 P3O（A3C 式同步更新 + 共享锁、梯度不丢、每 worker 单次批更新、各自 replay buffer）与 DDPG 的分布式版 D3PG（共享 replay buffer + 共享 target network），并开源全部实现。

## 局限与我的质疑
1. **预印本、未确认同行评审**：这是 arXiv 预印本（v2, 2018-03），抽取信息看不到同行评审确认；下列结论应保留态度。摘要里还有明显笔误（"fro continuous control""Bipedal Waler"），说明文字校对不严，需对细节多一分保留。
2. **超参调优极不充分，足以颠覆结论**：作者自承没钱做全面网格搜索，只在 Pendulum 上调 1–2 个关键超参、其余任务直接套用 Pendulum 参数。连续控制对超参极敏感，这种"跨任务套参"很可能系统性低估了某些算法在特定任务上的真实上限——"X 在任务 Y 上陷局部最优"也许只是没调好，而非方法本质缺陷。所有"谁比谁好"的方向性结论都建立在这个脆弱基础上。
3. **墙钟比较可比性弱**：作者自己承认相对墙钟"高度依赖实现"，且部分算法用第三方库（Lib CMA / NEAT-Python）、部分 PyTorch 从零写，又全程禁用 GPU——这对本可 GPU 加速的深度 RL 不公平。因此"深度 RL 在 Pendulum/Walker 上更快"这类速度结论的外部效度有限。
4. **样本与统计严谨度存疑**：每设置仅 10 个 run、用线性插值跨 run 对齐、曲线还做了窗口 50 平滑（仅对深度 RL 曲线平滑，更显得其方差被"美化"），但全文未见显著性检验或置信区间报告；"方差更大/更小""谁更好"多为读图的定性判断，缺定量支撑。
5. **任务面窄、规模小**：仅 4 个低维任务、网络仅 16/64 两档隐藏单元，刻意避开了社区主流的 MuJoCo（理由是"已有很多结果"，但这也使本文难与主流基准直接对照）。结论难外推到高维、图像输入或更大网络。
6. **机制解释多为事后归因**：如"进化方法更稳是因为探索更强→对初始化不敏感"属合理但未被独立验证的因果叙述，文中没有针对性消融（例如固定探索强度看稳定性是否随之变化）来证因果，更像对现象的自圆其说。
7. **对本研究主题（算法横向比较 / do's & don'ts）的价值与不足**：方向上很契合——"无一致赢家 + 按任务特性选方法"正是有用的实践取向；但因上述调参、统计、任务规模问题，其具体"推荐 NEAT/D3PG/P3O"难当强证据，宜作为"经验直觉/假设来源"而非定论引用，且时效较旧（2017，PPO/DDPG 之后又有大量改进未覆盖）。
