# Safe Reinforcement Learning via Shielding
> Mohammed Alshiekh, Roderick Bloem, Rüdiger Ehlers, Bettina Könighofer, Scott Niekum, Ufuk Topcu · 2018 ·  · 引用 617 · DOI 10.1609/aaai.v32i1.11797

## 一句话
本文提出"shielding"框架：用形式方法从一个时序逻辑安全规约 + 环境的粗粒度抽象自动综合出一个"护盾"（reactive system），在 RL 智能体学习和执行的**全过程**强制安全约束，且只在绝对必要时干预（最小干预），从而把"正确性/安全"与"最优性/收敛"解耦。

## 解决了什么问题
- RL 算法擅长最大化回报，但**不保证学习期或执行期的安全/正确性**（原文："do not necessarily guarantee safety during learning or execution phases"）。
- 现有"安全 RL"多靠 reward shaping、teacher advice 或外部知识引导探索，但缺乏**形式化的硬保证**；纯形式方法（reactive synthesis）能给保证却需要精确环境模型、计算代价大、且通常不带最优性。
- 本文目标即综合二者长处：在保证时序逻辑安全规约**始终不被违反**的前提下，让学习算法自由优化一个先验未知的性能目标（原文 §4 "combine the best of two worlds"）。

## 用什么方法解决的（含直觉：为什么 work）
- **核心对象 shield**：一个 correct-by-construction 的 reactive system，独立于学习算法的内部机制，只观察其输入输出行为。它强制两个性质：**correctness**（对安全规约 φˢ 永不违反）与 **minimum interference**（"as little as possible"，只在动作可能危及安全时才禁止）。
- **两种接法**：
  - **Preemptive shielding（前置，Fig.1/6）**：每步护盾先算出当前所有安全动作集合 {a¹…aᵏ} 交给智能体，智能体只能从中选。输出字母表 Σ_O = 2^𝒜（输出动作子集）。
  - **Post-posed shielding（后置，Fig.2/7）**：智能体先选动作 a¹ₜ，护盾监控之，**仅当该动作不安全时**才替换为一个安全动作 aₜ≠a¹ₜ。优点是即使智能体已是固定策略、处于执行期也能用，智能体甚至不需要知道自己被 shield（"does not even need to know that it is shielded"）。
- **为什么 work（直觉）**：安全不能只看当下——必须**提前规划（planning ahead）**。原文自动驾驶例子：车朝悬崖开，要保证不掉下去，必须在远未到崖边、异常尚不可检测时就减速，即"避免所有那些'已无法再避免掉崖'的状态"。护盾因此要禁掉**所有可能在未来被环境逼入不安全状态的动作**。
- **综合机制（§4–§6）**：把安全规约自动机 φˢ 与环境的 MDP 抽象 φ^M 做**乘积**得到一个 2-player 安全博弈 𝒢=Q×Q_M：环境玩家选下一观测（来自标签集 L），系统玩家选动作。用标准安全博弈求解算出**winning region W**（系统能保证永不进入不安全态的状态集）。护盾即由获胜策略实现：preemptive 输出 λ_S(g,l)={a∈𝒜 | δ(g,l,a)∈W}（所有保证留在 W 的动作）；post-posed 若智能体选的动作出 W 则替换为某个固定的安全 a′。
- **关键设计：抽象只需保守、可粗粒度、可无限状态 MDP→有限状态抽象**。护盾大小只取决于规约复杂度和抽象，**与被控系统真实状态空间维度无关**（§2 与 Wen/Junges 工作的主要区别）。博弈中若观测偏离抽象（落入 Q×(Q_M∖F_M) 的"paradise state"），算作系统获胜——因为系统只需在符合抽象的环境里正确。

## 动机 & 背景
- 学习型控制器越来越多用于人附近的物理系统，安全性受关注，但相比收敛/最优/数据效率，安全研究少（原文 §1）。
- 选用**时序逻辑的 safety fragment**（LTL，§3/§5）作规约语言：直觉上 safety = "something bad should never happen"，可表达不变式（如水位永不低于1升）也可表达更复杂的时间约束（如阀门一旦打开至少保持三秒）。Safety 规约可翻译为确定性 safety word automaton φˢ=(Q,q₀,Σ,δ,F)，只允许访问安全态 F。
- 与 teacher-guided RL 的关系：护盾可看作一个 teacher，但与以往不同，**不需要操纵 reward**，而是直接纠正学习/部署期的不安全动作（§2）。

## 方法细节
- **预备形式化（§3）**：MDP ℳ=(S,s_I,𝒜,𝒫,ℛ)；回报 R=Σγᵗrₜ；负回报 rₜ<0 称为 punishment。Reactive system / 有限状态机 / safety automaton / 2-player safety game 的定义齐全给出。
- **抽象 φ^M（§4）**：经 MDP observer function f:S→L 把状态映射到标签；要求抽象**保守**（真 MDP 的每条 trace 在抽象上对应的 run 始终留在 F），且不含"所有无限路径最终离开 F"的态，以尽早拒绝不可能出现的路径。
- **shield 综合三步（§6）**：① 把 φˢ 与 φ^M 翻成安全博弈 𝒢（G=Q×Q_M，环境选 L，系统选 𝒜，F^g=(F×Q_M)∪(Q×(Q_M∖F_M))）；② 标准安全博弈求 winning region W⊆F^g；③ 翻成 reactive system 护盾 𝒮=(Q_S,q_{0,S},Σ_{I,S},Σ_{O,S},δ_S,λ_S)。可选择删去不可达态化简。
- **Post-posed 支持动作 ranking**：智能体每步给出有序偏好 rankₜ=(a¹ₜ,…,aⁿₜ)，护盾选 rank 中**第一个安全**的动作；全不安全才用 rank 外的安全动作。ranking 还让智能体一步内对多个动作做策略更新（|rankₜ|+1 次）。
- **Post-posed 的 reward 两选项**：(1) 给不安全动作 a¹ₜ 赋惩罚 r′ₜ₊₁<0——智能体学到该动作不安全，但**不保证最终策略不含不安全动作**，故护盾即便学完也须常驻；(2) 把实际执行动作 aₜ 的 reward rₜ₊₁ 赋给 a¹ₜ——不安全动作可能仍出现在最优策略里，但因总被映射成安全动作不出问题，智能体无需学会回避，护盾在学习和执行期都要在。
- **理论证明（§6.1）**：证明了综合出的护盾满足 **correctness**（除非抽象本身先出错，否则规约永不被违反，且护盾永不 deadlock——每个标签下至少有一个动作留在 W）与 **minimum interference**（若护盾禁掉某动作，则存在一个与观测和抽象一致的 MDP，使得执行该动作有非零概率未来违反规约——即禁得有据，§6.1 对 preemptive 详证，post-posed 同理）。
- **收敛性（§7）**：把 shield+MDP 合成一个乘积 MDP ℳ′（标准 MDP），于是**任何在标准 MDP 上收敛的学习算法，在护盾下同样收敛**。条件：post-posed 情形当智能体给的 ranking 不含安全动作时，护盾对安全动作的选择须是一个不随时间变化的固定（可依状态而定）概率分布，否则无法建模为乘积 MDP。
- **可与函数逼近兼容**（§1/§2），因护盾只管输入输出结构、不碰算法内部；当规约自动机只有单态（"任意时刻 MDP 标签须为某种形式"）且抽象态可由上一 MDP 标签确定时，护盾状态空间可重构为与 ℳ 同，**对智能体而言与无护盾操作不可区分**（§7）。

## 数据集 & 实验设置
- 四个领域（§8）：(1) 9×9 与 15×9 网格世界机器人；(2) 自驾车绕街区（480×480 像素）；(3) Atari 2600 *Seaquest*（OpenAI Gym/ALE + DeepMind DQN 的 Python 实现，仅以 RGB 图为输入，agent 当黑盒）；(4) §4 的热水箱。
- 算法：网格用 tabular Q-learning（ε-greedy、支持一步多次更新）；自驾车用 DQN（Boltzmann 探索，4 输入节点/8 输出朝向/3 隐藏层）；水箱对比 Q-learning 与 SARSA。
- 网格安全规约：φ₁ˢ=机器人不得撞墙或撞移动对手（两实验都用）；φ₂ˢ=不得在炸弹上连续停留超过两步（仅 9×9）。综合时间：9×9 由 φ₁ˢ∧φ₂ˢ + 精确抽象 2 秒；15×9 仅 φ₁ˢ 0.6 秒；自驾车前/后置护盾各 2 秒；水箱后置护盾 <1 秒；水箱乘积博弈 602 态。
- 对比设置：无护盾 / 无护盾但加大惩罚 / 护盾（不同 |rank| 与是否对纠正动作罚分）。

## 主要结果 & 结论（写方向，不堆精确数字）
- **网格世界**：只有无护盾版本会经历负回报；护盾版本不仅安全，还**倾向于学得更快**（原文 "tend to learn more rapidly"）。在 15×9 中只有 |rank|=3 且不罚分的护盾版找到最优路径、平均回报最高；|rank|=1 或带罚分时学到次优路径（observed，见 Fig.11）。加大惩罚的无护盾版未达到护盾版的最高回报，也没加速学习（observed）。
- **自驾车**：无护盾版回报随时间上升但**仿真末段仍会撞墙**；不带惩罚的护盾版学得更快且**从不撞车**（observed，Fig.12）。
- **Seaquest**：shield 智能体性能与无护盾**基本相同**（"did not change its performance"），但安全规约 φ₁ˢ∧φ₂ˢ 在护盾下**未被违反**（observed，Fig.13）。
- **水箱**：护盾与无护盾的 Q-learning/SARSA **都**收敛到最优策略，但护盾版**显著更快**达到最优（observed，Fig.14）。
- 总结论（§9）：在所有场景，shield 智能体表现**至少不差于**无护盾版，多数情况下还改善了学习性能（"perform at least as well… In most cases… even improved"）。

## 适用边界（什么时候管用 / 什么时候不管用）
- **管用**：安全可写成时序逻辑 safety fragment（"坏事永不发生"型不变式/有界时间约束）；能给出一个**保守的有限状态环境抽象**；安全所依赖的环境状态分量可被观测/计算。护盾尤其适合规约复杂但安全相关状态维度可抽象得小的场景（与真实状态空间维度无关）。
- **本文验证规模**：网格/自驾/Atari/水箱等中小规模、离散或低维连续控制；安全规约都较简单（1–2 条）。
- **不管用/受限**：(1) 需要 liveness 等非 safety 性质时不在框架内（只处理 safety fragment）；(2) 抽象不保守或错误时，正确性保证失效（原文明说护盾只在符合抽象的环境里保证正确）；(3) 复杂规约 + 复杂抽象会让护盾状态空间很大（"can be relatively large"）；(4) 安全所依赖的环境信息无法获得/抽象时，无法判断哪些动作安全（§9 自承的主要缺点）。

## 核心贡献
- 提出 **shielded reinforcement learning** 框架：把 correct-by-construction 的护盾以 preemptive / post-posed 两种方式接入标准 RL 回路，在学习和执行全程强制时序逻辑安全规约。
- 给出从安全规约 + MDP 抽象**自动综合护盾的算法**（乘积安全博弈 + winning region 求解 → reactive system）。
- **证明**所综合护盾满足 correctness 与 minimal interference，并论证护盾不破坏底层学习算法的收敛保证。
- 关键工程优势：护盾**与学习算法内部解耦**、与函数逼近兼容、护盾规模独立于真实状态空间维度。
- 四个领域的实验（含源码公开，github.com/safe-rl/safe-rl-shielding）。

## 局限与我的质疑
1. **抽象的获取是真正命门，且本文回避了其难度**（作者自承 §9："need an approximate model of when which action is unsafe"）。论文实验里抽象多为"precise abstraction"或人工构造（网格/水箱手写），但现实复杂环境里构造一个既保守又足够精确的有限状态抽象，本身可能与原始难题一样难——这恰是纯形式方法的老问题，护盾并未真正绕过，只是把它前移到抽象设计上。
2. **正确性保证有强前提且实测安全性未量化报告**。所有保证都建立在"抽象保守且正确"之上，抽象一错保证即失效；而实验对"安全"的展示主要是回报曲线和"未被违反"的定性陈述（Seaquest "not violated"），**没有给出违规次数/碰撞次数等量化安全指标对照表**，对一篇主打"安全"的论文，这点证据偏弱（observed 级而非 strong）。
3. **学习加速是副产物、解释偏弱且非普适**。"护盾让学得更快"在网格/自驾/水箱观察到，但 Seaquest 性能无变化；作者未深入论证加速的机制边界（应是"剪枝坏动作=缩小有效探索空间"，但这依赖坏动作恰好低回报，并非总成立）。措辞上宜按 observed 理解，不应外推为"护盾普遍加速学习"。
4. **post-posed 的 reward 处理留有未解张力**：选项 1（罚不安全动作）不保证最终策略安全、护盾须永久常驻；选项 2 则智能体永远学不会自主回避不安全动作。两者都意味着**护盾在部署期不可移除**——即"安全"始终是外挂的、智能体本身从未真正"学会安全"，这对追求端到端自主安全策略的目标是个根本性局限。
5. **规模化与实时性证据不足**。护盾状态空间随规约/抽象复杂度增长（自承"can be relatively large"），实验综合时间虽都在秒级，但规约都极简单（≤2 条、博弈仅几百态）；对工业级复杂时序规约的综合可行性、以及每步护盾查询的实时开销，论文未给压力测试。
6. **与本研究主题（RL 通用工具箱/安全增强）的契合点与不足**：该方法提供的是"硬保证型"安全外壳，适合作为安全增强的一条形式化路线；但它要求白盒式的安全规约与环境抽象，与现代大规模深度 RL/连续高维控制（如 2018 年后的 SAC/PPO 安全约束、CMDP/拉格朗日法）相比，**可扩展性和对模型未知性的鲁棒性是明显短板**，更像是低维/可形式化场景下的安全保证工具，而非通用安全 RL 方案。
