# Sim-to-Real: Learning Agile Locomotion For Quadruped Robots
> Jie Tan, Tingnan Zhang, Erwin Coumans, Atıl Işçen, Yunfei Bai, Danijar Hafner, Steven Bohez, Vincent Vanhoucke · 2018 ·  · 引用 673 · DOI 10.15607/rss.2018.xiv.010

## 一句话
本文提出一套完整系统：在物理仿真里用深度强化学习（PPO）从简单 reward 学出四足机器人（Minitaur）的敏捷步态，再通过"提高仿真保真度 + 学鲁棒控制器"两条路缩小 reality gap，使仿真学到的策略**无需真机微调即可直接部署**，学出了小跑（trotting）和奔腾（galloping）两种步态。(supported)

## 解决了什么问题
- 传统四足敏捷步态控制依赖专家经验和手工调参，作者要把这一过程自动化。
- 仿真中学到的控制器迁移到真机常常失效，即"reality gap"——由模型差异（未建模动力学、错误参数、数值误差）造成；作者指出在 locomotion 任务上这一 gap 被**放大**，因为敏捷运动有频繁接触切换，把控制空间切成碎片，任何小模型误差都会被放大并产生分叉后果（原文 "bifurcated consequences"）。
- 直接在真机上学 locomotion 很难：难以自动重置实验、持续采数据，且每次摔倒都可能损坏机器人——所以作者选择"仿真里学、真机上测/部署"。

## 用什么方法解决的（含直觉：为什么 work）
两大支柱：**(A) 提高仿真保真度**，**(B) 学鲁棒控制器**。直觉是从两端夹逼 reality gap——既让仿真更接近真实，又让策略对剩余的仿真-真实差异不敏感。

(A) 提高仿真保真度（让仿真更像真）：
- **精确系统辨识**：拆解 Minitaur，量尺寸、称质量、测各连杆质心、测电机摩擦，写进 URDF（惯量难测，按均匀密度估）。
- **更真实的执行器模型**：作者发现 Bullet 默认的约束式电机模型会让大增益下电机"在仿真里稳、在真机上振荡"；且线性 torque-current 关系只在理想电机成立、真机里 torque 随电流饱和。于是按理想直流电机动力学 + 一个分段线性的 torque-current 函数重建执行器模型。直觉：执行器是仿真-真实差异的主要来源之一，把电机扭矩特性建准，真机才不会"瘫坐/抬不起腿"。
- **延迟（latency）建模**：Bullet 里命令瞬时生效、传感器瞬时反馈，使仿真里反馈控制器的稳定域比真机大得多，导致仿真学的反馈策略到真机会振荡发散。作者保留观测历史 \{(t_i, O_i)\}，按真实测得的延迟在历史里线性插值出"延迟后的观测"。直觉：不建延迟，反馈策略会学得过于激进，真机上失稳。

(B) 学鲁棒控制器（让策略对残余差异不敏感），三种手段：
- **动力学随机化**：每个 episode 开始从 Table I 的范围里均匀采一组物理参数（质量、电机摩擦、惯量、电机强度、控制步长、延迟、电池电压、接触摩擦、IMU 偏置/噪声等）。直觉：训练时见过参数分布，真机参数落在分布内就能 cover。作者特意把范围取得保守（基于已测量值 + 安全裕度），因为随机化是"以最优性换鲁棒性"，范围过大会学出过于保守的慢步态。
- **加随机扰动力**：仿真里每 200 步（1.2s）对机身施加随机方向、量级约 130–220N、持续 10 步（0.06s）的扰动力，逼策略学会从各种失衡中恢复。
- **紧凑观测空间**：观测只用 base 的 roll/pitch + 这两轴角速度 + 8 个电机角度（**故意排除会快速漂移的 IMU 位置、会噪的电机速度**）。直觉：高维观测易过拟合仿真无关细节，紧凑观测留给过拟合的空间小，更易迁移。

策略表示与训练：
- 把 locomotion 建成 POMDP（机身位置、足接触力等不可观），用 **PPO**（on-policy、稳定、易并行）优化。优化目标 π* = arg max_π E_{s0~D}[R_π(s0)]（式1）。
- **混合策略（可控性全谱）**：动作 a(t,o) = ā(t) + π(o)（式3），ā(t) 是用户给的开环参考信号（典型为周期信号，表达想要的步态风格），π(o) 是神经网络反馈分量（学平衡等难手调的部分）。把 π 的输出上下界都设 0 → 纯用户指定步态；让 ā(t)=0 且 π 输出范围放宽 → 完全从零学。直觉：用户管"风格"、学习管"平衡"，二者解耦。
- **动作空间用 leg space 而非 motor space**：每条腿用 swing/extension (s,e) 表示，映射到电机角 θ1=e+s, θ2=e−s（式中）。直觉：motor space 里大量配置因自碰撞无效、有效动作散成非凸区域，难学；leg space 里可用矩形框圈掉无效动作、仍覆盖大部分有效配置。

关键公式：
- **reward**（式2）：r = (p_n − p_{n−1})·d − w·Δt·|τ_n · q̇_n|。第一项 = 沿期望方向 d 的前进距离（鼓励跑快），第二项 = 能耗惩罚（τ 扭矩、q̇ 电机速度），w=0.008（称算法对 w 鲁棒故未调）。
- **执行器/PD**：误差 e_{n+1} = k_p(q̄ − q_{n+1}) + k_d(q̇̄ − q̇_{n+1})（式4，约束的是时间步**末**的角度/速度，区别于普通 PD 用当前值——这是大增益下仿真不再假性振荡的关键）；理想电机 τ=K_t·I，I=(V_pwm − V_emf)/R，V_emf=K_t·q̇（式5、6）；位置控制下 V_pwm = V(k_p(q̄−q_n)+k_d(q̇̄−q̇_n))（式7，目标速度 q̇̄=0）。

## 动机 & 背景
- 经典 legged locomotion 控制靠手工调参（Raibert 等），可否自动化？深度 RL 在仿真 benchmark 上进展大，但多数研究只在仿真里做、迁移真机表现差。
- 相关工作两类缩小 gap 的思路：① 系统辨识（[31–39]：辨识物理参数、行为匹配、自建模、GP 非参数建模、在线辨识、隐式嵌入 RNN）；② 鲁棒控制（注入噪声、扰动、多仿真器、域随机化、动力学随机化 [39,41,42,43,44]）。还有从仿真+真实数据联合学（预训练后微调 [45]、grounded action transformation [46]、视觉域适应 [47–49]）。
- 作者定位：既辨识又随机化，且**重点在真机上测策略**（区别于多数只在仿真里做的工作），并强调要缩的是**动力学**的 gap 而非感知的 gap。

## 方法细节
- **硬件**：Minitaur（Ghost Robotics），8 个 direct-drive 电机，每腿 2 电机在矢状面内运动，PWM 驱动；STM32 微控制器收发指令、Nvidia Jetson TX2 跑神经网络策略（微控制器算力不够跑 deep RL 策略）；控制环约 150–200Hz，**非实时系统**（故控制步长/延迟会波动）。
- **仿真**：用 PyBullet 建 Minitaur，Bullet 用广义坐标解刚体运动方程、满足接触/关节限位/执行器约束，半隐式积分。
- **观测/动作**：观测 = roll、pitch、两轴角速度、8 电机角（紧凑，安全且易学、易迁移）；动作 = leg space 的 (s,e)，位置控制（安全、易学）。
- **训练设置**：episode 1000 步终止，或仿真机身倾斜超 0.5 弧度（失衡）即终止；每次策略更新并行跑 25 个 roll-out；训练上限 7M 仿真步。神经网络反馈分量为全连接、2 隐层，大小经超参搜索定（见 Table II）。
- **延迟测量**：微控制器 PD servo 延迟低（3ms），TX2 上的 locomotion 控制器延迟高（典型 15–19ms），按实测设进仿真。

## 数据集 & 实验设置
- 无外部数据集；"数据"=仿真 roll-out + 真机部署回报。两个任务：galloping、trotting。
- **可量化的 reality gap 度量**：不用二元成功率（不能刻画速度/能耗），而用 Koos et al. 的连续度量——分别在仿真和真机用式2 算 expected return，二者之差即 reality gap。
- **为提高结论可信度**：每个实验训 100 个不同超参/随机种子的控制器，按仿真 return 取 top 3 部署真机，每个真机跑 3 次，9 次平均作为 expected return（应对学习算法随机性 + 真实世界随机性 + 鲁棒性差异带来的大方差）。
- **消融分组**（均用 4 维观测）：组I 基线仿真（无执行器模型/延迟）、组II 基线仿真+随机扰动、组III 改进仿真+随机扰动（=本文方法）（Fig 6）。
- 另有：随机化 vs 不随机化在不同 body inertia 下的对比（Fig 7）；不同观测空间 × 随机化在仿真各环境的 return（Fig 8）；观测空间 × 随机化的仿真-真机对比（Fig 9，4D 小观测 vs 12D 大观测）。

## 主要结果 & 结论（写方向，不堆精确数字）
- **两种敏捷步态成功直接迁移真机、无需真机微调**：galloping 从零学出、trotting 借用户开环参考学出，仿真里学完直接部署即可工作。(supported)
- **galloping 从零自动涌现**：在基线仿真（无执行器/延迟模型）下系统只学出慢走、真机立刻摔倒；改进仿真后涌现敏捷 galloping，且多数超参/种子的解都收敛到 galloping，偶见 trotting/pacing 等其它步态。(observed)
- **学出的步态与专家手调步态速度相当，但更省电**：Table III 显示 galloping/trotting 学习版功耗较手调版分别约降 35% 和 23%（功耗值见 §VI-A Table III）。注意速度上 trotting 学习版略快、galloping 学习版略慢于手调版，作者的方向性主张是"一样快但更省电"。(supported)
- **提高仿真保真度是迁移的必要条件**：组I/II（基线仿真，即便加扰动）在真机上表现差、reality gap 大；只有组III（改进仿真+扰动）在仿真和真机上表现相当（Fig 6）。结论：模型差异太大时，光靠鲁棒控制器也跨不过 gap。(supported)
- **执行器模型和延迟建模都不可或缺**：缺任一个，学到的控制器在真机上都不工作。(supported)
- **随机化以最优性换鲁棒性**：随机化训练的控制器在不同 body inertia 测试环境下表现稳定（return 随惯量变化平缓），不随机化的在惯量偏离训练值时 return 显著下降、但峰值更高（Fig 7）；聚合多环境看，随机化训练的均值更低、标准差更低（更鲁棒但更保守，Fig 8）。结论：随机化非免费午餐，应仅在必要时用。(supported)
- **观测空间大小与 reality gap 的权衡（一个反直觉发现）**：大观测（12D）在**仿真**里 return 更高（信息多、任务更易学），但部署真机后**反而更差**、reality gap 更宽；小观测（4D）仿真-真机更一致。作者解释：大观测下训练时遇到的观测相对稀疏，真机上难遇到相似观测易摔；小观测下训练/测试的观测分布更重叠。(observed/supported)
- **最佳组合**：小观测 + 随机化——该组 top3 控制器 9 次真机运行全部能 trot 超 3 米并维持整段平衡。(observed)
- 速度参考量级：galloping 仿真约 1.34 m/s（2.48 体长/s）、真机约 1.18 m/s（2.18 体长/s）；trotting（4D 观测重训后）仿真约 0.50 m/s、真机约 0.60 m/s（具体值见 §VI-A）。

## 适用边界（什么时候管用 / 什么时候不管用）
- **管用**：平地上、目标为"最大化前进速度"的简单环境；direct-drive 四足（Minitaur 类）；步态风格可由开环周期信号表达 + 反馈网络补平衡；reality gap 主要来自**动力学**且能通过系统辨识 + 保守随机化覆盖。
- **随机化要克制**：范围必须基于实测 + 安全裕度，过大将学出过于保守的慢步态（牺牲敏捷性）。
- **观测要紧凑**：高维观测虽利于仿真内学习，但会拉宽 reality gap、害迁移；小观测更易迁移。
- **不直接适用**：需要动态改变速度/方向、需要视觉感知复杂地形/转向导航的场景——作者明确把这两项列为未来工作；本文只做平地恒向前进。
- 缩的是动力学 gap，**不处理感知 gap**（无视觉输入）。

## 核心贡献
1. 提出一套完整的敏捷 locomotion 学习系统，给用户"从受限于指定步态到完全从零学"的全谱可控性（混合策略 a=ā+π）。
2. 系统性地用"多种手段 + 全面消融评估"展示如何缩小 reality gap（提高仿真保真度：执行器模型 + 延迟；鲁棒控制：动力学随机化 + 扰动 + 紧凑观测），并量化各手段贡献。
3. 实证 trotting/galloping 等敏捷步态可自动学出，且能**无需真机额外训练**直接在真机工作。

## 局限与我的质疑
1. **任务极简、泛化主张需克制**：全部实验是平地、定方向、最大化速度。作者自述真实场景需变速/变向/视觉导航复杂地形，均留作未来工作。因此"deep RL 能学敏捷 locomotion"这一结论只在很窄的设定下被证明，读者不应外推到复杂地形或导航任务。(我的质疑)
2. **结论高度依赖大量重复实验+top-3 挑选**：作者坦言真机表现方差很大（"some policies can transfer while others cannot"），做法是训 100 个、按仿真 return 挑 top3 再部署。这意味着**单个随机种子的可靠迁移并未被证明**；"成功迁移"带有挑选幸存者的成分，真实成功率/失败率分布未充分披露。(我的质疑)
3. **"更省电"的对照基线是否公平存疑**：与 Ghost Robotics 手调步态比功耗降 35%/23%，但手调步态的调优目标可能并非省电（如更高速度/稳定裕度），且 galloping 学习版速度略低于手调版——低速本身就更省电，能耗优势可能部分来自速度差而非方法优越。把"省电"当卖点需谨慎。(我的质疑)
4. **执行器模型/惯量等仍有未消除的近似**：URDF 惯量按均匀密度估、电机扭矩用分段线性近似、接触摩擦用 Bullet 默认 LCP 参数未精细辨识（作者自述接触参数辨识困难），这些残余误差正是要靠随机化兜底——但随机化又牺牲敏捷性，存在内在张力。(作者自述局限 + 我的质疑)
5. **观测空间结论的机制解释偏定性**："大观测训练观测稀疏→真机难遇到→易摔"是作者的推测（"We suspect/We believe"），并未给出观测分布重叠度的直接定量证据，机制层面证据偏弱。(我的质疑)
6. **相对本研究主题（数字人交互的 RL）的不足**：本文是固定 reward、无外部交互对象、无人在环、无语义任务的纯 locomotion；其 reward 工程（前进项−能耗项）和域随机化范式可借鉴，但它不涉及与动态环境/人交互、不涉及高层任务条件化，迁移到交互式数字人场景时方法的可控性（开环参考）和鲁棒性（随机化）只是部件级启发，非现成方案。(我的质疑)
7. **可复现性**：reward 权重、网络结构、随机化范围等关键超参给了具体值（式2、Table I/II），代码也开源（Bullet 库），这点较好；但延迟、电机参数等系统辨识结果绑定特定 Minitaur 硬件，换平台需重做辨识。(中性)
