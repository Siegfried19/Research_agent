# CIM: Constrained Intrinsic Motivation for Sparse-Reward Continuous Control
> [, ", X, i, a, n, g,  , Z, h, e, n, g, ", ,,  , ", X, i, n, g, j, u, n,  , M, a, ", ,,  , ", C, o, n, g,  , W, a, n, g, ", ] · 2022 · arXiv.org · 引用 2 · DOI 10.48550/arxiv.2211.15205

## 一句话
CIM 用"任务先验投影"把内在好奇心约束到与任务相关的低维子空间，再用拉格朗日方法把内在/外在目标写成"带约束的同时最大化"问题、随训练进展自适应缩减内在奖励权重，从而在稀疏奖励连续控制任务上比现有内在动机方法探索得更有效。

## 解决了什么问题
- 稀疏/无外在奖励的强化学习里，内在动机（intrinsic motivation）是主流探索手段，但作者指出现有做法有两处通病。
- 通病一：现有内在目标都是"任务无关（task-agnostic）"设计的——它鼓励 agent 覆盖**整个**状态空间，在高维连续控制里大量探索与任务无关的维度，效率低。
- 通病二：内在目标与外在目标的组合方式要么是"简单相加"，要么是"先无奖励预训练再下游微调"。作者主张简单相加会给收敛策略引入**不消失的偏置**（内在奖励不收敛到零，始终干扰 agent）；无奖励预训练得到的策略迁移性差。
- 作者用实验主张：在典型稀疏奖励连续控制任务上，这些设计会失败（原文 "these designs would fail in typical sparse-reward continuous control tasks"）。

## 用什么方法解决的（含直觉：为什么 work）
CIM 由两个可独立插拔的技术组成。

**技术一：任务先验投影器（task-prior projector），约束内在目标。**
- 不再最大化**完整**状态分布的熵，而是最大化**投影后**状态分布 d_π^p 的熵（Eq 16：`f_i^CIM(d_π^p)=E_{proj_P s~d_π^p}[−ln d_π^p(s)]`），投影空间 P 取为完整状态空间的一个低维子空间（P⊂S）。
- 投影器写成"掩码算子 ⊙ 选定基向量"的复合形式（Eq 12–13）：`proj_P := m^p ⊙ [e_{i1}…e_{im}]^T`，其中掩码 `m^p=[f_1(s_{i1}),…,f_m(s_{im})]^T`。例：SparseAnt 任务取躯干位置 x 与 x 向速度 v_x，`m^p=[1[x>0], 1[v_x>0]]`。
- **直觉（为什么 work）**：在高维任务里，"完整状态熵高"并不等于"任务相关维度被充分探索"——例如加速度维度多样并不意味着位置多样。把内在奖励聚焦到与任务方向相关的少数维度（如"向前跑"任务只看 x 与 v_x），就只奖励"对任务有用的探索"，不再在无关维度上浪费样本。附录还指出位置多样性贡献的 bonus 在初期几乎为零、用处不大，而速度多样性有助于 agent 在初始区域附近起步（见附录 B.3）。
- 附带好处：kNN 熵估计复杂度 `O(mn ln n)`，投影维 m 很小（多任务里 m=2），而 Humanoid 完整状态是 376 维、APT 的潜空间是 1024 维，故 CIM 在计算上也更省。

**技术二：用拉格朗日方法自适应平衡内在/外在目标。**
- 把外在目标改写成约束（Eq 21）：`max f_i(d_π) s.t. f_e(d_π) ≥ R̂`。拉格朗日量（Eq 23）：`L(d_π,λ)=f_i(d_π)+λ(f_e(d_π)−R̂)`；对偶问题（Eq 24）`min_{λ≥0} max_{d_π} L`。
- 乘子 λ **用梯度下降更新**（Eq 25，原文 "λ can be updated by gradient descent"）：`λ_{l+1}=λ_l − η_l(f_e(d_π)−R̂_l)`。
- 为稳定，实际用等价形式（Eq 26）：`L̃_l(d_π,λ)=λ̃_l^{-1} f_i(d_π)+(f_e(d_π)−R̂_l)`，其中 `λ̃_l=max(λ_l,1)`；外在目标 f_e 增大时 λ̃ 逐渐降到零。Table 1 给出的组合公式即 `max(λ_l,1)^{-1} r_t^i + r_t^e`。
- 约束阈值 R̂ 用启发式课程（Eq 22）：`R̂_l=α·f_e(d_{π_{l-1}})，α>1`。早期 R̂_l 与 f_e 都为零、约束天然满足，agent 专注内在目标（探索）；一旦 f_e 变非零，R̂ 自动开始增长。
- **直觉（为什么 work）**：简单相加会让内在奖励的偏置一直留在收敛策略里。约束形式让内在权重 λ̃^{-1} 在外在奖励出现后自适应地缩向零——前期"探索为主"、后期 agent 找到目标后"利用为主"，从而削弱内在动机带来的偏置（图 8/10 显示 λ̃^{-1} 从 1 降到 0）。

## 动机 & 背景
- 内在动机分三类：knowledge-based（如 ICM、RND）、data-based（如 MaxEnt、APT、MADE）、competence-based；作者认为 competence-based 太难、预训练后常不如随机初始化（引 Laskin 2021）。
- data-based 路线常用最大状态熵 + 非参数 k 近邻（k-NN）熵估计器（引 Hazan 2019、Mutti 2021、Seo 2021）；但这些要么只做无奖励纯探索，要么依赖 pixel 输入的随机编码器归纳偏置，在多种稀疏奖励连续控制上仍不灵。
- CIM 定位在"最大状态熵探索"谱系里，区别是把"任务无关投影"换成"任务先验投影"，并显式处理内在/外在组合的偏置问题。

## 方法细节
- 框架：凸 MDP 下，诱导状态分布 d_π，内在目标是 d_π 的可微函数 f_i（L-Lipschitz 梯度）；常见 f_i 为微分熵（Eq 6）、反向 KL（Eq 7）、MADE 的覆盖正则（Eq 8）。
- 投影熵估计（Theorem 2）：`ĥ_{n,k}^p(S)=(m/n)Σ ln(R_{i,k}^p)+b`，R^p 是投影后状态到第 k 近邻的距离；依据 Lemma 1（Jiao 2018，估计器近 minimax 最优）。
- 内在 bonus：`r_t^CIM=−ln f̂^p(x_t)−1 ∝ ln R_{t,k}^p`（Eq 19），稳定用平均版 `r_t^CIM=ln(1+(1/k)Σ_i R_{t,i}^p)`（Eq 20）。
- 理论支撑：Lemma 4（Hazan 2019，Frank-Wolfe 给出 oracle-efficient 算法，使 f_i 接近最优）；Lemma 3（Puterman）；据 Eq 16–18 推出 bonus。Eq 18 给出"内在奖励 = 内在目标对状态分布的梯度"`r_t^i=(∇f_i(d_π))_{s_t}`，并指出 `r^e=∇f_e(d_π)` 可恢复外在奖励。
- 与其它组合法的统一视角：设 `R̂_l=1[l>N], λ_0=0, η_l=+∞` 可恢复"无奖励预训练"；设 `R̂_l=0, λ_0=λ_p, η_l=0` 可恢复"简单相加"（见 §3.2 末）。
- 落地算法（Algorithm 1，附录 C.1）：on-policy PPO，分别估计外在/内在优势（GAE），总优势 `A=λ̃_l^{-1} A^i + A^e`，对 θ、外在 critic、内在 critic 做梯度下降。

## 数据集 & 实验设置
- 策略 oracle：on-policy PPO（基于 Tianshou 实现），k-NN 距离用 KeOps 计算；每个配置 5 个随机种子。
- 任务（均为自定义稀疏奖励）：经典控制 SparseGridWorld-v0（2D）、SparsePendulum-v0（3D，角度阈值收紧到 1°、角速度阈值 1°/s）；MuJoCo 三个高维任务 SparseHalfCheetah-x20（18D）、SparseAnt-x10（113D）、SparseHumanoidStandup-z1（376D），只有躯干越过指定阈值（如 x>20、x>10、z>10）才给外在奖励 1。最大 episode 步数均 500。
- 基线：ICM、RND、APT、MADE（其中 MADE、RE3、APT 被列为 SOTA）。明确不比 MaxEnt（只为无奖励纯探索）、MEPOL（不用内在 bonus）、RE3（只适配 pixel RL）。带稀疏奖励的纯 PPO oracle 学不会这些任务，故从图中略去（原文称其为 weak baseline）。
- 默认超参（Table 2/3）：total_timesteps 5e6、discount 0.99、GAE λ 0.95、k=10、α=2、η=1、obs_rep_dim 64、mlp_hidden_dim 128、策略/价值网 [64,64]、lr 3e-4、MLP 用 BN。

## 主要结果 & 结论（写方向，不堆精确数字）
- 低维任务（图 2）：CIM 在两个任务上都优于全部基线，SGridWorld 平均成功率约 0.8、SPendulum 约 1（supported）。
- 低维任务里基线不稳：APT 迁移差、SPendulum 上 ICM 成功率低且近零、RND 与 MADE 两任务都失败（observed）。
- 高维任务（图 3）：CIM 显著超过全部基线，且**只有 CIM 能稳定解出全部三个**高维任务（supported）。
- 对照：APT 能解两个低维任务，却三个高维任务全失败——作者据此论证任务无关设计在高维稀疏奖励连续控制上低效（observed→supported）。
- 拉格朗日消融（CIM vs CIM w/o L，图 2/3）：加 L 能有效平衡内在/外在、降低内在动机引入的偏置，使 agent 到达目标后不再被内在奖励分心（supported，仅本文设定内）。
- 插件研究（图 4）：把"任务先验掩码 P"和"拉格朗日 L"单独插进 APT/ICM/RND/MADE 都能提升其表现，尤其在 SHalfCheetah（observed）。掩码对 knowledge-based bonus（如 RND+P）比 data-based（APT bonus+P）更明显；L 还能把 MADE+P+L 再提升近一半。但在 SAnt 上 ICM+P 不起作用，作者归因于 agent 探索能力本身太差（observed）。
- 鲁棒性消融（图 5、图 11）：对课程增长率 α（1–16）、拉格朗日步长 η（0.1–10）、熵估计样本量 n（1e5–5e6）、近邻数 k（1–10）都不敏感（supported）。
- 可视化（图 7/9 状态热力图）：CIM 把探索集中在"四分之一投影空间"并到达目标；ICM 把力气花在投影空间所有方向上、属无效探索；PPO 难以覆盖目标区。图 8/10 显示逆拉格朗日系数 λ̃^{-1} 一旦 agent 跨过目标线就从 1 降向 0。

## 适用边界（什么时候管用 / 什么时候不管用）
- 管用：稀疏/无外在奖励的**连续控制**任务；状态完全可观（这样投影空间能取为状态空间子集，P⊂S）；且**事先知道哪些状态维度与任务相关**（如"向前跑"→取 x、v_x）。状态维度越高、任务无关维度越多，相对优势越大（图 3）。
- 低维任务（如 SGridWorld）可把投影器取为恒等映射（投影空间=完整空间）。
- 不管用/受限：作者明说当 agent 自身探索能力太差时，连"加任务先验掩码"也救不了（SAnt 上 ICM+P 无效）；且本文只用 on-policy PPO，off-policy 留作未来工作。
- 强/弱基线：与之比的 APT/ICM/RND/MADE 是较强的内在动机基线（含 SOTA），但它们都**不带任务先验**；纯稀疏 PPO 这种弱基线被直接略去。

## 核心贡献
- 提出 CIM：用"任务先验投影器"把内在状态熵目标约束到任务相关低维子空间，避免在无关维度上浪费探索。
- 提出用拉格朗日方法把内在/外在写成带约束的同时最大化问题，乘子 λ 用梯度下降自适应更新，前期重探索、后期重利用，削弱简单相加引入的偏置。
- 证明这两项技术可单独插进现有 knowledge-based / data-based 内在动机方法以提升其表现（插件研究）。
- 给出投影熵估计的理论（Theorem 2，基于 k-NN 估计器）与统一视角（恢复无奖励预训练 / 简单相加为特例）。

## 局限与我的质疑
1. **任务先验靠人工指定，"readily attainable"承担了过多假设。** 掩码如 `1[x>0]` 本质上把"任务目标方向"喂给了方法；对于不知道哪些维度相关的任务，CIM 的核心优势会消失。作者自己承认"目标不是为某任务找最佳先验，而是给出设计原则"，等于把这块难题留给了使用者。
2. **先验与稀疏奖励/目标定义高度耦合，近乎特权信息。** 稀疏奖励本身就用投影到目标空间定义（Eq 4），掩码又取同一组维度——部分"CIM 赢"可能只是"我们把任务方向信息给了自己的方法、却没给基线"。插件研究（给基线加 P）部分回应了这一点，是加分项，但主结果（图 2/3）对比并未对齐这一信息差。
3. **结果指标单一、规模有限。** 只报成功率曲线、5 个种子；正文没有给出明确的样本效率数值（只能从图读）。SAnt 上 ICM+P 失效归因于"探索差"略显事后解释（hand-wavy）。
4. **方法适用面被框定。** 只验证 on-policy PPO 与完全可观状态；off-policy、部分可观、像素输入都未验证（RE3 那类 pixel 方法被排除在对比外）。
5. **影响力与成熟度信号弱（非论文内容，仅元数据）。** 2022 arXiv 预印本、引用 2，未见正式发表信号；结论强度宜按"有系统实验支撑但样本/任务规模有限"来读，不宜外推为普适。
6. **与本研究主题（内在/外在奖励组合、约束优化）的契合点很实在**，但"投影维度怎么选"这一最关键的工程决策，本文给的是案例而非可自动化的方法——对想直接复用的人是主要缺口。
