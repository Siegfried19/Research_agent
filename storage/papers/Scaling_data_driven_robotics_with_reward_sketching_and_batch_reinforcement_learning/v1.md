# Scaling data-driven robotics with reward sketching and batch reinforcement learning
> Serkan Cabi, Sergio Gómez Colmenarejo, Alexander Novikov, Ksenia Konyushkova, Scott Reed, Rae Jeong, Konrad Zolna, Yusuf Aytar, David Budden, Mel Vecerik, Oleg Sushkov, David Barker, Jonathan Scholz, Misha Denil, Nando de Freitas, Ziyu Wang · 2019 · arXiv · 引用 0 · DOI arxiv:1909.12200

## 一句话
提出"奖励草图(reward sketching)"——让人手画一条进度曲线来高效标注每帧奖励,用它训出排序式奖励模型去回溯性地给海量历史机器人数据贴标签,再用纯离线的分布式 batch RL 学出真机操作策略,从而把数据驱动机器人规模化。

## 解决了什么问题
真实机器人 RL 缺两样东西:海量带奖励信号的数据,以及一个对每个新任务都能用的奖励函数;靠手工设计奖励工程(reward engineering)随任务复杂度增加无法 scale(supported)。本文要在"不预设奖励、不依赖状态估计、直接从像素学、且学习过程不在真机上在线探索"的约束下解决多步操作任务。

## 用什么方法解决的（含直觉：为什么 work）
- 核心三件事:(1) 高效征询人类偏好以学奖励函数;(2) 用学到的奖励自动标注全部历史数据;(3) 用 batch RL 完全离线地从这堆被标注的数据学策略。
- **Reward sketching(奖励草图)**:标注者用自定义界面在视频上"擦动(scrubbing)",画一条随时间表示"朝目标进展程度"的曲线 s(x_t)∈[0,1],绿色区域留给已达成目标的帧。直觉:人很难一帧帧打分,但能可靠地连续画出"进度趋势",所以一个标注者每分钟能产出数百帧标注——把昂贵的人类判断变成高带宽信号。
- **奖励学习用 intra-episode ranking,而非回归绝对值**。直觉:作者发现标注者对"同一 episode 内两帧谁更好"高度一致,但对"奖励的整体 scale"不一致;所以只学同 episode 内的相对排序,绕开 scale 噪声。两个 hinge loss:
  - 排序项:`L_rank(ψ) = max{0, r_ψ(x_t) − r_ψ(x_q) + μ_r} · 1[s(x_q) − s(x_t) > μ_s]`(当 x_t 的草图值显著高于 x_q 时,要求预测奖励也拉开 μ_r 的差)。
  - 成功/失败项:`L_success(ψ) = max{0, τ_r1 − r_ψ(x)} · 1[s(x) > τ_s] + max{0, r_ψ(x) − τ_r2} · 1[s(x) < τ_s]`(把"成功帧"压到阈值之上、"失败帧"压到阈值之下)。
  - 总损失 `L = L_rank + λ·L_success`,超参 μ_s=0.2, μ_r=0.1, τ_s=0.85, τ_r1=0.9, τ_r2=0.7, λ=10(见 §II-D)。
- **回溯性奖励标注**:奖励网络只在少量带草图的 episode 上训练,然后对 NES 里所有历史 episode(含为其他任务采集的数据)预测奖励。直觉:固定一份标注成本,就能把"为别的任务收集的旧经验"循环利用到新任务上,把数据量放大一个量级。
- **NeverEnding Storage(NES)**:一个集中、可用 SQL 查询的关系型数据库,持续累积所有任务的机器人经验(遥操作、人玩、脚本策略、训练策略产生的轨迹),并挂上环境/策略元数据与奖励标签。直觉:把"数据"与"任务"解耦,新任务来了不必重采,直接切片检索。
- **Batch RL(分布式)**:用类似 D4PG 的分布式 DPG 算法,维护循环的 value 网络 Q(x_t, h_t^Q, a|θ) 和 policy 网络 π(x_t, h_t^π|φ),用 target 网络周期性更新,BPTT 训练,采样时用零初始 recurrent 状态。直觉:全程不碰真机,既省磨损又让研究者能像在 ImageNet 上换模型一样自由试 batch RL 算法。
- **Fixed ratio batches**:每个 batch 75% 从整个 NES 抽、25% 从目标任务数据抽,保证当前任务有足够代表性。
- **迭代闭环**:奖励函数早期会被策略"钻空子(delusions)",人再补画几个 episode 的草图修正奖励,通常重复 2–3 次直到奖励满意。

## 动机 & 背景
- 视觉/语言/游戏靠海量标注数据让深度学习成功,但真机机器人数据只能实时采集、无法加速,且真实世界本身不自带奖励(supported)。
- 现有真机 RL 多依赖针对特定任务的手工奖励或状态估计,任务一复杂就不 scale;本文主张直接从原始观测学、不预设奖励、规模上超越以往(作者自述定位)。
- 与本文最接近的是 QT-Opt(Kalashnikov 等,文中[35]):收集 7 台机器人数周共 58 万+次抓取、训分布式 Q-learning;但它聚焦单一抓取任务、且仍是为奖励工程量身定制的脚本采集。本文对比强调自己覆盖多任务、学奖励函数(related work,非本文结果)。

## 方法细节
- 工作流 7 步(Fig.5):A 人遥操作示范 → B 全部经验入 NES → C 人对 NES 子集画草图 → D 训奖励模型 → E 用预测奖励在全 NES 上跑 batch RL 训策略 → F 部署真机并继续采集 → G 偶尔挑 agent 做正式评测。其中 D/E 无人、任务相关;B/A 任务无关。
- 机器人由 6-DoF 鼠标+夹爪按钮(或 VR 手柄)遥操作;观测 x_t 含多相机原始像素 + 本体感知。约 15% 的人类示范在结尾是失败的(作者特意保留)。
- 奖励网络:非循环的残差网络 + spatial softmax(64 通道关键点编码),本体特征拼入,输出经 sigmoid(因草图值在 [0,1])。
- Agent 网络(Fig.7):每个相机独立用残差网+spatial softmax 编码出 64 个 (x,y);softmax 前给 logits 加 U[−0.1,0.1] 噪声以让预测更集中;本体特征经线性层+layer-norm+tanh 后拼接。actor π(x) 直接吃联合特征;critic Q(x,a) 再过线性层并拼接动作;两者各用两层 layer-normalized LSTM(256 隐单元);动作经 tanh 限到 [−1,1] 再 rescale。

## 数据集 & 实验设置
- 硬件:Sawyer 机械臂 + Robotiq 2F-85 夹爪 + 腕部力矩传感器,面向 35×35cm 篮筐;动作空间 6-DoF 笛卡尔速度+二值夹爪(连续);控制 10Hz;每 episode 200 步(20 秒),安全则提前终止。
- 观测:3 个机笼相机 + 3 个腕部相机(广角×2 + 深度)+ 本体感知。
- 任务:rgb 数据集学 `lift_green`、`stack_green_on_red`;deformable 数据集学 `lift_cloth`(软球/绳/布)。RGB 总计约 37.9K episodes / 7.0M steps / 193.3 小时(见 Tab.I)。草图 episode 数:lift_green 894、stack 1201、lift_cloth 585;约 90% 训练 10% 验证;草图分 2–3 轮迭代积累,只标注 NES 中一小部分。
- `random_watcher`:脚本随机移动末端、随机开合夹爪,用于播种初始训练数据。
- 每个任务训练多个 RL agent 并短评、保留最优;每 agent 训 400k 更新步;迭代 2–3 轮(stack 三轮分别用约 82%/94%/100% 数据,第一轮能抓起绿块但放掉,第三轮才成功堆叠,见 Fig.8)。
- 评测:真机固定初始条件,三档难度——normal(基础矩形绿块/大红块居中)、hard(更多样、更小、位置分散的红物)、unseen(训练中从未见过的绿物、大红物);每档 10 个初始位置;成功由人判定。

## 主要结果 & 结论（写方向，不堆精确数字）
- agent 能在真机上完成抓取、堆叠刚性/可变形物体、USB 插孔等多步操作任务(supported);定性上能从抓取失误中恢复、对人为对抗扰动有一定鲁棒、对未见物体/初始条件有一定泛化(observed,Fig.4)。
- rgb 数据集成功率方向:`lift_green` normal/hard/unseen 约 80%/80%/50%,`stack_green_on_red` 约 60%/40%/40%(见 Tab.II);`lift_cloth` 随机初始 50 次约 74%。即:任务越难、物体越没见过,成功率越低,但仍非零(observed)。
- **消融1——random_watcher 任务无关数据有用**:去掉它各档成功率下降,在最难的 unseen 情形下贡献最大(约 +30%)(supported,Tab.II)。直觉:多样化数据扩大状态空间覆盖,帮泛化。
- **消融2——只用任务相关数据会崩**:只用 lift(或 stack)自身 episode 训练,几乎所有场景成功率为 0%(observed/supported,Tab.II)。说明回溯标注全库、跨任务复用数据是 work 的关键。
- **消融3——分布式 value function 是必需的**:换成非分布式 RL,各档成功率大幅下降(supported,Tab.II),与 Atari 上的发现一致(引用[1])。
- **交互式插入(USB)**:在线把数据采集/奖励学习/策略学习闭环,不依赖历史数据与 batch RL;6-DoF 速度控制,从零学起,约 8 小时内达 >80% 成功率(Fig.10),期间人额外补 65±10 条草图。表明一个工作日内可从视觉+人反馈解决工业相关任务(observed,单任务 3 次重复)。
- 与他人对比(非严格可比,作者明确指出物理装置不同):本文 lift/stack 约 80%/60%,Zhu 等[73]约 64%/35%;Jeong 等[31]用 sim2real + 4-DoF 在固定大块上达 62%,而本文是更复杂的连续 6-DoF + 多样物体(related work 对照,supported but 跨装置不可直接比)。

## 适用边界（什么时候管用 / 什么时候不管用）
- **管用**:适合"人能可靠比较两帧进度"的任务,典型是物体操作(抓取/堆叠/插孔/举布)。作者明确点名。
- **不管用/不适合草图**:变速很重要或带周期的任务(如行走),草图难画;作者自承当前方法"不能解决所有感兴趣的操作任务"(原文 "does not however cover many manipulation tasks of interest as shown here")。
- 训练完全离线、靠 batch RL,因此回避了在线探索,但代价是需要 NES 里有足够覆盖状态空间的多样数据(否则消融显示会崩到 0%)。
- 交互式插入那条线是**在线、数据需求更小**的替代路径,适合不便积累大历史库的应用。
- 学到的 agent 仍对装置的显著扰动敏感(作者自述),即鲁棒性是"一定程度",非全面。

## 核心贡献
- 提出 reward sketching:一种让人高带宽、可靠地按时间步标注奖励的偏好征询方式(strong,作者核心主张)。
- 提出"用学到的奖励回溯性标注全部历史数据 + 纯离线 batch RL"的规模化范式,使 RL 不必在真机上在线运行即可学策略(strong,作者核心主张)。
- 首次展示如何高效给这类异构机器人数据集贴奖励标签、并把 batch RL 应用到如此有挑战的真机域(作者自我定位的"first")。
- 用系统实验给出关键经验结论:训练数据多样性是标准 SOTA batch RL 算法成功的关键因素(此前有报告称这类算法在单一专家/单 agent 历史数据上会失败)(supported)。
- 随文发布 Sketchy 数据集([16])与 canonical agents([28])。

## 局限与我的质疑
1. **预印本/未同行评审**:本文为 arXiv 预印本(引用 0),结论未经同行评审独立确认,对其"超越人类遥操作""强泛化"等措辞应保留;尤其性能数字与跨工作对比都应谨慎。
2. **评测样本极小,统计可信度弱**:核心 Tab.II 每档难度仅 10 个初始位置,成功率以 10% 为粒度;USB 实验仅重复 3 次。这种规模下"80% vs 70%"的差异很可能在噪声内,作者未报告置信区间或显著性,把这些点差当结论卖点是危险的。
3. **跨装置对比不可直接采信**:与 Zhu[73]、Jeong[31]、QT-Opt[35] 的对比作者自己也承认物理装置不同("not perfectly comparable"),所以"compare favorably"只能算 observed,不能当作方法更优的硬证据。
4. **方法对人类在环的依赖未被量化为成本**:reward sketching 要人持续画草图、还要 2–3 轮迭代修"delusion",作者把"固定标注成本"当卖点,但论文没给"达到某成功率需多少标注分钟"的清晰曲线,所谓"高效"缺乏与其它奖励方案(如逆 RL、整段比较)在同等成本下的对照实验。
5. **奖励模型质量与策略成功率之间缺环节**:论文报告标注者对绝对 scale 不一致才改用 ranking,但没量化学到的奖励函数本身有多准(如与人判断的相关性),只能从最终策略成功率间接推断,奖励模型的失败模式(被钻空子)只是定性描述。
6. **"任务无关数据多样性是关键"虽有消融支撑,但泛化机制未深究**:消融显示去掉 random_watcher 掉性能,但这是该特定 setup 下的 observed 结论,并未证明"任意多样数据都帮泛化";random_watcher 与目标任务的分布关系、需要多少多样性才够,都没系统扫。
7. **与本研究主题(reward 工程 / SAC/PPO 之外算法)的契合点与不足**:本文确实给了"学习型 reward + off-policy/batch RL(分布式 DPG)在真机"的完整范式,命中主题;但它用的是 D4PG 系而非 SAC/PPO,奖励学习路线是"人画曲线→排序模型",可迁移性取决于你的任务是否满足"人能可靠比两帧进度"这一前提,行走/动态/无清晰视觉进度的任务难直接套用。
