# Scaling data-driven robotics with reward sketching and batch reinforcement learning
> Serkan Cabi, Sergio Gómez Colmenarejo, Alexander Novikov, Ksenia Konyushkova, Scott Reed, Rae Jeong, Konrad Żołna, Yusuf Aytar, David Budden, Mel Vecerik, Oleg Sushkov, David Barker, Jonathan Scholz, Misha Denil, Nando de Freitas, Ziyu Wang (DeepMind) · 2019 · arXiv · 引用 0 · DOI arxiv:1909.12200

## 一句话
一套"数据驱动机器人"流水线:用**reward sketching**(人手画进度曲线)给海量历史机器人经验**事后补打奖励**,再用**完全离线的 batch RL**(分布式 RL)从像素学操作策略,把真机交互从策略学习里彻底拿掉。

## 解决了什么问题
- 真实机器人 RL 缺两样东西:**大规模带奖励的数据集**和**现成的任务奖励信号**(真实世界不像仿真/游戏那样天然有 reward),数据采集只能实时进行、无法加速。
- 手工设计奖励函数对简单行为(抓取、避撞飞行)可行,但任务一复杂就**不可扩展**(原文 "as the task complexity increases, this approach does not scale well")。
- 在线 RL 要反复操作真机,有磨损、实时性、安全等代价,且每换一个新任务似乎都要从零重采数据。

## 用什么方法解决的(含直觉:为什么 work)
三个核心点 + 一个存储系统:
1. **Reward sketching(奖励速绘)**:人一边"拖动"(scrub)视频时间轴,一边画一条"完成任务的进度"曲线作为时间的函数,给每个时间步一个奖励 s(x_t)∈[0,1](Fig 2)。直觉:人**判断"朝目标的进度"很快很准**,且拖动式标注比逐帧标注快得多,一个标注员一分钟能标几百帧——用"固定的标注预算"撬动"海量历史数据"。
2. **事后补奖励(retrospective labelling)**:用少量速绘训练一个奖励模型 r_ψ,然后**对 NES 里所有历史 episode 自动打上这个新任务的奖励**(Fig 3)。直觉:奖励一旦学会,过去为别的任务/随机/脚本采集的数据都能被"重新利用"为当前任务的训练信号——这就是规模的来源。
3. **完全离线 batch RL**:用一整批已标注数据训练策略,**训练期间完全不碰真机**(off-line / off-policy)。直觉:把"学策略"和"跑机器人"解耦,研究者能像在 ImageNet 上换算法一样自由迭代 batch RL 算法,免去真机在环的代价。
4. **NeverEnding Storage (NES)**:一个**关系型数据库**,持续累积所有任务、所有来源(遥操作、人类玩耍数据、脚本策略、训练出的策略)的全部传感记录,带丰富元数据(日期、策略、人读标签、reward sketch),可用 **SQL 查询**按流水线阶段切片取数据。直觉:把"数据"当成可反复检索复用的资产,而不是每个新任务都从头采。

## 动机 & 背景
- 深度学习在视觉/语音/NLP/游戏里靠**大标注数据**成功;机器人领域缺这种数据,因为采集必须真机实时执行、无法超过实时速度。
- 作者主张走**数据驱动**路线:从视觉直接学、不预设奖励、把 RL 应用规模拉到远超常规。
- 与最接近的工作对比:QT-Opt [35] 收集 7 台机器人数周共 58 万次抓取、训分布式 Q-learning,泛化好但**只聚焦"抓取"单一任务**、靠脚本采数据、奖励工程难推广;本文要做**多样任务**且学奖励函数(原文定位本文是"第一个展示如何高效给这类数据集打奖励、并用 batch RL 攻克更难领域")。

## 方法细节
**整体工作流(Fig 1 / Fig 5,七步 A–G)**:A 人遥操作示范目标任务 → B 全部经验进 NES → C 人对 NES 中一小部分 episode 做 reward sketch(含目标任务的示范)→ D 用这有限标注训练奖励模型 → E 用 NES 全量数据 + 预测奖励训练 Q/π → F 部署真机、继续录数据(可再标注)→ G 偶尔挑 agent 做正式评测。图中明确区分了**任务相关/任务无关**与**需不需要人**的步骤。

**奖励学习(关键设计:用排序而非回归)**:作者发现标注员**在"相对好坏"上高度一致,但在奖励的整体 scale 上不一致**,所以**不直接回归速绘值**,而采用**单 episode 内的排序**方法。两个 hinge 损失:
- 排序项:`L_rank(ψ) = max{0, r_ψ(x_t) − r_ψ(x_q) + μ_r} · 1[ s(x_q) − s(x_t) > μ_s ]`(当速绘判定 x_q 明显优于 x_t 时,逼着预测奖励也满足这个序+间隔)。
- 成功项:`L_success(ψ) = max{0, τ_r1 − r_ψ(x)} · 1[s(x) > τ_s] + max{0, r_ψ(x) − τ_r2} · 1[s(x) < τ_s]`(把速绘里"成功/不成功"的帧分别拉到高/低奖励区)。
- 总损失:`L = L_rank + λ·L_success`。超参 μ_s=0.2, μ_r=0.1, τ_s=0.85, τ_r1=0.9, τ_r2=0.7, λ=10(见 §II-D)。直觉:**只信人对"哪帧更接近完成"的相对判断**,绕开 scale 噪声。
- 奖励网络:非循环残差网 + spatial softmax 关键点层,末端 sigmoid(因速绘值在 [0,1])。

**Batch RL**:用**分布式 RL**(类 D4PG [7]/[28]),**无任何特征预训练、无行为克隆初始化、无离线修正项/辅助损失**。Q 和 π 都用**循环网络**(LSTM 隐状态 h^Q_t, h^π_t,采用 [36] 的循环值函数思路),策略按 DPG [62] 更新,critic 用分布式值函数 [8],采样序列、零初始隐状态、用 **BPTT** 更新;**target 网络** θ'、φ' 周期性同步。
- **固定配比 batch**:每个 batch **75% 来自整个 NES、25% 来自目标任务专属数据**(借鉴 [54] 的 agent+示范配比),为提高当前任务数据的占比。

**奖励"妄念"(reward delusion)问题**:奖励覆盖不足时,策略会**钻空子**——在不该高奖励的行为上拿到高奖励。修法是让人**对出现妄念的 episode 补画速绘**,重训奖励;每个任务这个循环一般重复 **2–3 次**直到奖励满意。

## 数据集 & 实验设置
- 硬件:**Sawyer 机械臂 + Robotiq 2F-85 夹爪 + 腕部力矩传感器**,35×35 cm 篮筐;动作空间 **6 个连续自由度(笛卡尔平移+旋转速度)+ 1 个二值夹爪**,10 Hz 控制,工作空间 35×35×15 cm;每 episode 200 步(20 秒)。
- 观测:**3 个机笼相机 + 3 个腕部相机(2 广角 + 1 深度)+ 本体感觉**(Fig 6)。直接从像素学,免特征工程。
- 任务:`lift_green`、`stack_green_on_red`(rgb 数据集,变形状刚性红/绿/蓝物体);`lift_cloth`(deformable 数据集,软球/绳/布)。
- 数据规模(Table I):rgb 数据集合计 **37.9K episodes / 7.0M steps / 193.3 小时**;deformable 合计 36.5K / 6.9M / 191.2 小时;全库**超过 400 小时多相机视频**。速绘 episode 数:lift_green 894、stack 1201、lift_cloth 585(约 90% 训练 / 10% 验证)。注意:**只标注了 NES 中很小一部分数据**。
- 约 **15% 的人类示范在末尾是失败的**(数据仍保留)。`random_watcher` 是脚本随机策略(随机移动 + 随机开合夹爪),用于**冷启动**学习。
- 网络(Fig 7):每相机各自经残差网 + spatial softmax(64 通道,输出 64 个 (x,y) 关键点;softmax 前对 logits 加 U[−0.1,0.1] 噪声促使预测集中);本体特征线性嵌入+层归一+tanh 后拼接;actor/critic 各两层 256 单元层归一 LSTM。

## 主要结果 & 结论(写方向)
- **离线 batch RL 真能在真机做成多步操作**:抓取、堆叠刚性/可变形物体、USB 插接等任务可解(Fig 4)。strength: supported。
- rgb 任务成功率(Table II,normal/hard/unseen 三档,每档 10 个初始位):`lift_green` 约 80/80/50%;`stack_green_on_red` 约 60/40/40%;**面对训练中从未见过的物体仍能完成约一半**(lift 50%、stack 40%)。strength: observed(每档仅 10 个初始位,样本小)。
- `lift_cloth`:50 个随机初始条件下成功率约 74%。strength: observed。
- **与外部工作方向性比较**:与 Zhu et al. [73](抓/堆 64%/35%)相比"compare favorably";相对 [72] 用 QR 码状态估计、[31] 固定大块 sim2real 4-DoF,本文在**更多样物体 + 6-DoF 连续控制**下达到相近表现。strength: observed(作者明确说设置不同、不完全可比)。
- **消融一:数据多样性是关键**。只用任务专属数据训练,几乎所有场景**降到 0% 成功**(原文 "dramatically degrades… 0% in almost all scenarios")——说明"事后给海量异构历史数据补奖励"这件事本身贡献巨大。strength: supported。
- **消融二:random_watcher 数据有用**。去掉它最多损失约 30% 成功率,**在最难的 unseen 物体上优势最大**。strength: supported。
- **消融三:分布式值函数是必需的**。换成非分布式 RL 后大幅变差(印证 Atari [1] 的发现)。strength: supported。
- **迭代变好(Fig 8)**:stack 任务三代 agent 分别用约 82%/94%/100% 数据,第一代抓起绿块但掉落、第二代尝试堆叠、第三代成功——更多数据→更好。strength: observed。
- **在线交互式 USB 插接**(另一条路线,不用历史数据/batch RL,边采边学、策略从零):约 **8 小时内达 >80% 成功率**(Fig 10);期间人额外提供 65±10 张速绘;策略对插孔位置移动有鲁棒性。strength: observed。
- **个别情况下比人类遥操作者更快/更高效**(Fig 9,stack 任务)。strength: observed(作者用词即 "in some cases")。

## 适用边界(什么时候管用 / 什么时候不管用)
- **管用**:典型**物体操作类**任务——抓取、堆叠、插接,刚性与可变形物体都行;人能**可靠比较两个时间步谁更接近完成**的任务。作者明确说该速绘方法"**确实覆盖了许多感兴趣的操作任务**(原文 'does however cover many manipulation tasks of interest as shown here')"。
- **不管用 / 受限**:作者自述 reward sketching **并非通用**(原文结论部分 "not universal")——对**速度本身重要**或**有周期/循环**的任务(如**行走**)很难画奖励曲线;这类任务需要别的奖励获取策略。
- 还需要:**训练期间人要在环**(补速绘、修妄念),有额外人力成本;以及学到的策略对**显著扰动仍敏感**。

## 核心贡献
1. 提出 **reward sketching**:一种高效、直觉化、可大批量产出**逐时间步**奖励标注的人类偏好获取方式。
2. **事后补奖励 + NES**:用固定标注预算给长期累积的跨任务历史数据自动补打任务奖励,把数据变成可复用资产。
3. 展示**完全离线 batch RL(分布式 + 循环)**能在**真机、从像素、无预定义奖励**下学成多样操作任务,并系统消融出"数据多样性"和"分布式值函数"的必要性。
4. 公开了 **Sketchy 数据集 [16]** 与 canonical agents [28],推动 batch RL in robotics 研究。

## 局限与我的质疑
1. **未经同行评审的预印本**(arXiv v3, 2019/2020),结论应保留看待;以下质疑据此从严。
2. **样本量小、置信度有限**:rgb 主结果每个难度档只有 10 个初始位置,80%/60% 这类数字落到 8/10、6/10 这种量级,**条件间差异(如 hard 40 vs unseen 40)很可能在噪声内**,作者未给置信区间或方差(cloth 用了 50 episodes 稍好)。因此我把多数成功率定为 observed,不宜外推为"全面优越"。
3. **跨工作比较不严谨**:与 [73][31][72] 的对比作者自己也承认物理设置不同、"不完全可比",所以"compare favorably"只能当方向性参考,不能作为"超越 SOTA"的强结论。
4. **"比人类更快"被很容易过度解读**:仅 Fig 9 个别 stack 案例、"in some cases",并非系统性人机对比,标题里这点宣传性大于证据强度。
5. **奖励学习正确性缺独立验证**:速绘是主观人类进度判断,排序奖励是否真对应"任务完成"主要靠下游策略成功率间接背书;论文未给"学到的奖励 vs 真实成功"的独立量化校准,**妄念(delusion)说明奖励本身可被钻空子**,而修法是人工再标——这把一部分"奖励工程"成本转嫁成了"持续人工在环",与"可扩展"的卖点存在张力。
6. **数据/工程成本被淡化**:超 400 小时真机数据、数千遥操作示范、多次 2–3 轮迭代+人工补标,门槛极高;论文强调"固定标注预算",但**示范采集和迭代标注**的总人力并不小。
7. **泛化边界**:unseen 物体成功率掉到 40–50%,且仍局限于篮筐内的桌面级抓/堆/插;对本研究关心的更广义操作与长程任务,**正确性与可迁移性尚未被证明**,只能算 observed 级别的初步证据。
